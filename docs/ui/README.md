## 一、先立场景：这台机器上的 6 条真实任务链

定位来自 [AGENTS.md](../../AGENTS.md)：只做三核心——Web 管理服务 / Docker 管理 / 插件体系。用户不是「逛功能」，而是在完成以下任务。

### T1 首装后第一次登录：先把安全基线立起来

| 环节 | 他从哪进 | 点几下 | 看到什么 |
|---|---|---|---|
| 打开面板 | 安装脚本输出的安全入口 URL（`/p/<prefix>`） | 1 次提交登录 | 登录页；登录后进入概览（默认不强制改密，仅建议修改口令） |
| 改密后落点 | 保存新口令 | 1 次 | **概览**：服务健康 4 项 + 3 条待办，其中一条是「两步验证未开启」 |
| 补安全项 | 概览 → 设置 → 安全设置 | 2 次 | 口令、TOTP、安全入口、信任公钥在同一页；开启 TOTP 后返回概览，待办消失 |

**设计含义**：首登后的落点必须是「接下来做什么」清单，不是指标大屏；安全项必须集中在一页，不能散成 4 个子页面。

### T2 每天 30 秒巡检

| 环节 | 他从哪进 | 点几下 | 看到什么 |
|---|---|---|---|
| 打开 | 浏览器书签（会话仍在） | 0 | 概览：`12 容器 / 1 异常 / 1 待重载 / 1 插件可更新`，下方「需要处理」按影响排序 |
| 看异常 | 「nginx 反复退出」→ 查看容器 | 1 | 容器页**自动筛到「异常」**，异常行在顶部 |
| 处理 | 行内「日志」→ 抽屉；「重启」→ 确认 | 1–2 | 日志抽屉不离开列表；操作结果用 toast + 状态 chip 反馈 |

**设计含义**：概览的每一条都必须能一键深链到「已筛选好的目标页」；容器列表默认异常优先，操作不跳详情页。

### T3 从零装一个插件，装完立刻能用（以 FTP 管理为例）

| 环节 | 他从哪进 | 点几下 | 看到什么 |
|---|---|---|---|
| 找插件 | 插件中心 → 发现 | 1 | 7 个官方包卡片（6 个官方插件 + testkit）；FTP 管理显示能力面与版本 |
| 安装 | 卡片「安装」 | 2（打开弹窗 + 勾选授权并确认） | 权限清单（写哪些目录、能碰哪个容器）、验签/解包进度；安装后**不自动启用** |
| 启用 | 卡片「启用」 | 1 | 卡片变「已启用」；**「工具」菜单即时出现「FTP 管理」**；toast 告知入口 |
| 开始用 | 卡片「打开」或「工具 → FTP 管理」 | 1 | 直接进账号 / 运行状态页，而不是回插件列表 |

**设计含义**：安装/启用属于「管理」，留在插件中心；日常使用属于「应用」，必须是直达入口。

### T4 网站运行环境装完之后：配站点 → 看状态 → 重载（含排障）

| 环节 | 他从哪进 | 点几下 | 看到什么 |
|---|---|---|---|
| 进工作台 | 任意页「网站 → 网站列表」 | 2（悬停一级 + 点二级） | 左站点列表（3 个站点 + 状态）、右详情 |
| 改配置 | 选 site → 编辑器 → 保存配置 | 2–3 | 顶部黄色横幅「已保存，尚未生效」；状态行 `待重载` |
| 生效 | 「重载 NGINX」 | 1 | 按钮 loading → 状态行 `运行中 / 上次重载 刚刚`，横幅消失 |
| 失败分支 | 重载后容器退出 | 1 | 红色横幅 + 「查看容器日志」；日志抽屉定位 `exit 1`；再到 Docker → 容器处理容器 |

**设计含义**：**保存 ≠ 生效**必须在界面上说清楚；站点状态、容器状态、重载动作同屏，避免「配置页 / 容器页 / 日志页」三处来回跳。

### T5 文件 / 任务 / 监控 / 守护的日常使用

| 任务 | 路径 | 看到什么 |
|---|---|---|
| 查一份配置 | 工具 → 文件管理 → 已授权目录 | 面包屑 + 文件列表；只显示授权根，写操作有明确边界 |
| 看定时任务是否跑了 | 工具 → 计划任务 | 上次执行结果、下次时间、「立即执行」 |
| 看机器趋势 | 工具 → 主机监控 | 5 分钟采样的 CPU / 内存 / 负载；只读 |
| 看自动重启策略 | 工具 → 容器守护 | 演练/自动模式、冷却与次数上限、被排除容器 |

**设计含义**：插件一旦启用，就应像内核功能一样有稳定入口；停用后入口消失，但不留下空页。

### T6 事故排障 + 审计追溯

| 环节 | 他从哪进 | 点几下 | 看到什么 |
|---|---|---|---|
| 发现 | 概览红色异常卡 | 1 | 容器页（异常筛选） |
| 定位 | 日志抽屉 | 1 | 明确的错误行（配置指令不存在 / 退出码） |
| 修复 | 网站 → 网站列表 → 改配置 → 重载 | 3–4 | 状态恢复；概览待办自动消失 |
| 追溯 | 设置 → 审计日志 → 按「容器/配置/认证」筛 | 2 | 操作者（含 guard 自动动作）、动作、目标、结果、来源 IP；点行看详情 |

**设计含义**：排障路径不经过「插件中心」；审计是安全域的一部分，不是第六个一级菜单。

## 二、上一版为什么不对

上一版是「按现有路由分组」：`概览 / Docker(容器/镜像/网络/卷) / 插件(已安装/官方源) / 设置(锚点/审计)`。问题不在样式，而在 IA：

| 具体问题 | 根因 |
|---|---|
| 概览是空壳，用户看完还得自己找 | 概览被当作「路由集合」的一格，而不是任务决策面板 |
| 插件「使用」被埋在「插件 → 已安装」 | 没有区分**使用**（高频）与**管理**（低频） |
| 装完 nginx 后配站点要走 4–5 步 | 插件功能没有一级入口；nginx 只是插件列表里的一个名字 |
| 「设置」二级是页内锚点，算假二级 | 为了凑二级菜单，把一页拆成锚点，层级没有承载任务 |
| 插件入口直接占顶栏，装几个就有几个 | 菜单长度随插件数增长，核心/扩展边界消失 |

## 三、两个以上候选模型与取舍

### 模型 A：功能域导向（上一版）

`概览 / Docker(4) / 插件(已安装、官方源) / 设置(口令、TOTP、入口、审计)`

- 优点：与现有路由一一对应，实现成本最低。
- 缺点：T3 需 4–5 步（插件→已安装→详情→启用→再找使用）；T4 没有站点工作台入口；概览无行动力；二级项有假层级。
- 结论：否。它描述的是「系统有什么」，不是「用户要做什么」。

### 模型 B：插件平铺一级

`概览 / 网站 / 文件 / 任务 / 监控 / 守护 / 容器 / 镜像 / 网络 / 卷 / 插件中心 / 设置`

- 优点：插件使用 1 次点击；职责最直白。
- 缺点：官方 5 个插件已占 5 个一级位，第三方插件继续增长会挤爆顶栏；未安装时菜单忽隐忽现；Docker 与插件混排，核心/扩展边界消失；窄屏更难扫。
- 结论：否。短期最爽，长期不可维护。

### 模型 C（定稿）：任务分层的「决策 / 使用 / 基础设施 / 管理 / 安全」

`概览（决策） / 应用（使用） / Docker（基础设施） / 插件中心（管理） / 设置（安全与审计）`

- 一级固定 5 项，扩展只影响「应用」内部的二级项，不改变一级宽度。
- 使用与管理彻底分开：插件中心只装/启/停/更新；应用只放已启用插件的日常入口。
- 网站路径变成 `网站 → 网站列表`，1 次悬停 + 1 次点击，工作台内完成配/看/重载。
- 概览承载 T1/T2/T6 的行动入口，而不是统计页。
- 代价：新增一个抽象「应用」；插件入口比平铺多 1 次点击。用「固定最多 5 个一级」换长期可扩展，是本系统的正确取舍。

> 备选 C′：把「概览 + 应用」合并成「工作台」。但概览是**只读决策**，应用是**操作现场**，合并会让首屏同时承担两件事，故不采用。

## 四、定稿 IA

| 一级 | 二级 | 承担任务 | 出现条件 |
|---|---|---|---|
| **概览** | —（直接链接） | T1 首登落点、T2 巡检、T6 异常入口 | 常驻 |
| **应用** | 网站 / 文件 / 任务 / 监控 / 守护 | T3 装完即用、T4 nginx 闭环、T5 日常 | 只列**已启用**插件；固定顺序；0 项时整个一级隐藏 |
| **Docker** | 容器 / 镜像 / 网络 / 卷 | T2 容器状态、T4 容器日志/重启、T6 排障 | 常驻 |
| **插件中心** | —（页内 发现 / 已安装 / 可更新） | T3 安装、授权、启用、停用、更新 | 常驻；有更新时一级带角标 |
| **设置** | 安全设置 / 审计日志 | T1 安全基线、T6 追溯 | 常驻 |

命名、层级与去重原则：

- **用户词优先**：用「网站」而不是「NGINX 站点」，用「任务」而不是「计划任务插件」；插件正式名作为二级项副标题 / 插件中心卡片名。
- **保留产品名**：Docker 是用户心智词，不改叫「运行」或「容器管理」。
- **最多两级**：插件页内部的 tab、设置页内的分区都是**页内容**，不进入导航层级。
- **同一功能只出现一次**：插件安装只在插件中心；插件使用只在应用；容器操作只在 Docker；审计只在设置下。
- **不做空洞命名**：不出现「管理」「更多」「其他」「系统」这类可以装任何东西的词。
- **菜单稳定性**：应用二级固定「网站 → 文件 → 任务 → 监控 → 守护」顺序，只按启用状态显隐，不因安装顺序抖动。

### 插件四态怎么呈现（避免死入口）

| 插件状态 | 应用菜单 | 插件中心卡片 | 用户动作 |
|---|---|---|---|
| 未安装 | 不出现 | 「未安装」+ 安装 | 安装 → 授权弹窗 → 已安装未启用 |
| 已安装 · 未启用 | 不出现 | 「已安装 · 未启用」+ 启用/卸载 | 启用后立即出现在应用菜单（toast 告知位置） |
| 已启用 | 出现，固定顺序 | 「已启用」+ 打开/停用（可更新时加更新） | 打开直达工作台 |
| 有可用更新 | 不额外标记，避免日常打扰 | 「可更新」tab + 更新按钮 | 更新走验签，不中断当前使用 |

当**一个插件都没启用**时，「应用」一级隐藏，而不是给一个空页；插件中心里明确写「启用后会出现在应用菜单」。

## 五、视觉方向

### 布局骨架与密度

```
┌ 顶栏 56px：品牌 · 一级导航 · 健康点/身份 ───────────────────────────┐
│ 内容区：max-width 1200，左右 24px，卡片间距 16，12 列栅格          │
│  ├ 页头（标题 + 一句副标题 + 右侧主操作）                          │
│  ├ 概览：4 个健康块（1 行）+ 主内容 1.45fr / 侧栏 1fr              │
│  ├ 列表页：工具栏 52px + 44px 行高表格                             │
│  └ 工作台：左 270px 站点列表 + 右侧详情                            │
└───────────────────────────────────────────────────────────────────┘
```

- 字号：正文 14 / 表格 12.5 / 辅助 11.5；数字列等宽字形。
- 密度：表格行 44px，卡片内边距 16–18px；概览一屏内看完 4 个健康块 + 待办。
- 窄屏（≤900px 或预览切 430px）：顶栏只留品牌 + 菜单按钮 + 退出；导航变成下拉抽屉，分组就地展开；内容单列，指标 2 列，工作台站点列表排到详情下方；次要表格列标 `.hide-narrow` 隐藏。

### 层级与颜色（沿用现有暗色语言，只重排层级）

- 背景 `#0f1115` / 卡片 `#161a21` / 内嵌块 `#1c222b`；仅浮层与弹窗有阴影。
- accent `#5ad1a4` 只用于：当前态、主按钮、健康正常；警告 `#f5b942`、危险 `#ff6b6b`、信息 `#63a4ff`。
- 导航态：默认 muted → hover 面板色 → 当前一级 accent 底 + 2px 下划线（分组内命中时一级也亮）；二级当前项 accent 底；焦点统一 2px accent 外框。

### 空状态 / 错误态

- 空状态：不是空白表格。用虚线框 + 一句原因 + 一个恢复动作（如「没有匹配的容器 → 清除筛选」，预览里可试）。
- 错误态：顶部红色横幅承载「发生了什么 + 下一步动作」（查看日志 / 重试 / 去修复），不弹全屏错误页；容器异常用行内 chip + 行内操作。
- 加载态：按钮就地变为「重载中…」并禁用，避免重复提交。

### 约束

- 预览文件自包含（内联 CSS/JS），仅作为设计交付，不是产品代码。
- 落到产品实现时必须遵守现有 CSP：交互进同源 `/static/skiff.js`，无内联脚本、无 CDN、无外链字体；样式进 `skiff.css`，不重做整站。

## 六、预览怎么看

1. 双击打开 `docs/ui/redesign-preview.html`（无需服务器）。
2. 顶部工具条切换 **桌面 / 窄屏 430px**。
3. 顶栏：hover 或点击「应用 / Docker / 设置」展开；Esc、点空白、焦点移出都会关闭；Tab 顺序为「一级按钮 → 二级项」。
4. 关键路径可直接试：
   - **T2**：概览 →「查看容器」→ 已筛到异常 → 行内「日志」；
   - **T3**：插件中心 → 主机监控「安装」→ 勾选授权 → 进度 → 启用 → 「应用」立即多出「监控」；
   - **T4**：网站 → 网站列表 → 选站点 → 改配置 → 保存 → 重载 → 状态变「已生效」；点「新增备份任务」可看未启用 cron 的引导；
   - **T5**：工具 → 文件管理 / 计划任务 / 主机监控 / 容器守护；
   - **T6**：设置 → 审计 → 筛选 / 点行看详情；设置里开 TOTP，概览待办同步消失；
   - 容器搜索输入乱值，可看空状态与「清除筛选」。

覆盖界面：概览、容器列表、插件中心（装/启用/停用）、网站工作台、设置、审计，另含文件、任务、监控、守护、镜像/网络/卷。

## 七、仍需拍板（≤3）

1. **「应用」0 插件时**：隐藏一级（本文推荐），还是保留入口并引导去插件中心？
2. **Docker 一级名**：保留「Docker」，还是改成更任务化的「容器」/「运行」？
3. **停用/更新入口**：放在插件中心卡片（本文推荐），还是允许在插件工作台页头直接操作？
