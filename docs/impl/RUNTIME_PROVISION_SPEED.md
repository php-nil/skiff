# 运行环境供给速度方案

> 问题：新建 PHP 运行环境在「安装扩展」阶段曾达 30 分钟以上，测试机全新安装因此被判超时失败。
> 结论：**瓶颈在下载，而且可以靠「按实测吞吐自动选源」消掉**——同一台机器、同样清空的缓存，默认源装 `pdo_mysql` 30 分钟超时，自适应源装 `imagick`（更重）**53 秒**。
> 本文是实现方案与实测结论；「安装必须多快」的承诺口径在 [SITE_RUNTIME_CONTRACT.md](../contract/SITE_RUNTIME_CONTRACT.md)。

## 1. 事实基线（2026-11-18 测试机实测）

| 观测项 | 数值 | 场景 |
| --- | --- | --- |
| 默认源 + 冷缓存，装 `pdo_mysql` | **30 min 未完成**（判超时） | `job-1795003035-274fc34d8` |
| 默认源 + 热缓存（109 MB），装 `pdo_mysql` | **532 s** | `job-1795004860-27d8f8389` |
| 该次 `apk add` 规模 | 67 包 / **338.4 MiB**，收尾 purge 26 包 | 同上 |
| 默认源吞吐 `dl-cdn.alpinelinux.org` | **535 KB/s** | 容器内 `curl` 实测 |
| 同机清华源吞吐 | 29.5 MB/s | 同网络同时段 |
| 同机 aliyun 源吞吐 | **271 KB/s** | 比默认源更慢 |
| **自适应源 + 冷缓存，装 `redis`（PECL 编译）** | **30 s**，`php -m` 已加载 | 本轮验证 |
| **自适应源，装 `imagick`（ImageMagick 全家桶）** | **53 s**，`php -m` 已加载 | 本轮验证 |
| 源探测开销（4 个候选，ISO 3 MB range） | **2.2 s** | 选中清华 9176 KB/s |
| 扩展阶段日志落库 | 44 行**全部落在结束那一秒** | 无法还原阶段耗时 |

**结论修正**：最初判断“下载只占三段耗时的一段，解包与编译仍是大头”。实测否掉了后半句——同样 338 MiB 工具链，在 5 MB/s 的源下解包加编译只要几十秒。**下载就是主因，选源就是主要解法。**

（口径说明：`pdo_mysql` 走 `docker-php-ext-install`、`redis`/`imagick` 走 PECL 源码编译，扩展类型不同；但 60 倍的量级差异远超扩展类型带来的差别。）

## 2. 用户场景矩阵

| # | 场景 | 特征 | 由哪层解决 | 状态 |
| --- | --- | --- | --- | --- |
| A | 国内公网 | 默认源 535 KB/s | **L1 选源**（实测 30–53 s） | 已落地 |
| B | 海外公网 | 默认源快、国内源慢 | **L1 选源**（探测会保留 dl-cdn） | 已落地 |
| C | 内网 / 离线 | 不通公网，或只有内网 apk 代理 | L1 兜底（保持默认源不阻断）+ L2/L3 离线包 | 未做 |

| E | 低配机 | 1–2 核、慢盘 | L1 选源后基本够用；极端情况才需要 L3 | 部分 |
| F | 重建 / 二次安装 | 缓存已在 | **已解决**（30 s 级） | 已落地 |

## 3. 已落地：L1 源自适应

实现位置：`crates/app/src/runtime_catalog.rs::installer_prelude()`。

- **候选**：`dl-cdn` / 清华 / 阿里 / 中科大。不写死任何一个——实测阿里比默认源还慢，单源切换会把另一批用户做坏。
- **判据**：对 `<base>/alpine/v<rel>/releases/<arch>/alpine-virt-<完整版本>-<arch>.iso` 发 **3 MB range 请求**，取 `%{speed_download}`。`<rel>`/完整版本取自 `/etc/alpine-release`、`<arch>` 取自 `apk --print-arch`，跟随镜像实际版本。
- **为什么不用 APKINDEX 测速**（踩过的坑，必须写下来）：最初用 `APKINDEX.tar.gz`（约 500 KB）测 `%{speed_download}`，实测被首包延迟与镜像边缘缓存带偏到离谱——阿里源测得 **4.2 MB/s**，而同一时刻它下 3 MB 文件只有 **1.5 KB/s**（虚高 2800 倍）；清华真实 11 MB/s 却只测出 1.86 MB/s。按这个排序会**把用户切到最慢的源**，线上第一次生效就选错了。改为下足量真实数据后，排序才与实测一致（清华 9.2 MB/s 胜出）。
- **有效性判据**：响应不足 512 KB 说明该源没有这个文件（404 页面），按**不可用排除**而不是“慢”；全部排除时保持镜像默认源，绝不靠小文件估值去猜。探测在测试机耗时 **2.2 s**。
- **噪声抑制**：小文件测速受首包延迟影响，**至少快 1.5 倍才换源**，否则保留先出现的 `dl-cdn`。这保证海外用户不会被误切到国内源。
- **开销**：结果写 `/var/cache/apk/.skiff-mirror`（该目录挂宿主 `<runtime>/cache/apk`，跨容器复用），24 小时内复用；首次探测 1.6 s。
- **兜底**：全部候选不可达（典型纯内网）时**不动** `/etc/apk/repositories`，保持镜像默认源，并在日志里说明；整段包在子 shell 里 `|| true`，任何意外都不阻断安装。
- **写入格式**：`<base>/<rel>/main` 与 `<base>/<rel>/community`——**不能带 arch**，否则 apk 会拼成 `.../main/x86_64/x86_64` 直接全盘失败。
- **只覆盖 Alpine**：Debian 家族镜像走 apt，源文件格式与签名机制不同，需单独处理（见 §7）。
- **回归保护**：`installer_prelude_is_shell_syntax_clean` 用 `sh -n` 校验拼装结果，并钉住 `%{speed_download}`、`${SKIFF_SPD%%.*}` 等被 `format!` 转义影响的关键片段。

## 4. 仍需做的两层

### L0 可观测（P1）

选源已把常规安装压到分钟级以内，但两个问题还在：

- **进度是假的**：执行阶段固定在“安装扩展 15%”，结束时直接跳 80%，中间没有任何反馈。
- **日志是结算式写入**：44 行全部落在结束那一秒，事后无法回答“慢在哪”，本次是靠宿主抓 `/proc/fd` 才定位到下载。

做法：把 `docker exec` 输出按秒流式落 `job_logs`（`exec_capture_impl` 已经在逐 chunk 读，只需加回调）；解析 `apk (12/67)`、`Installing` 等标记映射进进度；结束写 `download_ms / extract_ms / compile_ms`；超时从“总时长”改为“连续无输出”。

### L2 / L3（P2，仅内网、无网与极端低配）

- **L2 宿主预取**：实测 `apk add --no-network` 能从缓存 **12/12 包**纯离线解析，路径成立。价值已不是提速，而是 ① 内网/无网时能装；② 缺包时秒级报清单而不是等超时；③ 跨环境复用。**常规场景不需要。**
- **L3 预编译扩展包**：按 `php 精确版本 + alpine 版本 + arch` 指纹分发 `.so`，命中即解包、不命中回退编译。成本高（CI 矩阵、ABI 验证、双架构、体积），而 L1 已把常规路径压到 30–53 s，**暂不作为通用方案**，只在“无编译能力”或“无外网”的部署里考虑。

## 5. 验收口径

| 场景 | 构造方式 | 通过标准 | 实测 |
| --- | --- | --- | --- |
| A 国内慢链路 | 测试机默认网络 | 首装 ≤ 3 min | **30–53 s** ✅ |
| F 重建 | 同环境重建 | ≤ 60 s | **30 s** ✅ |
| 源探测不阻塞 | 任一安装任务 | 探测 ≤ 5 s 且失败不阻断 | **1.6 s** ✅ |
| 国内源更快时切换 | 默认源 535 KB/s | 自动切到快源并记日志 | ✅ 选中 ustc 5074 KB/s |
| 海外不误切 | 模拟 dl-cdn 最快 | 保留 dl-cdn | 靠 1.5 倍阈值保证（待海外机验证） |
| C 离线 | 断公网 + 预置包 | 秒级报缺包 | 未做（L2） |

## 6. 不做

- 不硬编码任何源（含清华）。实测阿里 271 KB/s < 默认 535 KB/s，单源会让部分用户更慢。
- 不把“调大超时”当方案。超时只作无进展保险。
- 不为提速引入 Node 构建链（遵守 D1）。
- 不预烤自有基础镜像取代 L3：那要求用户能 pull 我们的 registry，恰是场景 D 不成立的前提。

## 7. 待实测 / 未覆盖

- **Debian 家族**：`php:8.5-fpm`（apt）未做源自适应，多阶段构建下 apt 源同样可能慢。
- **海外链路的源选择**：1.5 倍阈值是按国内数据定的，需在海外机器上验证不会误切。
- **极端低配（1 核）**：选源后仍需实测，决定 L3 是否需要。
- **532 s → 30 s 的时间分解**：要等 L0 落地才能拿到 `download/extract/compile` 三段数字。
- **`install-php-extensions` 是否会自行改写 `/etc/apk/repositories`**：当前直接在容器内改写，与它共存无冲突；若将来改成只读挂载需复核。
