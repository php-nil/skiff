## 1.1 显式需求 → 可验收项

| # | 需求 | 验收项 | 方式 |
|---|---|---|---|
| R1 | Rust | 服务端代码除前端静态资源外全 Rust。**例外仅三项**：SQLite(bundled, C)、TLS 密码学 provider（`rustls`+`ring`，含 C/asm）、`.wbpkg` 的 zstd 编解码（`zstd-sys`, C）；`install.sh`/`uninstall.sh` 等 POSIX sh 仅作部署脚本 | `cargo tree` + CI 构建日志审计：除例外三项外无 C/asm 构建单元；显式锁 `ring`（aws-lc-rs 需 cmake/clang，不用） |
| R2 | 极简轻量 | 空闲 RSS ≤ 25MB；CPU < 0.3%；冷启动 < 200ms；二进制 ≤ 14MB | systemd cgroup / `/proc` 30 分钟**闲置态**采样 p50/p95（登录峰值口径见 §7）；镜像 ≤25MB 仅对可选 Docker 形态 |
| R3 | 部署 + 1Panel 兼容 | systemd 直装即用（install.sh）；与 1Panel/宝塔**同机共存不冲突**；可选 1Panel 商店 Docker 包（受限形态，§5.4） | 真实机器直装实测 + 共存用例，不接受“应该可以” |
| R4 | 远程 HTTP(S) 管理 | 监听可配；非 loopback 默认 HTTPS（内置 TLS 或可信反代终止）；反代场景正确处理 `X-Forwarded-*` | 直连 TLS + Nginx 反代；远程明文 HTTP 默认不可用 |
| R5 | 扩展化、内核稳定 | 插件崩溃不影响内核；装卸/升级不重启内核；权限显式授权；API 版本化；**未签名包默认拒装** | `kill -9` 插件，面板须全可用；恶意插件（伪造 UI 桥消息 / 直连 socket / 越权 fs 路径 / 未授权 Docker 对象）用例被沙箱与 Broker 隔离；UI + CLI 安装及迁移失败恢复实测 |

## 1.2 隐含需求

认证/爆破防护、安全入口、审计日志、升级不丢数据、多架构、**Docker 绑定挂载路径校验**（§5.5，卷/容器创建需要）。

## 1.3 需求冲突

**冲突 A｜「极简」×「功能预期」** → 内核只留 `docker`/`identity`/`fs`/`net` 四项原子能力 + web 管理面，具体功能（文件管理器/防火墙/网站…）全部插件化。
**冲突 B｜「扩展性」×「内核稳定」** → 进程外插件，否决 dlopen 与 wasmtime。
**冲突 C｜「远程 HTTP(S) 管理」×「轻量」** → 内置 TLS 可接受（约 +1.5MB，估算），ACME 交给反代或插件；非 loopback 默认 HTTPS。

## 1.4 分层边界 / 明确不做

**内核不内置、由插件层实现（宿主能力面已开放，§3.3）**：文件管理、主机监控（CPU/内存/磁盘/网络）、进程管理、宿主 shell、防火墙管理、网站管理（建站/证书/数据库类能力由插件自行取舍）——内核给 `fs`/`net`/`docker` 能力与动词白名单，具体功能是插件层的事。官方示范插件（Nginx 管理）走 docker 能力；fs/net 类官方插件（如文件管理器）排在 MVP 之后。

**明确不做**：多机纳管 / Windows / 内置容器运行时 / 中心化插件 PKI。

**未决策（既不是“不做”，也不阻塞）**：商店与分发渠道——是否自建商店、商店是否同时承载插件，均后期再定。本期只定**交付物**：systemd 安装包（主）+ 签名 `.wbpkg`（与渠道无关，见 §4.4）；1Panel 商店 Docker 包为可选受限形态（§5.4）。
