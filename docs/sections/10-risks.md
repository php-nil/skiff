# 10. 风险

> 主文档：[DESIGN.md](../DESIGN.md) ｜ 本文件：§10 ｜ 上一章：[§9 里程碑](09-milestones.md) ｜ 下一章：[§11 已拍板的决策](11-decisions.md)

21 条风险按层级标注：**架构 10 条**（改动会动到进程模型/权限模型/控制面边界）、**契约 5 条**（一次定死、后期改要迁移）、**实现 3 条**、**运营 3 条**。架构级里有 6 条属于「假设错了要返工结构」，单独列在 §10.1 做原型验证；其余架构级条目的核实用例分散在 §10.2（#5）与 §12（#2、#19、#20）。

| 1 | 1Panel 对空字符串变量 / `${VAR:-default}` 的渲染行为未知（仅可选 Docker 形态） | compose 起不来 | 运营 | 打商店包前用最小 compose 实测 |

## 10.1 架构支柱级待核实（假设不成立要返工结构）

以下 6 条做最小原型，**不通过就不进入对应能力的编码**；原型按里程碑分组（M1 为 A 组三条 #16/#12/#4、M2 为 B 组两条 #15/#18、M4 为 C 组一条 #17），与 [§9.1 架构核实门](09-milestones.md) 是同一张表的两面——这里是「假设与证伪后果」，那里是「通过门槛与不通过的处理」。其余 4 条架构级风险中，#5 因含契约成分列在 §10.2，#2、#19、#20 的核实用例在 §12，不单独做原型。

| # | 架构假设 | 最小核实用例 | 证伪后要改的架构 | 里程碑 |
|---|---|---|---|---|
| 16 | landlock + 降权 = 隔离地基 | 在目标发行版矩阵上各跑三个恶意用例：读其他插件 `data/`、写宿主其他路径、UDP 外联。注意 Landlock 在 `open()` 时判定、**继承的 FD 不受限**，其网络维度仅较新 ABI 才有且只覆盖 TCP bind/connect | 隔离主力从 landlock 换成「独立 UID + 0700 目录 + 0600 内核数据」，landlock 降为加固；出网改走独立收口机制 | M1 原型 / M4 验收 |
| 12 | 独立 UID 同时满足隔离与「用户授权目录可写」 | 用一个非 root 授权目录（如 `www-data:0755`）走通「授权 → 写入 → 撤销」，并验证目录被重建后 ACL 是否丢失 | 权限模型增加 ACL 生命周期管理（`setfacl` 授予/撤销、重建重放），manifest 与 UI 授权流程同步调整 | M1 原型 / M4 |
| 4 | 路径校验能封住 bind 逃逸 | 竞态用例（校验通过后把中间目录换成 symlink）+ 四种 named volume 变体（`o=bind`、`type=none`、`device=<host-path>`、既有卷携带 bind） | 路径下传改为 fd 传递（`openat2(RESOLVE_BENEATH)` 优先），并补「最低内核版本 + 发行版支持矩阵」到架构前提 | M1 |
| 15 | 三层控制闭环，且 grant 语义稳定 | 「授予既有容器 → 该容器被删除重建 → grant 是否仍生效」；插件给自建容器打 `io.skiff.owner=<self>` 是否被拒 | grant 改绑稳定标识（项目名 + 内容哈希），必要时把粒度收到项目级；否则整个授权模型要重做 | M2 |
| 18 | 迁移可回滚 | 造一个「先改外部资源（宿主 `nginx.conf`）再迁移失败」的插件，看回滚后的实际状态 | manifest 增「迁移可回滚性」声明；不可回滚的插件禁止自动升级，只允许显式停机升级 | M2 契约 / M4 验收 |
| 17 | nftables owner-match 可做出网收口 | 与 ufw、firewalld 共存（含一次 reload）+ 域名访问场景：白名单只有 IP/CIDR 时 UDP/53 是否放行 | 要么内建 DNS 代理与解析白名单，要么强制插件只用 IP；明确规则生命周期由 Skiff 独占，不与被管防火墙共享链表 | M4 |

## 10.2 契约级待核实（一次定死，改要迁移）

| # | 待定契约 | 怎么定 | 定错后的迁移成本 |
|---|---|---|---|
| 13 | 签名编码跨实现一致 | 把 §4.1 的签名输入固化为字节级 golden test vectors 进仓，SDK 与内核共用同一套 fixture 做 CI 比对 | 已在第三方插件上散开后格式无法回改，只能加版本 |
| 19 | 两遍解包的资源峰值 | 在目标盘测 100MiB 包 / 512MiB 总量 / 4096 条目的耗时与峰值磁盘占用 | 决定是否需要排队限流与安装期提示，改造成本中等 |
| 5 | SQLite 文件系统检测是否有效 | Docker 形态下 `statfs` 看到的是 bind mount 的 fs type，验证能否识破底层 NFS/CIFS | 放错数据等于丢库，只能事前拦，事后无法补 |
| 20 | 内核侧背压上限 | 给 Broker 定 per-plugin 缓冲/队列上限与慢消费者策略（当前只限了插件侧：帧 1MiB / 并发 8 / 队列 32） | 单个慢插件能撑爆内核内存，事后补要改 IPC 层 |
| 21 | 多级反代取第几跳 | CDN→Nginx→Skiff 下 `X-Forwarded-For` 的取值规则与 `trusted_proxies` 的层级模型 | 取错即限流旁路 + 审计污染，属安全回归 |

> 本轮审查新发现、原本 §10 未覆盖的 5 个架构缺口（最低内核矩阵、运行时授权语义、RLIMIT_AS 双轨、cgroup 进程树清理、插件 UI 的 opaque origin 行为）见 [§12.1](12-pending-tests.md)。
