# 11. 已拍板的决策（默认值，可推翻）

> 主文档：[DESIGN.md](../DESIGN.md) ｜ 本文件：§11 ｜ 上一章：[§10 风险](10-risks.md) ｜ 下一章：[§12 待实测清单](12-pending-tests.md)

按“缺口按通用默认值处理并标注”收口，不再留阻塞实施的开放问题：

| # | 决策点 | 拍板 | 备注 |
|---|---|---|---|
| 1 | 发布渠道 | **本期**：systemd 安装包直发（主）；1Panel 商店 Docker 包为可选受限形态 | 长期渠道未决策——是否自建商店、商店是否含插件皆未定（§1.4） |
| 2 | 插件信任模型 | **ed25519 签名 + TOFU 公钥导入**，不自建中心 PKI | 未签名默认拒装；`allow_unsigned` 仅开发用 |
| 3 | 插件分发渠道 | **未决策，不阻塞**——本期只定交付物 = 签名 `.wbpkg` | 直接分发可用；将来无论自建/第三方/商店上架都复用同一包（§1.4、§4.4） |
| 4 | 插件兼容承诺 | 内核并行兼容插件 API **N-1 主版本** | 破坏性变更升主版本 |
| 5 | 插件默认运行模式 | `on-demand`（空闲 300s 回收） | `resident` 须显式声明理由并计入预算 |
| 6 | 插件 UI 隔离 | 沙箱 iframe（opaque origin）+ postMessage 桥 | 同源 `import()` 是会话级 XSS 面，否决 |
| 7 | 插件进程权限 | 每插件独立降权 UID/GID，不进 docker 组 | 封死直连 docker.sock / 读库旁路；权限用于防误用，沙箱用于约束与减灾，不宣称可彻底防恶意原生代码 |
| 8 | 插件流式场景 | 流式不经过插件，UI 直连内核 API | 控制面/数据面切分，保住 N-1 兼容承诺 |
| 9 | **部署形态** | **全家 native（systemd 直装），插件落宿主机** | 容器内 fork 不出宿主进程；插件体系要成为真核心必须开放宿主能力面（2026-10-30 拍板）；Docker 包降级为可选受限形态 |
| 10 | 内核能力面 | `docker` / `identity` / `fs` / `net` 四类，Broker 逐次校验 | 文件/防火墙/网站等具体功能在插件层，内核不内置 |
