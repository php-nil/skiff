# 11. 已拍板的决策（默认值，可推翻）

> 主文档：[DESIGN.md](../DESIGN.md) ｜ 本文件：§11 ｜ 上一章：[§10 风险](10-risks.md) ｜ 下一章：[§12 待实测清单](12-pending-tests.md)

按“缺口按通用默认值处理并标注”收口，不再留阻塞实施的开放问题：

| # | 决策点 | 拍板 | 备注 |
|---|---|---|---|
| 1 | 发布渠道 | **本期**：systemd 安装包直发（主）；1Panel 商店 Docker 包为可选受限形态 | 长期渠道未决策——是否自建商店、商店是否含插件皆未定（§1.4） |
| 2 | 插件信任模型 | **ed25519 签名 + TOFU 公钥导入**，不自建中心 PKI | 未签名默认拒装；`allow_unsigned` 仅开发用 |
| 3 | 插件分发渠道 | **未决策，不阻塞**——本期只定交付物 = 签名 `.wbpkg` | 直接分发可用；将来无论自建/第三方/商店上架都复用同一包（§1.4、§4.4） |
| 4 | 插件兼容承诺 | 内核并行兼容插件 API **N-1 主版本** | 破坏性变更升主版本 |
| 5 | 插件默认运行模式 | `on-demand`（空闲 300s 回收） | `resident` 须显式声明理由并计入预算 |
| 6 | 插件 UI 隔离 | 沙箱 iframe（opaque origin）+ postMessage 桥 | 同源 `import()` 是会话级 XSS 面，否决 |
| 7 | 插件进程权限 | 每插件独立降权 UID/GID，不进 docker 组 | 封死直连 docker.sock / 读库旁路；权限用于防误用，沙箱用于约束与减灾，不宣称可彻底防恶意原生代码 |
| 8 | 插件流式场景 | 流式不经过插件，UI 直连内核 API | 控制面/数据面切分，保住 N-1 兼容承诺 |
| 9 | **部署形态** | **全家 native（systemd 直装），插件落宿主机** | 容器内 fork 不出宿主进程；插件体系要成为真核心必须开放宿主能力面（2026-10-30 拍板）；Docker 包降级为可选受限形态 |
| 10 | 内核能力面 | `docker` / `identity` / `fs` / `net` 四类，Broker 逐次校验 | 文件/防火墙/网站等具体功能在插件层，内核不内置 |
| 11 | crate 拆分粒度 | **维持现状（17 crate + xtask），暂不动** | 2026-11-01 复核时实测 65 个 `.rs` 约 1.7 万行；2026-11-02 全量实测 83 个 `.rs` / 21,536 行，结论不变。双消费方/信任边界/判定裸测类拆分有硬约束，`compose`、`app` 最薄但各有实测动机；同日 `cron` 从 `plugin` 拆为独立 crate（内核调度 / 装包校验 / 计划任务插件三处共用），计数 13 → 14；其后 `sched` / `fs` 独立成 crate；2026-11-16 `host` 从 `core` 抽出为共享执行通道（内核与插件能力面共用），当前 17。重审触发条件：`compose` 与 `docker` feature 拆分再议（若 xtask 瘦身诉求消失）、`app` 膨胀成杂物间时收口，其余不碰 |
| 12 | 发布物完整性 | **只验 detached `SHA-256` 摘要，不做签名**（2026-11-01 拍板） | 发布物信任锚是「装机的人自己核对摘要」，防的是传输损坏，不是渠道投毒——真要防投毒得配公钥分发体系，对自用/小范围分发成本大于收益（对照 1Panel：同域 checksums 且新装路径实际不比对）。`RELEASE_SIGNING_KEY_HEX` secret、`.sig` 产物、`skiff-plugin sign-file/verify-file` 链路整体移除；**插件包 `.wbpkg` 签名/TOFU 不受影响**（决策 2 不变） |
| 13 | 执行型特权动词扩展 | **`exec` 能力面（粗授权 + 全审计 + 运行记录）**：三条路由（提交/状态/取消）+ 权限串 `exec:run` + 对象授权 `bin:<绝对路径>`，内核只校验二进制身份，**执行过程落任务中心的 `host.exec` 作业**（与环境安装共用进度、日志、取消），请求阶段审计 argv 全文；**不做命令模板 DSL**（2026-11-16 拍板，同日否决原方案 A） | 修订决策 #10 的词汇表口径：判定型能力面（fs 路径代数 / docker / identity / net 出网收口）留内核，执行型走 `exec` 的 `bin:` 授权——授权粒度是二进制（授 `apt-get` 即等价 root，明示粒度），换来「新宿主功能零内核改动」。记录分流是本决策的一部分：**文件读写进审计（90 天，安全追溯），任务执行进运行记录（过程、输出、退出码）**——命令耗时由命令自己决定，同步等结果会把「慢」变成「超时失败」。否决方案 A（manifest `[[host_action]]` 命令模板）：表面积三倍、白名单与槽类型仍是内核封闭集合、4000 行迁移无用户价值。特权伴随进程否决。设计见 [HOST_EXEC_DESIGN.md](../plugin/HOST_EXEC_DESIGN.md)，契约见 [KERNEL_EXEC_CONTRACT.md](../contract/KERNEL_EXEC_CONTRACT.md)；内核底层已落地，`ftp`/`firewall` 冻结为 legacy，未上机验收 |
