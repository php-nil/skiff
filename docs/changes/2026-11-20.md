## 页面 URL 按一级菜单分组统一

**背景**：页面 URL 此前按资源平铺在入口根下（`/{p}/containers`、`/{p}/runtimes`、`/{p}/audit` 等），与侧栏一级菜单的分组关系不一致。本批把页面 URL 收拢到一级分组下，接口路径（`/ui/v1/*`、`/api/v1/*`）与长连接端点保持不变。

### 1. 新页面 URL

| 分组 | 旧 URL | 新 URL |
| --- | --- | --- |
| 网站 | `/{p}/sites`、`/{p}/runtimes` | `/{p}/sites/list`、`/{p}/sites/runtimes`（详情 `/{p}/sites/runtimes/{id}`） |
| Docker | `/{p}/containers`、`/{p}/images`、`/{p}/networks`、`/{p}/volumes`、`/{p}/compose`、`/{p}/settings/docker` | `/{p}/docker/containers`、`/docker/images`、`/docker/networks`、`/docker/volumes`、`/docker/compose`、`/{p}/docker/settings` |
| 插件 | `/{p}/plugins`、`/{p}/store`、`/{p}/store/confirm` | `/{p}/plugins/installed`、`/{p}/plugins/store`、`/{p}/plugins/store/confirm` |
| 设置 | `/{p}/settings`、`/{p}/audit` | `/{p}/settings/security`、`/{p}/settings/audit` |

### 2. 代码改动

- `crates/app/src/menu.rs`：内置 L2 的 `href` 全部改为新路径；插件空态链接统一为 `/{p}/plugins/{tab}`。
- `crates/web/src/handlers/spa.rs`：壳页白名单收缩为 `sites`、`docker`、`files`、`plugins`、`settings`、`tasks`、`jobs`。
- `crates/web/static/budding/budding-boot.js`：`BUILTIN_PAGES`、`SUBVIEW_TABS`、隐藏路由与页面内跳转全部换新路径；站点详情的 blocked 段新增 `list` / `runtimes`，避免把 `/sites/list`、`/sites/runtimes` 误判为域名。
- `crates/web/src/lib.rs`：为 `/{p}/plugins/store/confirm` 增加显式壳页路由（该路径会被通用插件功能页路由 `/{p}/plugins/{id}/{view}` 抢先匹配）。
- `crates/web/src/handlers/auth.rs`、`middleware.rs`：首登强制改密跳转与放行路径改为 `/{p}/settings/security`。
- `crates/web/src/handlers/sites.rs`、`ui/plugins.rs`：跨页深链与安装完成后的 `redirect_to` 同步新路径。
- `crates/web/src/assets.rs`：`SHELL_VERSION` 升到 `9`，避免前端路由表被旧缓存命中。
- 旧路径不做兼容跳转（测试开发阶段，按 `AGENTS.md` §4.2 不保留旧版本迁移）。

## 站点详情：主键深链、伪静态、限速与可调备份计划

**背景**：站点详情此前用主域名做页面与接口路径，域名调整会打断深链；vhost/日志 code 组件显示语言标签；备份固定每日 03:00；PHP 站无法配伪静态；站点目录需要手动去文件管理里找；nginx 内置限速能力未暴露。

### 1. 行为与接口

- 站点深链与 `/ui/v1/sites/*` 写接口统一改用站点主键：`/{p}/sites/{id}`、`GET /ui/v1/sites/{id}`、`POST /ui/v1/sites/{id}/{default,domains,config,policy,ssl,backup,delete,logs,action}`；主域名只用于展示与删除确认。
- 新增 `POST /ui/v1/sites/{id}/policy`（动作 `site.set_policy`）：保存伪静态预设与出口限速并重生成 vhost。
  - 伪静态仅 PHP 站：`none` / `wordpress` / `laravel` / `thinkphp`，规则文本由内核白名单生成，不拼接用户输入。
  - 限速为 nginx `limit_rate`（KB/s，0 不限制，上限 4 GiB/s）。
- `POST /ui/v1/sites/{id}/backup` 增加 `interval`（`daily` / `weekly` / `monthly`）与 `time`（本地 `HH:MM`）；站点详情备份卡可直接改计划，关闭后计划与历史保留。
- 站点详情的 vhost 配置与日志 code 组件不再显示语言标签；站点目录/文档根各加「打开文件管理」深链（`/{p}/files?path=`）。

### 2. 代码与数据

- `crates/store/src/db.rs`：schema v22，`sites` 增加 `rewrite`（默认 `none`）与 `limit_rate_kbps`（默认 0）；`sites.rs` 增加 `site_by_id`、`set_site_policy` 与默认值用例。
- `crates/app/src/sites/vhost.rs`：`VhostPolicy` 注入 vhost 生成；PHP 按伪静态预设渲染 `try_files`/`rewrite`，所有类型按限速渲染 `limit_rate`；新增校验与 golden 用例。
- `crates/app/src/sites/crud.rs`：`set_site_policy` 先落库、再写站点与默认站 vhost、`nginx -t` 后重载，失败回滚库与文件。
- `crates/app/src/tasks.rs`：站点备份计划支持间隔 + 时间解析与反解；关闭时仍保留/登记计划，不再强制每日 03:00。
- `crates/web/src/handlers/ui/sites.rs`、`dto.rs`、`templates.rs`：站点路由改主键、`SiteItem` 增加 `id/rewrite/limit_rate_kbps`、备份信息增加 `interval/time`。
- `crates/web/static/budding/budding-boot.js`：路由与所有站点写操作改 `id`；配置标签页新增「伪静态与流量限制」卡；备份卡新增计划表单；code 组件通过 `skiff-code-no-lang` 隐藏语言标签；`SHELL_VERSION` 升到 `10`。

### 3. 文档

- 契约：`docs/contract/URL_CONTRACT/{01-RULES,02-ROUTES}.md`、`SITE_RUNTIME_CONTRACT/{01-MODEL,03-ROUTES_SCOPE}.md`、`KERNEL_SCHEDULER_CONTRACT/02-WAKE_PERSIST.md`；实现说明 `docs/impl/KERNEL_SCHEDULER_IMPL_NOTES.md`；上机矩阵 `docs/test/TEST_MATRIX/03-FS_SCHEDULER.md`。

## 即时修复：站点详情 URL slug → id 重定向（`b0db64d`）

**触发**：用户反馈浏览器里出现 `/sites/a.com/domains`（域名当 URL 段），契约（URL_CONTRACT §2.1/§2.2/§3.2）明确站点 URL 只暴露主键 id。

**根因链路**：
1. **壳页 SUBVIEW_TABS**（`budding-boot.js`）站点详情 pattern `['sites', ':id']` 下，tab 路径是 **段式拼接**（`/sites/:id/domains` 等），不会 query-string 化
2. 后端 API 层（`handlers/ui/sites.rs` 15 个路由）全部用 `Path<i64>`，**只接受数字 id**
3. 但 SPA shell handler（`fallback` / `method_not_allowed`）只做 path segment 边界匹配，**不**清洗 slug→id——任何 `/{p}/sites/{anything}` 都会返回壳页 HTML，壳页 JS 再把 `anything` 当 `:id` 传给 API → `GET /ui/v1/sites/a.com` → 400 parse error
4. 浏览器历史、收藏夹、旧链接都会积累 slug URL，壳页始终拿不到 id

**修复**（`spa.rs`）：
- 新增 `slug_to_site_id_redirect(state, path)`：对 `/{p}/sites/{seg}/...`，seg 不是纯数字且不是字面段（`new` / `list` / `web` / `runtimes`）时，查 `state.db().site_by_domain(seg)`，命中则 `AppError::Redirect`（`SEE_OTHER=303`）到 `/sites/{id}/...`；查不到则保持（壳页自行处理 404，不猜测意图）
- 同时在 `fallback` 和 `method_not_allowed` 两个 shell 入口都调用，确保所有 GET 壳页入口归一化
- 新增单元测试 `seg_looks_like_slug` 覆盖字面段/纯数字/典型 slug（含 `.`）三类判定；既有 `whitelist_matches_by_segment_boundary` 保持

**部署验证**（就地覆盖，不重装）：
- Run **185**（head `b0db64d`，publish success，amd64 包 `4a9e7002...ad`）→ 测试机 `cp skiff /usr/local/bin/skiff` + restart → healthz ok，schema v21
