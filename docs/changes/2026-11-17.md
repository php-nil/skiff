## FTP 安装提示错误但刷新显示正常 + 任务中心无记录

- **现象**：插件页点「安装 pure-ftpd」弹出失败提示，F5 刷新后服务已装好、状态正常；任务中心没有这条安装记录。
- **根因两条**：
  - **竞态**：`systemctl restart pure-ftpd` 返回零退出码后，pure-ftpd wrapper 读 conf、`authentication` 链重扫、端口绑定需要一个短暂窗口；代码紧接着调 `systemctl is-active` 只查一次，窗口内就会看到 `inactive`，直接判失败。刷新后用户看到的已经是 systemd 完成收敛的状态——所以「提示错误但实际好了」。
  - **任务中心无记录**：FTP 能力面所有命令走 `skiff_host::run` 同步直调（`systemd-run --wait`），不经过 `JobService`，整个 install/uninstall 没有任何作业提交。`exec` 能力面是唯一进任务中心的宿主命令入口，ftp/firewall 都没接。
- **修复（`crates/plugin/src/ftp.rs`）**：
  - 新增 `wait_until_active(host, service, max_wait_secs)`：每 500ms 轮询一次 `is-active`，最多 `max_wait_secs * 2` 次，首次命中 `active/activating/reloading` 即返回 true。
  - 三处立即检查全部改轮询：`apply_service_config`（install 路径，等 15s）、`service_restart` 能力面（等 15s）、内部 `restart_service`（账号操作后的重启，等 10s）。超时时返回明确错误（带 `systemctl status pure-ftpd` 提示），不再静默吞掉。
- **修复（`crates/core/src/kernel/ftp.rs`）**：
  - 新增 `is_job_method("install" | "uninstall")` 分流：长耗时方法先进任务中心。

## FTP 架构迁移：写操作全部迁到插件侧 exec 能力面编排

- **背景**：HOST_EXEC_DESIGN.md 早把 firewall / ftp 标注为「执行型域下放插件」的终局方向（§7 词汇表终态：留内核 `exec` 判定 + `skiff_host` 通道 + 作业记录；下放插件 `firewall / ftp`），2026-11-16 exec 能力面全部落地后只差迁移。本轮用户反馈触发了这张账单：ftp_call_with_job（临时在 ftp 内核 handler 外包 Job 提交）本质上是在一个本该被清空的 legacy 体系上加代码，方向和终局相反。
- **迁移范围**：
  - Manifest（`plugins/ftp/manifest.toml`）：
    - `requires = ["exec", "ftp", "interop"]`（加 `exec`）
    - `resource_hints` 新增 13 条 `bin:`（apt-get、dpkg-query、systemctl、pure-pw 双路径、tee、install、mkdir、ln、rm、cat、openssl、ldconfig）+ `plugin:com.skiff.firewall`（fail2ban 可选项）
    - `ftp` capability 的 verbs 从 11 条减到 3 条：只读 `status` / `sites.list` / `accounts.list`，写操作（install / uninstall / account.create / account.password / account.delete / account.set_enabled / service.configure / service.restart）全部删除
  - 内核 ftp 能力面（`crates/plugin/src/ftp.rs`）：
    - `dispatch_host` 路由表只保留 `status` / `sites.list` / `accounts.list`，其他方法返回 `FtpError::deny("方法 ftp.X 已迁移到插件侧 exec 能力面编排，请更新调用方")`
    - 常量 `PASSWD_FILE` / `PDB_FILE` / `CONF_DIR` / `AUTH_DIR` / `AUTH_DB_LINK` / `AUTH_STALE` / `SERVICE` / `UMASK` / `PURE_PW_CANDIDATES` / `SERVICE_CONFIG_FILE` / `MAX_TLS_SOURCE_BYTES` / `DEFAULT_*` 改 `pub const`，方便插件侧复用
    - 写操作函数（`install` / `uninstall` / `account_*` / `service_configure` / `service_restart`）内部的 `run_ok` / `run_raw` 宿主命令执行**暂未删除**——等 CI 验证后再清理（Windows 本机无 C 编译器，无法本地编译 skiff 主 workspace）
  - 内核 handler（`crates/core/src/kernel/ftp.rs`）：
    - 删除 `is_job_method` 分流 + `ftp_call_with_job` 整个函数——迁移后 ftp 能力面已经不执行写操作
  - 插件侧（`plugins/ftp/src/main.rs`）：
    - 新增 `exec_ok` / `exec_any` / `pure_pw_path` 三个辅助函数，等价于旧内核侧的 `run_ok` / `run_raw`：用 SDK `Plugin::host_exec_full` 调 exec 能力面，成功返回 stdout、非零退出转可读错误
    - `install` 完整重写为 exec 编排：apt-get install（带 Unable to locate package 重试 → apt-get update）→ mkdir conf/auth → 清理 Unix/PAM auth 链 → 建 PureDB 链 → tee 写 10+ conf 文件 → install 建 PureDB → disable openbsd-inetd → enable+restart pure-ftpd → 轮询 `systemctl is-active` 等待 active（最多 15s）→ 返回 `ftp_call("status")` 最新状态
    - 其他 7 个写操作（`uninstall` / `create` / `password` / `delete` / `toggle` / `restart` / `save_config`）**先 stub**：返回 `RpcError::internal("已迁移到 exec 能力面，完整实现待补")`——install 跑通后逐批补完整 exec 编排
    - 常量自管（`PDB_FILE` / `CONF_DIR` / `AUTH_DIR` / `AUTH_DB_LINK` / `SERVICE` / `UMASK` / `PURE_PW_A/B`），零 `skiff-plugin` 内核依赖
- **收益**：
  - 任务中心自动有运行记录——exec 能力面的核心就是作业化（submit + 轮询 + finalize 自动写 jobs 表），不需再 ftp_call_with_job 这种内核侧临时补丁

  - 宿主命令统一走 execgrant 三道闸——plugin 本体 / binary / resource hints，有审计日志

- **约束**：install 现在是同步等待（host_exec_full 内部用 std::thread::sleep 轮询，最大 timeout 900s），HTTP 请求会等完 apt-get。后续可改成 host_exec_submit + host_exec_status 轮询 + 前端 SSE/API 轮询的异步模式。
- **待补**：uninstall / account.* / service.configure / service.restart 的完整 exec 编排（参照 `crates/plugin/src/ftp.rs` 里原始的宿主命令序列逐行翻译）；`crates/plugin/src/ftp.rs` 里已无调用方的写操作函数 + `run_ok` / `run_raw` / `FtpHost::run_ok` / `wait_until_active` 清理（CI 验证后执行）；`PDB_FILE` / `AUTH_DB_LINK` / `UMASK` / `SERVICE` 等常量同步两处（插件侧自管 + 内核侧 pub const），后续考虑合并到公共模块。

## 上机验证暴露的防火墙 / FTP 功能缺陷修复

- **防火墙 rules.list**：原先返回的是 `nft -a list chain` 的原始行（含 `type filter hook...` 与 `}`），而 UI 列按 `action_text / protocol_text / port_text / source_text / id` 取值，表格全空。改为只解析带 `# handle <n>` 的规则行并拆出上述字段；iptables 同理只保留 `-A SKIFF ...`（原先 `starts_with('-')` 把所有规则都过滤掉了）。
- **防火墙 rule.remove**：原先按端口直接 `flush chain`，删一条会清空整链，且 UI 只传 `id`（端口为 0）实际删不掉。改为 nft 按 handle 精确删除；iptables 用 `-A SKIFF` 后的参数串拼 `-D`；无 id 时退化为按端口删第一条，不再整链 flush。
- **防火墙 rule.add / port.allow**：端口校验 1–65535；表单的「全部」协议展开为 TCP+UDP 两条（nft 不接受 `all dport`）；nft 支持 `ip saddr` 来源；`port.allow` 的 `both` 同样展开。
- **防火墙按需建链**：新增 `ensure_nft` / `ensure_iptables` / `ensure_managed_chain`，列表/加/删/放行前幂等创建受管表与带 hook 的 input 基链（全新机器首次打开不再报 `No such file or directory`）。
- **FTP 授权缺口**：`create` 走 `chown`/`mv`/`chmod`，manifest 资源提示缺 `bin:/usr/bin/chown`、`bin:/usr/bin/mv`（补上）；`align_tree` 原先用 `find -exec chmod`，`find` 属包装器被内核拒绝授权，改为 `chmod -R u=rwX,g=rwX,o=rX`（目录 0775 / 文件 0664）+ `chown -R`，并补 `bin:/usr/bin/chmod`。
- **防火墙资源提示**：补 `bin:/usr/bin/mkdir`（fail2ban 安装要建目录）。
- **契约**：`KERNEL_FIREWALL_CONTRACT.md` §3/§4 的 `id` 与 iptables 删除口径改为「`-A SKIFF` 后参数串」，注明行号会顺移的原因。
- **测试**：新增 `parse_nft_rules` / `parse_iptables_rules` 两条单测（结构行过滤 + 字段拆分），`cargo test --manifest-path plugins/Cargo.toml -p skiff-plugin-firewall` 2 passed。上机实测：`rules.list` 返回空列表、`rule.add` 后出现 `tcp dport 18081 accept # handle 2`、`rule.remove` 精确删除、`port.allow`/fail2ban 状态正常。
