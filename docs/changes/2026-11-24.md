## 三处体验修复：浮动镜像不刷新 / 侧栏品牌图标 / Web 服务状态页

**背景**：三条来自实际使用的反馈——① PHP 8.5 最新是 8.5.13，新装运行环境却仍是 8.5.12；② 后台侧栏顶部显示的「S」色块不是产品图标；③ Web 服务状态页的「安装已完成」顶上就是一大块绿色提示，且停止/重启按钮埋在正文卡片里。

### 1. 运行环境镜像：未登记 digest 时必须拉取

- **根因**：`ensure_runtime_image` 原逻辑是「本地已有该 tag 的镜像 → 回填 digest 并跳过 `ImagePull`」。目录里的 tag 是浮动的（`php:8.5-fpm-alpine`），于是「首次拉到的那一版」被当成本版本的永久实现：8.5.13 发布后，新装仍是 8.5.12，且再装几次都还是它。
- **改法**：把决策抽成纯函数 `plan_image_pull(image, registered_digest, local_digest) -> ImagePullPlan`：
  - 未登记 digest（新环境）→ **按 tag 拉取**；本地 digest 只作拉取失败时的回退（离线 / 镜像源不可达不再把装机打成失败，但会记一条警告，不留静默降级）。
  - 登记 digest 与本地一致 → `Reuse`，不拉取（同一实例重建保持同一版本）。
  - 登记 digest 与本地不一致 → 按登记 digest 拉取，**不允许**回退到漂移的本地镜像。
- 镜像已最新时 `docker pull` 只做 manifest 校验，新增开销可忽略；Web 服务（OpenResty）安装本来就是每次都拉，口径一致。
- **存量实例不会自动升版**：它的 `image_digest` 已登记，重建按 digest 走。要取最新补丁需删除该运行环境后重装（已写入契约文档）。
- 新增单测 `image_pull_plan_refreshes_floating_tag_and_pins_registered_digest` 覆盖四种组合；`TEST_MATRIX/02-SITE_WEB` 新增上机用例 SITE-22（旧补丁镜像在宿主时重装必须取到新补丁），`00-USAGE` 计数 15 → 16 同步。

### 2. 侧栏品牌标记换成产品图标

- 上游 `admin` 外壳的 `.bud-admin__mark` 默认渲染「品牌名首字母 + 强调色方块」（Skiff → `S`），且没有品牌图标 prop；`brand` 插槽只能由节点能力 `provideSlots` 提供，JSON 无法注入。
- `skiff-shell.css` 用入库的 `favicon.svg` 覆盖该标记：相对样式表解析 → `/<入口前缀>/static/favicon.svg`（不写绝对路径，自定义前缀下不会 404），首字母用 `font-size: 0` 藏掉；选择器 `.bud-admin .bud-admin__brand .bud-admin__mark` 压过上游 scoped 规则。
- `assets.rs` 新增用例钉住「必须引用 favicon.svg / 必须相对路径 / 选择器层级」；`SHELL_VERSION` 48 → **49**（样式带 `?v=` 命中 immutable，不升就是旧样式）。

### 3. Web 服务状态页：完成态收敛 + 启停/重启上移页头

- **页头主操作**：安装 / 停止（启动）/ 重启 迁到 `page_with_actions` 的 `content.actions`（与标题同行、右对齐）；重新安装与删除容器留在正文「重新安装与删除」卡片（破坏性动作不占页头）。原「容器运维」卡片随之改名。

### 6. ctx 传递纠偏（重构后发现的 UX 回归）

运行环境写函数原来的 `.catch(runtimeFail)` 是 toast（顶部提示），重构时误传了 `ctx: ctx` 给 writePost，会走默认 onCatch 的 formError（表单内联错误）。修复 6 个函数去掉多余的 ctx：

- `runtimeImagesWrite` / `runtimeNodeWrite` / `runtimeFileWrite` / `runtimePecl` / `runtimeClone`：原来 catch 是 runtimeFail（toast），去掉 `ctx: ctx`。
- `webConfigWrite`：原来 catch 是 toast，去掉 `ctx: ctx`。

**行为保持**：只有原来就用 formError 的函数（`runtimeCreate` / `uiThemeWrite` / `file*` 系列 / `composeEdit`）保留 ctx 传递。其余全部走 toast 风格错误展示。

- `dockerWrite`（53L）：容器写操作有条件 reload + 条件 toast + 自定义 payload 映射，强行接 writePost 反而让代码更难读。
- `siteWrite`（151L）：站点写操作最大函数，多分支（新建/保存/启停/删除/域名/证书），条件跳转和条件 toast 密集；值得后续单独拆分但本批次不动。
- `runtimeProbe`（12L）：探测操作成功时可能返回 warning 级别 toast 且不 reload（与 writePost 默认行为冲突）；强行接入反而让代码更长。
- **文件体积**：gzip 后实际传输体积需部署时实测，当前只做了源码级静态清理。

## 镜像服务清单：固定路径 + 服务端生成（取代上面的取数口径）

**背景**：上一批让用户手填清单地址（`sites.runtime_index_url`），既不固定也不强制，还会出现「镜像前缀指 A、清单指 B」的漂移；镜像服务实际只需提供一份 `php.json`。

### 1. 路径定稿

- `<镜像基址>/channels/<channel>/runtime-index/php.json`：基址取 `[catalog].mirrors` 首项（默认 `http://10.66.52.7:8080`，一期只走 HTTP），渠道取 `[catalog].channel`（默认 `stable`）。与目录客户端自己拼 `{base}/channels/{channel}/index.json` 同一条规则，`mirrors = []` 仍表示「不联网」。
- 落在渠道目录下是因为服务端产物里 `channels/<name>/` 是唯一可变层（`blobs/` 内容寻址、`schema/` 随产物）；`01-DESIGN.md` §2.2 的树与环境已补上该文件。
- 删除 `sites.runtime_index_url`：Docker 设置页不再有输入框，改为一律只读的「生效地址」；`DockerSettingsBody` 去掉该字段，`docker_settings::apply_settings` 去掉写库与清缓存分支。**地址不可配 = 没有第二份真相。**

### 2. 服务端生成

- `tools/skiff-server/src/build.rs` 新增 `runtime_index_bytes`：从该渠道 `runtimes/` 里 `kind=php` 且未 `yanked` 的条目生成，版本**数值降序**、`generated_at` 取渠道时间戳（不取系统时间，保证同输入同字节）；无条目时不落盘（面板 404 → 回退内置副本，语义清晰）。
- 新增 `deploy/skiff-server/schema/runtime-index.schema.json` 并纳入 `SCHEMA_FILES`（9 份），产物随之带 `schema/`。
- `serve.rs` 白名单只放行 `channels/<ch>/runtime-index/php.json` 及其短别名，其余子路径仍 404；`07-SERVE.md` §16.2 补两行、§16.5 注明清单**不是**客户端硬依赖。

### 3. 文件格式 v1

```json
{"schema":"skiff.server.runtime-index/v1","kind":"php","channel":"stable",
 "generated_at":"2026-11-24T12:00:00Z","versions":[{"version":"8.5.13","default":true}]}
```

- 只放面板真正消费的字段：`version` / `eol` / `default`。**与设计稿的差异**：原计划一并下发 `image` / `image_digest` 供「按 digest 锁定安装」，本期去掉——按 digest 锁定会把「镜像尚未同步」变成硬安装失败，需要单独设计失败面；先下发没人消费的字段还会诱使有人手填假 digest。等锁定方案落地再以 v2 加，旧客户端按「未知字段忽略」不受影响。

## 运行环境版本清单扩到三类（php / node / rust）

**背景**：上一批只把 PHP 的补丁号接到了镜像服务；Node.js / Rust 仍是自由输入框（`version_other`），用户得自己记住 `24` / `1.99` 这种写法，清单机制等于只覆盖三分之一。

### 1. 口径：按类型分文件

- 路径从"只有 `php.json`"扩为 `channels/<channel>/runtime-index/<kind>.json`（`php` / `node` / `rust` 各一份）。这条本来就在 `01-DESIGN.md` §2.2 的命名里，此前只是"当前只产 php"，现在兑现。
- **某类型没有 `runtimes/` 条目就不产出该文件**：面板取到 404 回退（PHP 用内置副本、Node/Rust 用目录大版本），比产一份空清单更诚实。
- 服务端 `build`：`RUNTIME_INDEX_KINDS` 逐 kind 生成，`runtime_index_bytes` 增加 `kind` 入参；`serve` 白名单放行三个文件名，同目录其它文件仍 404。

### 2. 内置副本只对 PHP

- Node.js / Rust **不造**内置副本：可选版本是 LTS/stable 大版本，目录本身就是权威；更要紧的是内置副本 `generated_at` 一旦比产物新，回滚保护会把服务端清单**永久**判成"更旧"（`TEST_LEDGER` 已记过一次）。
- 因此 `VersionIndex.source` 新增语义：`catalog` = 目录大版本回退，与 `builtin`（PHP 快照）并列。

### 3. 「服务端未发布」不是故障

- `fetch_index` 返回 `Fetched::{List, NotPublished}`：HTTP 404/410 记 `NotPublished`，不再当失败。
- `VersionIndex` 新增 `failed: bool`，取代原来"`error` 非空即失败"的隐式判据：`error` 变成**展示原因**（可能是"未发布"，也可能是"超时"），`failed` 只决定缓存 TTL（60 秒 vs 10 分钟）。否则 404 会每 60 秒重打一次网络。
- `parse_index` 允许 **1–3 段**纯数字版本（Node 的 LTS tag 是单段 `24-alpine`，原来按 2–3 段判定会被全部丢弃、清单恒为空）；版本都合法但大版本不在目录时报「不在目录支持范围内」，让上层回退而不是给空下拉。

### 4. 面板

- `runtime_index`：`KINDS`（三类顺序）、`index_file(kind)`、`index_url(state, kind)`、`fixed_index_url(base, channel, kind)`；`load` 对所有 `KINDS` 生效（不再只有 PHP 打网络）。
- `catalog_json`：`version_index` → **`version_indexes: {php, node, rust}`**（单一结构，不再有"PHP 专用字段"），每份带 `source / failed / pending / remote / url`。
- 弹窗：版本字段按目录 key 生成 `version_<kind>`（`visibleOn: "${kind === '<kind>'}"`），不再有 `version_other`；「自定义版本」保留且优先。提示行改为「版本清单来源：PHP 镜像服务 · N 个版本；Node.js 目录大版本：镜像服务未发布 node.json 清单（HTTP 404）…」并给出清单目录。
- 壳脚本：`runtimeCreate` 取 `version_custom || v['version_' + kind]`（原来按 php > other 硬编码，切到 Node 时 `version_php` 的默认值会抢先）；「刷新版本清单」串行刷三类，`failed` 才告警、"未发布"只提示来源。`SHELL_VERSION` 51 → **52**。
- `GET /ui/v1/runtimes/versions` 增加 kind 白名单校验（未知类型 400，避免拼出不存在的地址）。

契约 §4.1/§4.5（三类下拉、按 kind 分文件、内置副本只 PHP、404 语义）、`URL_CONTRACT/02-ROUTES`（`kind=php|node|rust`）、`SKIFF_SERVER`（§2.2 目录树与说明、`04-ROLLOUT` 产物、`07-SERVE` §16.2/§16.5、一页结论）、`06-BRIDGE-PAGES-B`、`TEST_MATRIX/02-SITE_WEB` SITE-23（改成三类逐项验收）、`TEST_LEDGER`（夹具缺 node/rust 条目、未签名口径改 `<kind>.json`）。

- `visibleOn: "${kind === '<kind>'}"` 与 budding 1.8.7 的 `expr.condition` 契约一致（`packages/ui-vuetify` 的表单用例同形，单引号字面量由 `lexer.readString` 支持）；三类下拉的 `initialValues` 按 `version_<kind>` 各给一份，切换类型不需重选。
- `runtimeCreate` 取 `version_custom || v['version_' + kind]`，与后端「空则取目录首项」互补；`9.0.1` / `8.5.13-beta` / `8.5.13.1` 被 `version_supported` 拒。
- `runtime-index.schema.json` 的 `type: ["string","null"]` 与 `minLength/maxLength=20` 都在自带校验器支持范围内；`generated_at` 由 `channel.validate()` 保证是 20 字符 UTC RFC3339，不会因长度被 schema 拒。
- `check` / `release` 按整张 `artifact.files` 处理，新增目录不被丢弃（`write` 先清空输出目录，删条目后不会残留旧 `node.json`）。
