## 升级安装同步随包官方插件

- 缺口：`install.sh` 只把 `official/*.wbpkg` 复制到 `/www/skiff/official/`，升级后已装插件
  的 `versions/<ver>` 仍是旧内容（实测 cron `ui/app.js` 仍是旧哈希），插件 UI 修复需人工重装。
- 方案：内核启动早期（`bootstrap`，在自动信任官方公钥之后、拉起插件之前）调用
  `skiff_plugin::sync_official_plugins`，新增 `crates/plugin/src/official.rs`：
  - 只处理库内**已安装**插件；未安装的包仍不自动安装（首次授权确认不能被启动流程绕过）。
  - 版本更高，或同版本但已装版本目录与包的文件集合/SHA-256 不一致时，复用
    `install_package` 重装：`data/` 不动、既有 grants 原样沿用、manifest 新增声明不自动授予。
  - 安装器会把记录重置为 `enabled=true/installed`；同步后对原本停用的插件恢复
    `enabled=false/status=disabled`，不改变管理员意图。
  - 包版本低于已装版本直接跳过；单包失败只 `warn` 并继续，日志打印可人工重试的
    `skiff plugin install <包>` 命令；坏包不阻断面板启动。
- 涉及文件：`crates/plugin/src/official.rs`（新增）、`crates/plugin/src/lib.rs`、
  `crates/plugin/Cargo.toml`（`hex`）、`crates/core/src/bootstrap.rs`；
  部署侧仅同步文案：`deploy/install.sh`、`deploy/pack-release.sh`、`docs/DEPLOY_TEST.md` §2.5/§2.11。
- 本地验证：`cargo test -p skiff-plugin --locked` 37 passed（含同版本内容更新保 data/授权、
  高版本升级、降级跳过、幂等、未装跳过 + 坏包隔离、停用状态保留）；`cargo test -p skiff --locked bootstrap`
  8 passed（含坏官方包不阻断启动）；`cargo fmt --all --check` 与
  `cargo clippy -p skiff-plugin -p skiff --all-targets --locked -- -D warnings` 通过。
- 待上机复验（未发版）：
  1. 装旧版并安装 `cron` 等官方插件，记录 `versions/<ver>/ui/app.js` 的 sha256、
     `plugin_grants` 条数、插件 `data/` 内文件与 sha256。
  2. 用新发布包覆盖安装（`sh install.sh`），确认 `/www/skiff/official/` 已换新包后启动。
  3. 确认已装插件的 `ui/app.js` 哈希等于新包内容、`plugin_grants` 条数/内容不变、
     `data/` 文件未变；停用某个插件后重复升级，确认仍为停用。
  4. 放入一个坏 `.wbpkg` 再启动，确认面板正常启动且日志有失败包路径与重试命令。

## Docker 页：内核容器保护标签与容器删除入口

- `crates/app/src/sites.rs`：`skiff_labels` 统一追加 `io.skiff.protected=true`，
  覆盖 Web 服务 nginx、PHP/Node/Go/Rust 运行环境的唯一创建路径 `ensure_container`。
- 存量容器：Docker 标签不可后加，选择「只对新容器生效 + 页面标注」而非启动重建；
  `crates/docker/src/client.rs` 新增 `ContainerRow.unprotected_kernel`，
  `io.skiff.project=sites` 且缺保护标签时在列表/详情显示「存量未受保护」。
  代价：旧容器需重建 Web 服务或运行环境后才受保护。
- `crates/web/src/handlers/containers.rs`：新增 `remove` 动作 → `Verb::ContainerRemove`，
  走 `Docker::execute(ContainerRemove { force: true })`；受保护容器沿用 stop/restart
  同一策略判定 403；`crates/app/src/sites.rs::container_busy_reason` 按 BusyGuard 语义
  对执行中任务/安装中的容器返回 409；列表与详情按 `DockerLifecycle` 显示删除按钮并二次确认；
  删除后回列表。
- 单测：策略（正常放行/受保护拒绝/存量不误判）、docker（缺标签存量识别）、
  app（三类内核容器规格带标签、BusyGuard 空闲/占用）、web（remove 动作白名单）。
- 待上机复验（未发版）：重建内核容器后核对三个容器标签、面板 stop/restart 403；
