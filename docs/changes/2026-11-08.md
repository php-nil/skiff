## 后台端口 / 入口前缀 / TLS 可配置（含三态 Cookie）

- 配置结构（单一来源，不拆两套）：
  - `Config` 新增 `tls_enabled: Option<bool>`（三态）、`entry_prefix: Option<String>`、`tls_active: bool`；
    `FileConfig` 同步，环境变量 `SKIFF_TLS_ENABLED`（`true/false/on/off/1/0`）与 `SKIFF_ENTRY_PREFIX`。
  - `tls_enabled = true` 必须有 `tls_cert`/`tls_key`，缺失拒绝启动且报错可读（指出字段、提示改 `false`）；
    `tls_enabled = false` 直接明文，不读证书、不生成自签；不写 = 旧行为自动推断（loopback / 反代 / 拒绝裸奔）。
  - 入口前缀显式值（config / env）优先并同步库；未配时首启随机 8 位落库。已有部署不改入口。
- 三态 Cookie（`crates/identity` 侧按 `dev_http` 判定）：
  - TLS 开启 / 反代终止 TLS：`__Host-skiff_session` + `Secure`（不变）。
  - 直接明文（`tls_enabled=false`）：`skiff_dev_session`，无 `Secure`、无 `__Host-`，HttpOnly/SameSite 保留；
    浏览器 HTTP 下登录、改密可走通，不再依赖反代/转发进程。
  - `allow_insecure_http` 语义收窄为「直接明文监听」；`trusted_proxies` 仍是「反代终止 TLS 时采信哪些 peer 的
    `X-Forwarded-*`」。显式 `tls_enabled=false` 时两者不参与判定。
- 启动与页面：明文非 loopback 时日志打一行「明文 HTTP 监听：Cookie 已降级，仅限内网或反代之后」，
  设置页显示醒目告警；启动地址 scheme 由 `tls_active` 决定。
- 设置页（「设置 → 后台端口 / 安全入口 / TLS」，仅管理员）：
  - 读取/修改 `listen`、`entry_prefix`、`tls_enabled`、`tls_cert`、`tls_key`，POST 保存写回 `config.toml`。
  - 端口 1–65535、`TcpListener::bind` 占用探针（同当前监听视为自己占用）；前缀 6–32 位 ASCII
    字母/数字/`-`/`_`、首字符字母或数字、不得为 `/`、保留段（`api`/`healthz`/`static`/`assets`/`favicon.ico`/`robots.txt`）。
  - 写盘：按 key 原位替换、去重复键、`toml` 解析复验、临时文件 rename；保留注释与其他字段。
  - 生效方式：**重启生效**，页面明确提示，不静默失败。
  - 防锁死：旧前缀 24h 内 GET 302 到新前缀（`settings.security.entry_prefix_previous` +
    `..._previous_until`），窗口外 404；新前缀始终可用。
- 安装脚本：`--tls on|off`、`--tls-cert`、`--tls-key`、`--no-tls`、`SKIFF_TLS`；on 时复制证书到
  `/etc/skiff/tls/`（0600）并写 `tls_enabled=true`，缺证书可读报错；off 写 `tls_enabled=false` 并告警。
  `systemd` 的 `ReadWritePaths` 补 `/etc/skiff`，否则设置页写不回配置。
- 涉及文件：`crates/core/src/{config,server,main,bootstrap}.rs`、`crates/app/src/{lib,panel_settings}.rs`（后者新增）、
  `crates/web/src/{lib,middleware,handlers/settings,templates}.rs`、
  `crates/web/templates/settings.html`、`deploy/{install.sh,config.toml.example,systemd/skiff.service}`。
- 验证：`crates/core` 新增 `tls_enabled_without_cert_fails_readably`、
  `tls_off_allows_lan_plaintext_and_downgrades_cookie`（断言两种 Cookie 名）、`invalid_entry_prefix_fails_startup`；
  `crates/app/src/panel_settings.rs` 覆盖前缀合法/非法/保留段、端口 0、占用检测、保留注释/去重、父目录不存在。
  门禁命令与结果见文末「验证」。

## 工具 → 文件管理 读取目录 404

- 根因：`crates/web/static/files.js` 的 `apiUrl()` 用相对路径。页面 `/{p}/m/core/files` 下
  `fetch("api/list")` 被解析成 `/{p}/m/core/{p}/files/api/list`，路由不存在 → HTTP 404。
  与插件是否安装、grants、iframe 地址拼接无关（插件已装、RPC 正常）。
- 修复：`apiUrl(path) => "/" + prefix + "/files/api" + path`（绝对路径）。
- 回归：`crates/web/src/assets.rs` 新增 `files_js_builds_absolute_api_urls`，断言脚本内含绝对路径拼接。
- 复验：打开「工具 → 文件管理」，`GET /{p}/files/api/list?path=...` 应为 200 且列出目录；
  浏览器 Network 面板里请求 URL 不应出现重复的 `/{p}/m/core/`。

## FTP 能力面扩容与插件接线

- 内核 `ftp` 能力面新增 `service.configure`（校验并持久化服务配置）与 `account.set_enabled`
  （启用/禁用账号）；`install` 入参扩展为 `listen_port`、`passive_port_start`、`passive_port_end`、
  `max_clients`、`max_per_ip`、`tls_mode`、`tls_cert_path`、`tls_key_path`、`login_guard`，均可选。
- 服务配置以 `/etc/skiff/ftp-service.json` 为唯一真相来源（systemd `ReadWritePaths` 已覆盖 `/etc/skiff`）：
  未安装时只落盘，已安装时立即写 conf/TLS 并重载；插件侧 `service-config.json` 删除，避免双份真相漂移。
- `status` 回传真实运行态：安装/运行/监听/监听端口/当前连接数/连接上限/TLS/账号启停计数，
  以及 fail2ban 的 `installed`/`running`/`jail_configured`/`jail_enabled`/`currently_banned`/
  `total_banned`/`recent_ban`；探测失败的字段回传 `null`，不用 0 冒充。
- TLS：`off` / `optional`（显式 TLS、可选）/ `required`（强制）三态，`explicit` 作为 UI 别名；
  证书与私钥先校验再合并写入 `/etc/ssl/private/pure-ftpd.pem`（0600），路径缺失或内容非法返回可读错误，
  不静默回退自签。
- 账号：`account.set_enabled` 只改 passwd 行的 `#` 前缀并重建 PureDB；禁用后登录失败、账号与目录保留。
  `accounts.list` 明确回传 `last_login=null` / `last_login_source=unavailable`，不伪造最后登录时间。
- fail2ban：不是内核内置，首装且 `login_guard=true` 时随 pure-ftpd 一起装；只写
  `/etc/fail2ban/jail.d/skiff-pureftpd.conf`，关掉开关只移除本插件 jail，不卸载包、不动其它 jail。
- 审计：成功时只记定位摘要（监听端口、被动范围、TLS 模式、登录防护、是否已应用；账号只记登录名与启停），
  密码与私钥内容不入审计。
- `plugins/ftp` 接线：manifest 增补两个动词；服务配置面板改由内核 `status`/`service.configure` 驱动，
  账号页支持启停；新增 `ui/base.css` 统一插件内样式。
- 文档：`docs/KERNEL_FTP_CONTRACT.md` 动词表与安全口径、`docs/PLUGIN_CATALOG.md`、
  `plugins/README.md` 的 fail2ban 生命周期；`docs/TEST_MATRIX.md` 新增 `FTP-06`～`FTP-08`。

## 计划任务弹窗与 cron 插件 UI

- `plugins/cron` 新建与编辑统一进同一弹窗：基本信息 / 调度 / 高级三个分组；编辑走 `task.update`，
  不改任务身份（id / kind / source）。
- 高级参数（超时、重试、退避）在插件侧按内核 `skiff-sched` 同一口径提前校验：
  `timeout_secs` 1–600、`retry_max` ≤10、`backoff_secs` 1–3600；只提交显式传入的字段，不覆盖未改项。
- 内置任务（`builtin:` 前缀）只渲染启停，不渲染删除；删除与编辑在插件 RPC 层硬拦截，
  返回「内置任务不可删除（只能停用）」「内置任务只允许启停，不能编辑」，不依赖 UI 隐藏。
- 新增 `ui/base.css` 统一列表与表单样式；列表右上角「新建任务」与 L3 入口都直接开弹窗，不跳页。
