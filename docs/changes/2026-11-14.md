- 存储：复用任务中心 `jobs`，新增 `steps_json TEXT NOT NULL DEFAULT '[]'`（v20，迁移幂等）；`kind=web.install`、目标 `web_env/web`，活跃唯一索引防止并发安装。删除内存 `site_env`/`site_install_progress`，安装/重建只提交作业。
- 步骤模型：6 步，状态对外统一 `pending/running/ok/failed`，每步含 `key/name/detail/started_at/finished_at`；每次推进同步写 `steps_json`、`phase/progress` 与作业日志。失败时同时落 `error_class=web.install.failed` 与带步骤上下文的 `error_detail`。
- 查询：新增 `GET /ui/v1/web/install`（Admin + 会话，`no-store`，只读作业快照）；`/ui/v1/web` 的 install 块、旧 SSR 与任务详情共用同一构建函数；任务详情新增 `steps`，补 `web.install`/`web_env` 标签与重试计划。
- 页面：仅在 running/queued 时 2 秒轮询，递归 `setTimeout`，只更新 `.skiff-web-install` 进度块；终态停止并整页刷新一次；离开 `/sites/web` 清理、`document.hidden` 暂停、网络失败 5 秒退避且保留旧进度。展示发起人、来源 IP、起止时间、耗时、当前步骤与失败原因，并提供任务详情入口。
- 重启：`JobService::new` 对全部遗留 `queued/running` 作业做中断收尾（`failed/interrupted`），`running` 步骤改 `failed` 并补结束时间；历史保留至任务中心清理窗口。
- 测试：store v20 迁移/步骤往返/中断收尾，app 视图映射与重启模拟，web 接口 401/403/`no-store`/与 `/web` 同源/`steps` 字段，boot 轮询与单一事实源静态断言。
