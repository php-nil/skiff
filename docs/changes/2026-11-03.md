### 方案要点（详见 ITERATION.md）

- 编译**不进测试机**：测试机保持干净，专职验"装完能不能用"；L2 交给 CI 的 `test` job
- 不加第二台构建机：CI 已覆盖 unix-only 用例、public 仓库不计费、对测试机零占用
- 两类轮次：首装轮（回滚）与升级轮（不回滚，直接换二进制），默认 3 : 1
- 回滚协同：脚本请求 → 轮询 SSH 与 `/proc/uptime` 判恢复 → 自动接续，人只需点一下

### 发现的缺陷（待上机复现后修，本轮未改码）

1. **P0：按发布包装机，服务起不来。** `install.sh` 原样拷贝 `config.toml.example`，
   其中 `allow_insecure_http` 为注释态（默认 `false`），systemd `ExecStart` 又不带 `--dev`，
   而 `listen` 默认是 loopback → `Config::validate` 直接 bail。
   2026-11-03 用等价配置实跑 `skiff serve` 复现，输出
   `未配置 TLS：loopback 调试请显式加 --dev 或 allow_insecure_http = true（§6.2）`。
   之所以至今未暴露：装机链路**从未在真机执行过**（`DEPLOY_TEST.md` §9.5）。
2. **约束：`dev_http == false` 时 cookie 带 `Secure`**，明文 HTTP 下 curl 与浏览器都不回传，
   因此首登/改密类断言必须走 `--dev`（dev 档）或自签 TLS（prod 档）。验收脚本需支持两档。

两条都写进 `ITERATION.md` §7，作为上机首轮的预期红灯与修复前置。

## 复审：按「内网 VM + 全量回滚 + Docker 需测」重写方案

用户补充：测试机为内网虚拟机、数据可随意删除、允许暴露、凭据可提供；
**初始无 Docker，需脚本安装，且在测试范围内**。据此重审，`docs/ITERATION.md` 整体改写。

### 六处实质变更

1. **Docker 安装升为待测对象。** 验收分组新增 D0（安装链路）、D1（三层策略）、D2（容器操作）。
   读 `docker-bootstrap.sh` 确认：已就绪时 `exit 0` 不重装、`--check-only` 退出码 2 且不改动、
   daemon 起不来时 `exit 3` 且不自动重装——这三条都是可断言的行为。
2. **基线分 T0 / T1。** T0（纯净）用于验安装链路，T1（已装 Docker）用于日常迭代，
   避免每轮为 Docker 安装付 3~5 分钟。检查点打两个，一次性成本。
3. **回滚协议加「强制校时」。** VM 快照回退会把系统时钟拉回过去，
   TOTP 校验与 session 判定都依赖时钟，不校时会让 B 组假红。新增强制 `makestep` + 偏差 < 30 s 断言。
4. **新增 `iter.yml`，不再复用 `release.yml`。** 后者的 concurrency 是 `cancel-in-progress: false`
   （防发半个包），每轮 dispatch 会累积排队并污染发布 run 历史。迭代包单独一条流水线，
   只编 musl x86_64、`--skip-plugins`、可取消。
5. **补前置断言。** root / systemd PID 1 / 时钟 / 端口 / 磁盘 / landlock ABI / cgroups v2，
   不满足即 FAIL 或 SKIP——插件沙箱依赖 landlock ≥ 5.13，内核不够时 E 组只能 SKIP，不能算通过。
6. **凭据口径改「约定 + 理由」。** 内网 VM 被打的风险低，但 public 仓库里的密码会永久留在
   git 历史并随 fork 扩散；仍放 `.workbuddy/server.env`，若坚持入库需显式确认。

### 新识别的最大未知项

`docker-bootstrap.sh` 的安装链路**强依赖外网**：先拉 `https://linuxmirrors.cn/docker.sh`，
再以 `mirrors.tencent.com/docker-ce` 为源安装，任一不通即 `exit 4`。

### 风险与口径

- **明文裸露**：同网段可抓包拿会话；仅限隔离内网/测试机。
- **Cookie/Secure**：`plaintext_behind_proxy` 下 `dev_http=false`，会话与登录页 CSRF Cookie 均带

  `curl` / `/api/v1` Bearer 不受影响。**浏览器登录必须 TLS（自签亦可）或反代终止 TLS**。
- **伪造头**：只有 peer 命中 `trusted_proxies` 才采信 `X-Forwarded-*`。实测外部来源带
  `X-Forwarded-For: 1.2.3.4` → 审计仍记 `10.10.15.1`；本机（受信 `/32`）带 `9.9.9.9` → 记 `9.9.9.9`。
- **换 TLS / 反代**：证书路径走 `[tls]` 配置；反代方案把 `trusted_proxies` 换成真实反代地址，
  并保持 `listen` 只在回环或防火墙白名单内。

## 同端口 TLS（自签）人工复核：`https://10.10.15.4:18080/6gp3m9vq/login`

### 证书

- `/etc/skiff/tls/fullchain.pem`（**0644 root:root**）、`/etc/skiff/tls/privkey.pem`（**0600 root:root**）；
  私钥只放该目录，不在 `/root` 或临时目录。
- subject `CN=10.10.15.4`；SAN `IP:10.10.15.4, IP:127.0.0.1, DNS:skiff.local`；
  有效期 `2026-11-03 → 2036-10-31`（10 年）。
- SHA-256 指纹 `D7:49:D0:06:BC:64:70:3C:E9:D2:AE:D5:D6:62:07:25:B9:97:60:CE:54:0C:57:D8:27:5B:FB:5B:D3:92:67:78`。
- 生成方式（openssl 3.5.7，自签仅限内网复核）：

```sh
openssl req -x509 -newkey rsa:2048 -nodes -days 3650 \
  -keyout /etc/skiff/tls/privkey.pem -out /etc/skiff/tls/fullchain.pem \
  -subj "/CN=10.10.15.4" \
  -addext "subjectAltName=IP:10.10.15.4,IP:127.0.0.1,DNS:skiff.local"
```

### 配置

```toml

tls_key  = "/etc/skiff/tls/privkey.pem"
allow_reduced_sandbox = true
trusted_proxies = ["127.0.0.1/32"]
```

## 官方插件恢复：为什么面板一个都看不到 + nginx 落地

### 根因（逐项排除后的结论）

- **列表读库，不读目录**：`GET /{p}/plugins` 走 `state.db().plugins()`（SQLite `plugins` 表）；导航插件项也由
  这些行生成。表为空 → 页面「还没有安装插件」、导航无插件入口。入口与路由本身存在，**不是代码缺失**。
- **`official/` 只是分发物**：`install.sh` 把发布包的 `official/` 复制到 `/var/lib/skiff/official/` 后只打印提示，
  **不自动安装**；`.wbpkg` 在目录里 ≠ 已安装。
- **信任库为空**：`trusted_keys` 0 行时安装被 TOFU 拒；需先从 `official/public-key.txt` 导入公钥。
- **`allow_reduced_sandbox=false` 会全拒**：5 个官方包 manifest 未显式写 `requires_full_sandbox`
  （默认 true），关闭 reduced sandbox 时安装一律拒绝；本机当前为 `true`。
- **快照就是空插件状态**：`/var/backups/skiff/datadir-initial-state.tgz` 内 `plugins=0`、`trusted_keys=0`、
  无 `official/`；回到该快照不会带回任何插件。
