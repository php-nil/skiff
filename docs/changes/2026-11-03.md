### 方案要点（详见 ITERATION.md）

- 编译**不进测试机**：测试机保持干净，专职验"装完能不能用"；L2 交给 CI 的 `test` job
- 不加第二台构建机：CI 已覆盖 unix-only 用例、public 仓库不计费、对测试机零占用
- 两类轮次：首装轮（回滚）与升级轮（不回滚，直接换二进制），默认 3 : 1
- 回滚协同：脚本请求 → 轮询 SSH 与 `/proc/uptime` 判恢复 → 自动接续，人只需点一下

### 发现的缺陷（待上机复现后修，本轮未改码）

1. **P0：按发布包装机，服务起不来。** `install.sh` 原样拷贝 `config.toml.example`，
   其中 `allow_insecure_http` 为注释态（默认 `false`），systemd `ExecStart` 又不带 `--dev`，
   而 `listen` 默认是 loopback → `Config::validate` 直接 bail。
   2026-11-03 用等价配置实跑 `skiff serve` 复现，输出
   `未配置 TLS：loopback 调试请显式加 --dev 或 allow_insecure_http = true（§6.2）`。
   之所以至今未暴露：装机链路**从未在真机执行过**（`DEPLOY_TEST.md` §9.5）。
2. **约束：`dev_http == false` 时 cookie 带 `Secure`**，明文 HTTP 下 curl 与浏览器都不回传，
   因此首登/改密类断言必须走 `--dev`（dev 档）或自签 TLS（prod 档）。验收脚本需支持两档。

两条都写进 `ITERATION.md` §7，作为上机首轮的预期红灯与修复前置。

## 复审：按「内网 VM + 全量回滚 + Docker 需测」重写方案

用户补充：测试机为内网虚拟机、数据可随意删除、允许暴露、凭据可提供；
**初始无 Docker，需脚本安装，且在测试范围内**。据此重审，`docs/ITERATION.md` 整体改写。

### 六处实质变更

1. **Docker 安装升为待测对象。** 验收分组新增 D0（安装链路）、D1（三层策略）、D2（容器操作）。
   读 `docker-bootstrap.sh` 确认：已就绪时 `exit 0` 不重装、`--check-only` 退出码 2 且不改动、
   daemon 起不来时 `exit 3` 且不自动重装——这三条都是可断言的行为。
2. **基线分 T0 / T1。** T0（纯净）用于验安装链路，T1（已装 Docker）用于日常迭代，
   避免每轮为 Docker 安装付 3~5 分钟。检查点打两个，一次性成本。
3. **回滚协议加「强制校时」。** VM 快照回退会把系统时钟拉回过去，
   TOTP 校验与 session 判定都依赖时钟，不校时会让 B 组假红。新增强制 `makestep` + 偏差 < 30 s 断言。
4. **新增 `iter.yml`，不再复用 `release.yml`。** 后者的 concurrency 是 `cancel-in-progress: false`
   （防发半个包），每轮 dispatch 会累积排队并污染发布 run 历史。迭代包单独一条流水线，
   只编 musl x86_64、`--skip-plugins`、可取消。
5. **补前置断言。** root / systemd PID 1 / 时钟 / 端口 / 磁盘 / landlock ABI / cgroups v2，
   不满足即 FAIL 或 SKIP——插件沙箱依赖 landlock ≥ 5.13，内核不够时 E 组只能 SKIP，不能算通过。
6. **凭据口径改「约定 + 理由」。** 内网 VM 被打的风险低，但 public 仓库里的密码会永久留在
   git 历史并随 fork 扩散；仍放 `.workbuddy/server.env`，若坚持入库需显式确认。

### 新识别的最大未知项

`docker-bootstrap.sh` 的安装链路**强依赖外网**：先拉 `https://linuxmirrors.cn/docker.sh`，
再以 `mirrors.tencent.com/docker-ce` 为源安装，任一不通即 `exit 4`。
内网 VM 若隔离，D 组直接不可执行，需预置 `.deb` / 内网源 / 临时 NAT 三者之一。

### 修掉两个真缺陷（都是「只有真机才暴露」）

1. **P0 装机即 crash loop**（原 §6.1 预判，已复现）：`install.sh` 拷示例配置（`allow_insecure_http` 注释态）+ unit 不带 `--dev` + loopback → `Config::validate` bail，
   `restart counter` 一路涨到 9，而 `install.sh` 仍打印「已启动」并退出 0。
   修法：新增 `ensure_insecure_http`（仅 loopback 且未配 TLS 时追加该行并告警，非 loopback 明文仍拒启）+ 启动后轮询 20 s 验 `active`，不过就打印 journal 并 `exit 1`。
2. **systemd 静默改掉数据根属主**：unit 的 `StateDirectory=skiff` 让 systemd 按 `Group=skiff-plugins` 把 `/var/lib/skiff` chown 成 `root:skiff-plugins`，
   覆盖 `install.sh` 的 `root:root 0711`。已删该行（数据根口径回归单一来源）；`/run/skiff` 仍由 `RuntimeDirectory` 建，属组正好符合 §1.1。

另修正一处**文档口径**（非缺陷）：服务进程创建的文件（`skiff.db`、`initial-admin.txt`）属组是 `skiff-plugins`，闸门是 `0600` 而不是属主，`DEPLOY_TEST.md` §1.1 已按实测改。
