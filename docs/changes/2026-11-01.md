## 官方插件集规划（分析建议稿）

竞品（1Panel、宝塔、Coolify/Dokploy、CasaOS、Portainer、YunoHost）对照后，
Skiff 的完整度上限取决于官方插件集：容器/终端已在三核心内，文件、网站、监控、
防火墙、计划任务/备份、应用模板、数据库管理全部在插件层。新增
`docs/PLUGIN_CATALOG.md`，只做分析与选型，**不改代码、不建目录**。

- **能力现状核对**（选型硬约束，均附代码位置）：`docker.call` 实际只执行读操作
  与 start/stop/restart/kill（exec/create/remove/pull/compose 为 Unsupported）；
  `fs` 只允许插件自身 `data/` 相对路径，无宿主授权目录；`net` 一律 501；
  插件 UI 走 postMessage 且单帧 1MiB、CSP `connect-src 'none'`；信任库只有 TOFU，
  **无内置官方公钥**（与 §4.3 承诺不符）。
- **官方插件清单**：P0 三个（`com.skiff.monitor` 主机监控、
  `com.skiff.nginx` 网站管理、`com.skiff.files` 文件管理）；P1 五个
  （应用模板、防火墙、备份、数据库、计划任务）；P2 四个（日志、容器守护、告警、SSO）。
- **首批 3 个与实现顺序**：monitor（只读 fs，最小）→ nginx（exec 命令模板）→
  files（fs 授权 + 大文件传输 + TOCTOU）。每个都列了 manifest 草案与内核前置，
  避免先写插件再返工。
- **目录方案**：推荐顶层 `plugins/` 作为**第二个 cargo workspace**（与 `crates/`
  平级），根 workspace 加 `exclude`；不推荐 `crates/plugins/*`（破坏内核边界）、
  `deploy/plugins`（只放部署物料）；独立仓库留作中期选项。
- **开箱即用三条线**：内置官方公钥、官方 `.wbpkg` 随发布包放本地只读源、
  面板一键安装但权限确认不跳过；只发 GitHub Release 让用户手传不算开箱即用。

## 发布物去签名（§11 决策 12）

拍板：发布物只验 detached `SHA-256` 摘要，**不做签名**。理由：发布物信任锚是
「装机的人自己核对摘要」，防的是传输损坏而非渠道投毒——真要防投毒需要公钥
分发体系（离线公布指纹、独立信道换钥），对自用/小范围分发成本大于收益；
对照 1Panel（同域 checksums，且官方 quick_start.sh 新装路径实际不比对哈希），
SHA-256 已是同类水位。**插件包 `.wbpkg` 的签名/TOFU 不受影响**（决策 2 不变，
那是插件信任内核，不是发布物链路）。

移除面：

- **`deploy/pack-release.sh`**：删 `--key` 参数与签名段，产物由
  tar.gz + `.sha256` + `.sig` 三件套变两件套；`README.txt` 安装说明同步。
- **`release.yml`**：删 `RELEASE_SIGNING_KEY_HEX` secret 注入与「未配置则
  warning」段，`.sig` 自检行删除。
- **`skiff-plugin` CLI**：删 `sign-file` / `verify-file` 子命令（只为发布物
  detached 签名存在；`keygen`/`pack`/`verify` 插件链路不动）；`skiff-pkgfmt`
  的 `sign_bytes` 一并删（`verify_bytes` 是 `.wbpkg` 验签内核，保留）；
  `skiff-sdk` 去掉 `hex` 依赖（Cargo.lock 只少一行）。
- **`ci.yml` pkg-chain 首步**：「发布物签名/验签」改「keygen 冒烟」——保留
  keygen 落盘/0600/公钥 64 位 hex 输出的断言与「`--help` 不落盘」回归
  （曾出过 `keygen --help` 真写私钥），只摘掉 sign-file/verify-file 段。
- **口径同步**：`install.sh` 头注、`05-deploy.md` §5.1 交付物、`CI.md` §4
  发布物表、`DEPLOY_TEST.md`（§0 取包/§0.3 文件表/§2.1 安装顺序/§9.3/A2
  用例改「缺 .sha256 不得安装」）、`12-pending-tests.md` M5 验签项作废。

`docs/sections/11-decisions.md` 新增决策 12 记录本拍板。

## 官方插件集落地：guard（零内核改动）+ monitor → nginx → files + 发布包携带

规划稿（上一节）的「首批 3 个」按实际能力面落地成 4 个，并补上「安装包必须带
插件」这条交付链。代码在 `plugins/`（**第二个 workspace**，根 `Cargo.toml` 已
`exclude = ["plugins"]`，`plugins/Cargo.lock` 入库），内核侧只补 `fs` 能力面，
**没有为 guard 加任何新接口**。

### 内核侧（唯一改动面：`fs`，guard 用不到）

- `crates/core/src/capability.rs`：`fs.read/write/list/mkdir/remove/rename` 六个
  handler，挂到 `kernel.sock` 路由表（unix-only）。权限串之外**必须**有安装时
  确认的 `path:<绝对路径>` 授权根，否则 403——宿主路径与插件自身 `data/` 是两把
  钥匙，后者不需要授权根。
- `crates/core/src/fsops.rs`：路径判定（`resolve`：`..`/符号链接/绝对路径越界一律
  拒）、`MAX_IO = 256KiB` 单次读写上限（分页由调用方按 `offset` 走）、
  `read_chunk`/`write_chunk`（追加式写入带 `eof`）、`list` 返回 type/size/mode/mtime、
  `own_by_plugin` 把新建文件属主还给插件 UID。
- `crates/plugin/src/fsgrant.rs`：安装确认页/`--resource path:<根>` 的授权根解析与
  匹配（`is_scope_root` 只认根本身或其子路径）。
- `crates/plugin/src/cron.rs`：5 段 cron 匹配 + 每 30s 巡检按 `{id}|{expr}` 记住
  「已触发的分钟序号」，`* * * * *` 不会一分钟触发两次。
- `crates/wire`、`crates/web`（插件详情页 `plugin_detail.html`、确认页、列表页、
  授权根展示）：插件 UI 走 postMessage 桥，不自持凭据。

### 官方插件（`plugins/`）

| 插件 | 能力 | 关键取舍 |
|---|---|---|
| `guard` `com.skiff.guard` | `docker`(list/inspect/restart) + `fs`（自身 data/）+ `identity` | **零内核改动**：纯既有能力组合；`dead`/`restarting`/`unhealthy`（可选 `exited`）按冷却 + 每小时预算重启；逐对象授权 `container:NAME\|ID` / `project:P`，未授权容器只展示；带 `dry_run` 演练模式 |
| `monitor` `com.skiff.monitor` | `fs`（`path:/proc`） | 只读采样 CPU/内存/负载/网卡/运行时长；`store` 时才落环形缓冲，避免每分钟写盘 |
| `nginx` `com.skiff.nginx` | `fs`（站点目录）+ `docker`(list/restart) | **不用 `containers.exec`**（exec 属 M3 门禁）：写授权目录 + 重启容器；目标容器仍须显式 `container:<名>` grant；一期不做 `nginx -t` |
| `files` `com.skiff.files` | `fs` + `identity` | 授权根内浏览/新建/删除/改名/编辑；256KiB 分页；根外一律 403 |

- 四个 manifest 的 `requires` 都只引用既有能力；`key_id` 源码里是 64 个 `0` 占位，
  打包时 `stamp` 在**临时目录**回填（仓库不含任何密钥指纹）。
- `resource_hints` 只做预填建议：`monitor` 建议 `path:/proc`，`nginx` 建议站点目录 +
  `container:nginx`，`guard`/`files` 留空（让管理员自己选对象）。

### 发布物携带（「打包后需带这些插件」）

- **`plugins/pack.sh`**：`build` → 临时目录 `stamp --key` → `pack --arch` →
  `verify --arch` → `official/*.wbpkg` + **`official/public-key.txt`**；日志末尾打印
  `官方插件签名公钥(hex): …`，装机侧照抄进面板「设置 → 信任公钥」（TOFU 首次信任）。
- **`deploy/pack-release.sh --plugin-key <私钥> [--skip-plugins]`**：给出私钥才出包，
  缺私钥且未 `--skip-plugins` 直接拒绝；打插件前 `rm -rf plugins/official`（否则
  amd64/arm64 两台机器连打会把上一轮**别架构的包**静默塞进发布包）；`official/` 含
  4 个 `.wbpkg` + `public-key.txt`，`README.txt` 写清导入公钥与逐条 `--resource`。
  顺带修 `[ -f x ] && cmd` 在 `set -e` 下的提前退出。
- **`deploy/install.sh`**：把 `official/` 复制到 `/var/lib/skiff/official`（0755
  root:root，只有安装器能写），**不自动安装**——权限与对象授权必须逐条确认；
  结尾提示导入公钥。

### CI / Release

- **`ci.yml` 新增 `plugins` job**：`fmt --check` / `clippy -D warnings` / `test`，
  全部走 `--manifest-path plugins/Cargo.toml`（根 `--workspace` 对第二 workspace 无效）。
- **`ci.yml` `pkg-chain` 新增「官方插件真打包」**：临时密钥 → `pack.sh` → 断言
  恰好 4 个包 → 逐个 `verify`。发布包 `official/` 就是这条脚本的产物，坏了不能等到

### 1. 文件管理接入 highlight.js（不自写 tokenizer）

- 依赖选择：**highlight.js 11.9.0（BSD-3-Clause）** 的 cdn-assets，vendored 进包内
  `plugins/files/ui/vendor/`：`highlight.min.js`（common bundle，35 种语言）、
  `theme-dark.min.css`（github-dark）、5 个额外语言脚本（`nginx` / `dockerfile` /

- 为什么必须 vendor：插件 UI 的 CSP 是 `script-src 'self'; connect-src 'none'`，
  引 CDN 与内联脚本都会被拒；同源文件放 `ui/` 才加载得到。
- `.toml` 映射到 `ini`：cdn-assets 11.9/11.10/11.11 都**没有** TOML 语法
  （`languages/toml.min.js` 404），与其自写 tokenizer（用户明确否掉）不如标注近似。
- 编辑器实现：`<pre><code>` 着色层 + 透明 `textarea` 收键盘（字体/行高/padding 逐字一致、

  `hljs.listLanguages()` 动态生成，默认按扩展名识别（可手动指定）。超过 100KB 且无语言时
  **不做** `highlightAuto`（回溯代价高），退化为转义纯文本；着色异常同样回退纯文本。
- 路径：`plugins/files/ui/{index.html,app.js}` + 新增 `ui/vendor/`。

### 2. iframe 沙箱补齐（此前只有 CSP 与 postMessage 桥）

- `plugin_detail.html` 的 iframe 加 `sandbox="allow-scripts allow-modals"`（不给
  `allow-same-origin`）→ opacity origin，插件脚本拿不到面板会话/DOM；`allow-modals`

### 3. 顶栏插件菜单（`[[ui]].label` 进导航）

  当菜单名，当前插件高亮（`active = "plugin:<id>"`）。`skiff.css` 加 `.nav-plugin`

### 4. 跨插件跳转（`skiff.open`）

- 新增面板级消息 `{type:"skiff.open", nonce, id, plugin, path}`：**不转发**给插件进程，
  由父页面 `skiff.js::openFromPlugin` 校验后 `location.assign`。校验四道：插件 id 正则
  （`^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`）、`data-plugins` 白名单（详情页下发，同一份
  顶栏清单）、`path` 长度 ≤512 且无控制字符、服务端 `?open=` 再清洗一遍
  （`handlers::plugins::sanitize_open`：去控制字符 + 按字符截 512）并 `encode_uri_component`
  后拼进 iframe `src`。失败回 `skiff.open.result {ok:false, error}`。
- **安全口径**：跳转只改地址，不授予任何能力；定位路径能不能读，仍由目标插件自己的
  `path:` 授权根（内核 fs 面）判定——例：NGINX 的 `/etc/nginx/conf.d` 若不在 `files`
  的授权根内，`files` 会明确提示「无法定位（未授权该路径）」而不是静默 403。
- 插件侧：`files/ui/app.js` 读 `?open=`（先按目录 `list`、失败再按文件 `read`）；
  `nginx/ui/app.js` 加「在文件管理里打开该目录」按钮，把当前站点目录交给 `files`。
- 回归：`sanitize_open_*` 单测（控制字符、按字符截断、边界）+ 上面的 main_flow 用例
  （`?open=` 百分号编码透传、控制字符被清、白名单只含启用插件、顶栏高亮）。

## 计划任务插件 + 插件间接口调用（interop）：把「跳转」和「调用」分成两件事

三点需求：① 增加计划任务插件；② 插件之间不只要能按地址跳转，还要**暴露接口**
供其他插件调用（例：网站管理点「新增备份任务」就把一条计划任务写进去）；③ 设计
插件间交互逻辑、提升体验。落地口径是「跳转只改地址、调用才过权限」，两者不混。

### 内核侧：新增第五个能力面 `interop`

- **`crates/pkgfmt/src/manifest.rs`**：新增 `Capability::Interop` 与
  `[interop]`（`provides` = 对外方法，`consumes` = 允许调用的 `<插件 id>:<方法>`
  或 `*`），以及三条联动校验：声明 `[interop]` 必须在 `requires` 里、
  声明 `consumes` 必须同时申请 `interop:call`、`provides.method` 必须过动词校验。
  `resource_hints` 接受 `plugin:<id>` / `plugin:*`（禁 `plugin:com.*` 这类部分通配）；
  `interop_resource_hints()` 把 `consumes` 翻译成安装确认页的默认勾选项。
- **`crates/wire`**：`capability/interop/call`、`capability/interop/catalog`
  两条路由常量（`route_table_is_stable` 同步断言）。
- **`crates/core/src/interop.rs`（新）**：四道闸的纯判定——调用方 `interop:call`、
  调用方 `plugin:<目标>`（或 `plugin:*`）对象授权、调用方 `consumes` 白名单、目标
  `provides` 声明；外加 `catalog()`（只列**真调得通**的接口）。无 DB/Docker 依赖，
  跟 `policy` 一样可裸测。
- **`crates/core/src/kernel.rs`**：两个 handler 接线。`call` 的错误口径
  404 目标未装 / 409 目标未启用或正忙 / 400 参数非法 / 403 四道闸任一不过 /
  502 目标 RPC 失败 / 504 15s 超时；转发前注入 `params._interop.caller`
  （**覆盖**调用方自带同名键，来源不可伪造）；`AppState.interop_busy` 做单层防环
  （A→B→A 在第二层被挡），超时/失败路径都保证释放占用；成功与失败均逐次审计
  `interop.call`，目录调用审计 `interop.catalog`。
- **`crates/sdk`**：`Plugin::interop_call(target, method, params)` /
  `interop_catalog()`；`kernel_contract` 的假内核补两条路由并断言路径顺序。

### 新共享 crate `skiff-cron`（`crates/cron`）

- 原先 `crates/plugin/src/cron.rs` 的解析/匹配抽成独立 crate（只依赖 `chrono`，
  禁 `store`/`docker`/`web`），`plugin` 侧改为 `pub use skiff_cron::*`，调用点与
  测试不动。三处共用同一份实现：内核 `tick` 调度、装包校验（`pkgfmt`）、
  计划任务插件。根 workspace 成员与依赖表（§8）同步为 14 个 crate。

### 计划任务插件 `plugins/cron`（`com.skiff.cron`）

- **不执行宿主 shell**：任务 = `表达式 + 目标插件 + 方法 + 参数`，`tick` 里只发
  interop 调用。能力面只要 `identity` + `interop`，因此不需要新增任何命令执行面。
- manifest：`requires = ["identity","interop"]`、`cron = ["* * * * *"]`
  （内核按分钟去重）、`provides = jobs.create/jobs.list/jobs.remove/jobs.run`、
  `consumes = ["*"]`、`resource_hints = []`（「能调谁」由安装时勾
  `plugin:<目标>` 决定）。
- **幂等与归属**：`jobs.create` 按 `(source, key)` upsert；`source` 取内核注入的
  `_interop.caller`，插件来源不能改/删手动创建的任务。参数上限 4KiB、任务上限
  200 条、每轮最多执行 `tick_batch` 条；已执行过本分钟的任务再 `tick` 会跳过。
- UI：任务表（下次触发 / 目标与方法 / 来源（可跳转）/ 上次结果 / 立即执行 /
  启停 / 删除），目标下拉直接读 `interop_catalog`；`?open=job:<id>` 高亮并
  `scrollIntoView`。

### NGINX 站点：一键「新增备份任务」

- manifest：`requires` 加 `interop`、`provides backup`、
  `consumes = ["com.skiff.cron:jobs.create"]`、`resource_hints` 加
  `plugin:com.skiff.cron`；新增 `backup_expr`（默认 `0 3 * * *`）。
  **移除本插件自己的 `cron` 表达式**——否则计划任务与自带定时每天各备份一次，
  会出双份快照。
- RPC `scheduleBackup`：`interop_call("com.skiff.cron","jobs.create", { expr,
  target: 自己, method: "backup", key: "nightly" })`，返回
  `{created, job_id, next_run, expr}`；403/404/409 分别给出「勾
  `plugin:com.skiff.cron`」「先装计划任务」「目标停用或正忙」的人话提示。
- UI：`新增备份任务`（表达式用 `prompt` 输入，默认值来自 `backup_expr`）→ 成功后
  启用 `查看计划任务` → `skiff.open("com.skiff.cron", "job:<id>")`，跳过去即高亮
  刚写的那条。重复点击只更新表达式/启停，不堆任务。

### Web：安装确认页与详情页

### 回归与本轮修掉的缺陷

- **新增 `crates/pkgfmt/tests/official_manifests.rs`**：用 `skiff-pkgfmt` 的同一份
  解析器遍历 `plugins/*/manifest.toml`，断言「目录名 = id 末段」「至少 5 个」
  「`com.skiff.cron` 在列」。`plugins/` 是第二 workspace，根三关原本不编译它，
  这条把 manifest 契约漂移前移到根 `cargo test`。
- **`interop.consumes = ["*"]` 原先解析失败**：`validate_interop` 在
  `split_once(':')` 之前没有放行单独成项的 `*`，导致计划任务这种「全量白名单」
  在装包时直接被判非法。已放行并补断言。
- **`resource_hints` 的 `path:` 绝对路径判定带平台差异**：`Path::is_absolute()`
  在 Windows 上不认 `/proc`，`monitor` 的官方 manifest 会在 Windows 的根
  `cargo test` 里被误判（Linux CI 反而看不出）。改为「`/` 开头或平台绝对路径」，
  与 `crates/core/src/fsops.rs` 同一口径，并加 `path:/proc` 断言。
- `interop` 单测：四道闸逐条拒绝理由、自调拒绝、`plugin:*`、`catalog` 只列可调通项；
  修正两处测试自身的用例错位（用错调用方 id / 用单方法白名单去验 provides 闸）。

## 架构审查第五轮：P0/P1/P2 全部落地（模块划分 / 职责边界 / 依赖关系 / 复用性）

本轮按 `docs/ARCH_REVIEW.md` 第五轮审查清单逐项落地，**P0-1/P0-2/P0-3 与
P1-1～P1-4、P2 五项全部完成**。主线是三件事：把**判定规则**收到唯一一份、
把**能力面实现**搬回它的归属 crate、把**值类型**下沉到零 I/O 的 `model`。
不改产品功能面，不改对外接口语义（唯一的行为变更见「登录流程收口」，已标注）。

### P0-1 角色→权限矩阵统一到 `skiff_model::Permission`

三处各写各的角色判定合并成一张表：

- `crates/model/src/rbac.rs` 新增 `Permission`（9 条：`DockerRead` / `DockerOperate` /
  `DockerLifecycle` / `DockerExec` / `AuditRead` / `PluginManage` / `HostPathGrant` /
  `Admin`）与 `RoleExt::can()`，**全仓唯一**的角色→权限矩阵。
- `crates/model/src/verb.rs` 的 `Verb::permission()` 由 `all()` 派生，26 个动词到权限
  的映射不再手写；`verb_permission_matches_role_matrix` 单测把「viewer 只读、
  operator 可启停、exec 与生命周期 admin 专属」这条口径钉死。
- 删除 `crates/policy` 内的联 `Action` 三分法与 `crates/web` 的 `require_admin`
  手写判定，判定入口改为 `Role::can(Permission)`。

### P0-2 + P0-3 能力面实现从 `core` 迁入 `crates/plugin`

插件能力面（`fs` 读写、`identity`、`config`、`docker` 回调、`interop` 插件间调用）
此前寄居在 `crates/core/src/`，导致 `core` 变成「什么都干一点」的大杂烩，且能力面
逻辑在 Windows 开发机上根本编不到（unix-only 的 socket 挂载点把整块逻辑圈住）。

- 拆为 `crates/plugin/src/{fsops,fsgrant,capability,interop}.rs`，能力面回到它的
  归属地（`crates/plugin`）。
- **`fsops`/`fsgrant`/`interop` 与平台无关**（只有 `core/src/kernel/server.rs` 的
  socket 监听是 unix-only），因此这批代码在 Windows 本地可编译、可单测。
- **依赖倒置**：`skiff-plugin` 不能依赖 `skiff-app`（后者依赖前者，会成环），
  宿主上下文改由 `plugin::CapabilityHost` 这个 trait 注入（`data_dir` /
  `plugin_grants` / `audit` 三件事），`skiff_app::AppState` 实现它。

### P0-2 + P1-4 路径授权原语统一到 `skiff_model::path`

仓库里原有三处各写各的路径前缀匹配（`policy::PathGuard`、`plugin::fsgrant`、
插件侧 `skiff-plugin-common` 的前置快筛），最容易出的事故是**字符串前缀相同但不是
目录包含**：`/etc/nginx/conf.d-evil` 落在 `/etc/nginx/conf.d` 的字符串前缀下，
却不在该目录内。

- 新增 `crates/model/src/path.rs`：纯代数、**零 I/O** 的路径原语 11 个
  （`within` / `within_any` / `normalize_dir` / `has_parent_segment` / `is_absolute` /
  `is_posix_absolute` / `within_root` / `is_root_path` / `any_root_contains` /
  `hits_a_root_itself` / `parent_within`）。
- 口径分工写进模块注释：字符串级（`within`）用于插件侧**快筛**（fail fast），
  canonical 级（`within_root`）用于内核**授权判定**（`canonicalize` 后按组件比），
  符号链接逃逸由 `fsgrant` / `PathGuard` 在解析阶段挡住。

### P1-1 值类型下沉 `skiff-model`，`policy` 只留判定

`crates/model/src/container.rs` 新增 `ContainerSpec` / `PortMapping` / `Healthcheck` /
`Mount` / `ObjectRef` / `Actor`，`crates/model/src/verb.rs` 承接 `Verb` / `Tier` /
`LABEL_*`，并加 `short_id()`（`SHORT_ID_LEN = 12`，短 id 展示口径收敛到一处）。

`compose` 为了拿 `ContainerSpec` 而依赖 `policy`，会把 `libc` 拖进一个「纯 serde_yaml
演算」的解析器——因此这类值类型一律走 `model`，`compose` 只依赖 `model`。

### P1-2 `AppState` 收口 + 登录用例统一

- `AppState` 的 `db` / `docker` / `supervisor` 三个根服务句柄**私有化**，改走访问器
  `db()` / `docker()` / `supervisor()`，外部只能拿到引用。
- 新增 `crates/app/src/auth.rs`：UI 表单登录与 JSON API 登录此前各实现一遍几乎相同
  的流程（限流 → 并发闸 → 查用户 → 验口令 → 验 TOTP → 备份码 → 建会话 → 写审计），
  两份实现此后各自漂移。现在判定只此一份（`AppState::login`），调用方只负责
  「怎么把结果渲染出去」，配 5 条 tokio 单测（建会话可用、口令错被拒且留审计、
  重复失败触发限流、TOTP 必填、备份码一次性）。
- **行为变更（唯一一处）**：API 侧限流现在也写审计；错误文案与 UI 侧对齐
  （启用 TOTP 时「用户名、口令或动态码不正确」，否则「用户名或口令不正确」）。

### P1-3 / P1-4 依赖与测试卫生

- `tempfile` 从 `skiff-pkgfmt` 的 `[dependencies]` 移入 `[dev-dependencies]`：
  它只在测试里用，却让每个依赖 pkgfmt 的目标都拖着它。
- 插件侧路径快筛改用 `skiff_model::path`，与内核判定同源。

### P2 五项

- **core 拆分**：`crates/core/src/kernel.rs`（992 行）拆为
  `crates/core/src/kernel/{mod,routes,auth,capability,interop,server}.rs`；
  `routes` / `auth` / `capability` / `interop` 跨平台，`server`（socket 监听）unix-only。
- **中间件顺序修正（真实缺陷）**：axum 0.8 的 `Router::layer` 是**后加的先跑**
  （后加 = 更外层）。原代码 `.layer(protocol_guard).layer(plugin_auth)` 的注释声称
  「协议版本先于鉴权判定」，实际执行顺序相反——协议版本闸排在鉴权之后。
  现改为先挂 `plugin_auth`、最后挂 `protocol_guard`，保证版本闸真正先于鉴权执行。
  顺序用一次性探针实测确认（`ORDER = ["b", "a"]`）。
- **短 id 收敛**：`SHORT_ID_LEN = 12` 与 `short_id()` 收到 `model`，展示层不再各截各的。
- **容器匹配下沉**：`match_container` 从 `crates/web` 移到 `crates/docker::resolve`
  （完整 id / 名称 / id 前缀 → 具体容器，精确优先、前缀歧义即拒），CLI 与 SDK 侧
  不必再反向依赖表现层。
- **wire 协议版本字段**：`PROTOCOL_VERSION = 1` / `PROTOCOL_HEADER =
  "x-skiff-protocol"` / `check_protocol()` 落在 `skiff-wire`，内核与 SDK 共用一份；
  版本不符返回 426 `UPGRADE_REQUIRED`。
- **`plugin/src/cron.rs` 转发层删除**：cron 表达式实现已独立为 `crates/cron`
  （内核调度、装包校验、计划任务插件共用），插件 crate 不再保留转发层。

### 顺带收口

- **安装选项组装去重**：能力集 / 架构 / 降级开关过去在 CLI 与 Web 各写一遍（漂移
  风险），抽成 `skiff_plugin::install_options`，两侧共用同一份组装逻辑。
- **CLI 安装审计补齐**：CLI 侧装包此前不留审计，与 Web 侧口径不一；现补
  `plugin.install` 审计（actor=`cli`、channel=`local`，成功 `ok` / 失败 `fail`）。
