## 测试补强：把 10-31 CI 修出来的坑从「推 CI 才发现」前移到「cargo test 就红」

10-31 四轮修 CI 暴露的问题分四类：cfg(unix) 编译错、平台假设（uid==0）、
kernel::spawn 阻塞真 bug、冒烟脚本期望与 §6.3 相悖。前两类靠 Linux CI 把关
（无法再前移到 Windows 本地），后两类可以前移。本批共补 **10 条回归 + 1 个
Windows CI job**，并顺带修一处报错口径。

### P0（对应 10-31 四类坑的发现时点前移）

- **kernel+HTTP 并存**（`crates/core/src/kernel.rs` 测试）：
  - `spawn_does_not_block_and_http_serves_alongside`：`kernel::spawn` 必须立即返回
    （独立线程 + 2s 超时，阻塞即红而不是挂死测试），且 `/healthz` 与 `kernel.sock`
    同时可用。历史缺陷（常驻 accept 循环被 `.await`，HTTP 永远排不到）从冒烟
    前移到 `cargo test`。
  - `kernel_bind_failure_degrades_but_http_stays_up`：`kernel.sock` 路径被占（目录）
    时不得 panic，HTTP 照常服务。
- **裸 `/` 404 契约**（`crates/web/tests/main_flow.rs`）：
  `bare_root_is_hidden_404_and_prefix_redirects_to_login`——§6.3 契约固化进
  in-process 测试，与冒烟脚本互为对拍（脚本曾把期望写反）。
- **权限位口径回归**（`crates/core/src/bootstrap.rs`，unix-only）：
  `bootstrap_permission_bits_match_red_line`——data=0711、plugins=0711、
  backup=0700、skiff.db/initial-admin.txt=0600。红线「勿改回 0700」此前零测试守着。
- **Windows CI job**（`ci.yml` 新增 `test-win`）：同一套单测在 windows-latest 跑。
  `cfg(not(unix))` stub 路径此前 CI 从不编译；「Windows 本地三关」交付口径也
  一直没人复核。CI.md 门槛表同步。

### P1（同类盲区，未踩坑但风险同源）

- **并发票据复用**（main_flow）：`exec_ticket_concurrent_reuse_wins_exactly_once`——
  并发双出示同一 ticket 恰好核销一次（顺序版在 app 层已有，这条守临界区拆分回归）。
- **故障注入**（`crates/core/src/server.rs` 测试 + 上面 kernel 降级测试）：
  `occupied_port_reports_address_in_use`——端口被占必须立即返回明确 Err。
  顺带修报错口径：`serve_error()` 区分 AddrInUse（「地址已被占用」）与其他
  IO 错误，不再笼统一句「服务异常退出」。
- **插件迁移恢复**（`crates/plugin/src/install.rs` 测试）：升级保 data/、
  版本目录 N-1 窗口（0.1.0→0.2.0→0.3.0 后只剩 0.2.0+0.3.0）、同版/降级拒绝、
  卸载默认保 data 且 `delete_data` 才清干净。此前 install.rs 只有 2 条纯逻辑测试。
- **受限形态断言**（main_flow）：`restricted_form_rejects_plugins_beyond_capability_surface`
  ——DockerRestricted 形态下需要 fs 能力的插件在确认安装时被拒（不落库、留审计），
  docker 能力对照组可装。
  - **范围如实说明**：「bind 类 API 被拒」的 web 层断言暂无落点——建容器端点
    尚未实现（main_flow 头部已标注），bind 拒绝在 policy 层已有覆盖

    web 安装路径）；建容器端点落地时应把 bind 断言上移。

### CI 首跑（run 41263332697）追加修复

新 job 首跑即抓到两处（都是「本地照不到」类）：

- **`bootstrap_permission_bits_match_red_line` 编译错**：`.mode()` 来自
  `std::os::unix::fs::MetadataExt` 而不是 `PermissionsExt`——又是 cfg(unix)
  Windows 编不到的盲区，修法是两个 trait 都导入。
- **存量 `paths::tests::existing_path_inside_root_ok` 在 Windows runner 挂**：
  runner 临时目录带 8.3 短名/大小写差异，`Path::starts_with` 比的是未规范化
  的拼接路径；期望值改为与实际值同口径（canonicalize + normalize_display）。
  这正是 `test-win` 的价值：该测试在开发机 Windows 上全绿、在 runner 上红。
