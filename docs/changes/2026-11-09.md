## 修复：testkit 缓冲探针任务未声明缓冲，`buffer.stat` 恒返回「任务不存在」

- 现象：测试机按 TASK-06 调 testkit `buffer_probe {"id":"plugin:com.skiff.testkit:busy-probe"}`，
  内核 HTTP 400「任务不存在」；任务页却能看到同一 id 的 `busy-probe`。
- 根因：`crates/app/src/tasks.rs::task_spec_from_manifest` 只在 manifest 声明 `sample_method`
  时才给 `TaskSpec` 挂 `BufferConfig`；`buffer.stat` / `buffer.push` 依赖运行时缓冲，
  `busy-probe` 只有调度声明，没有缓冲，因此 `Scheduler::buffer_stat` 返回 `None`。
- 修复：`plugins/testkit/manifest.toml` 给 `busy-probe` 补
  `sample_method = "buffer_sample"` / `sample_interval_secs = 3600` / `capacity_bytes = 4096`；
  `plugins/testkit/src/main.rs` 补 `buffer_sample` 方法（返回最小点）。任务默认停用，
  内核不会自动采样，手工 `buffer_push` 的计数即真值；4 KiB 容量便于构造丢弃与高水位。
- 同步：`crates/web/tests/main_flow.rs` 的 manifest 断言要求该任务同时声明缓冲；
  `docs/TEST_MATRIX.md` TASK-06、`docs/PLUGIN_CATALOG.md`、`docs/TEST_LEDGER.md` 同步口径。

## 修复：升级不补授新声明权限（缺陷二）

- 现象：插件升级后新增能力动词（如 testkit 新增 `scheduler:manage`），库内 grants 仍是旧的，
  必须 `remove` + `install --yes` 才能拿到。
- 根因：`crates/plugin/src/install.rs` 升级分支只对既有 grants 做 manifest 过滤，不补新声明项。
- 修复：升级时对「新 manifest 相对已装 manifest 新增声明的 perm」补授（仍受 manifest 声明集约束）；
  既有 grants 先按新声明过滤，不做清空。刻意不按「declared - existing」补，避免把用户当初拒绝过的
  权限在升级时自动授予；旧 manifest 不可解析时保守不补并 `warn`。新增只读动词仅 `info`；
  命中敏感动词（`is_sensitive_perm`：write/delete/exec/manage/install/reload 等）时 `warn` 并审计
  `plugin.grant_upgrade`，detail `升级新增授权: {全部新增动词}；版本 {from} → {to}（敏感: {敏感动词}）`。
- 回归：`upgrade_grants_newly_declared_permissions_and_audits_sensitive`、
  `upgrade_grants_read_only_declaration_without_sensitive_audit`、
  `upgrade_drops_grants_no_longer_declared`、`sensitive_perm_classification`；
  `reinstall_same_version_preserves_existing_grants` 保持通过（同版本内容重装路径未破坏）。
