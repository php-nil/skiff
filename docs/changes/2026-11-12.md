# 2026-11-12

## R2b：提交记录抽象出 `kind`，旧记录与插件全链路零变化

R2 的第二步：先把「提交的是什么条目」从插件硬编码里抽出来，为 R2c 的模板（app）
与 R2d 的运行环境（runtime）铺路，同时保证既有插件链路一个字节都不变。

### 改动（`tools/skiff-server/src/api/store.rs`）

- 新增 `EntryKind`（`plugin` 缺省 / `app` / `runtime`），附 `as_str` 与 `is_plugin`。
- `Submission` 新增 `kind: EntryKind`：
  - `#[serde(default)]`：旧 `state/submissions/*.json` 缺该字段时解析为 `plugin`，无需迁移；
  - `skip_serializing_if = "EntryKind::is_plugin"`：插件记录写盘与 API 响应里**不出现** `kind`，
    源条目、索引与签名产物因此字节不变。
- `create` 构造记录时显式写 `kind: EntryKind::Plugin`；本步不新增接口，也不改任何校验与状态机。
- 命名区分：`Submission.kind` 是条目类型；`TakedownInfo.kind` 仍是撤包动作（yank / revoke）。

### 测试

- 新增 `tests/api.rs::plugin_records_omit_kind_and_legacy_records_still_load`：
  插件提交响应与落盘记录都没有 `kind`；无 `kind` 的旧记录反序列化为 `plugin`；
  approve → release 后源条目与 `index.json` 都不出现 `kind`。
- `cargo test -p skiff-server`：32 单测 + 23 API + 4 CLI + 15 P0 + 7 serve + 6 sync，共 87 项全绿；
  `cargo clippy -p skiff-server --all-targets -- -D warnings` 通过。
