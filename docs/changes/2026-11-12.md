## R2b：提交记录抽象出 `kind`，旧记录与插件全链路零变化

R2 的第二步：先把「提交的是什么条目」从插件硬编码里抽出来，为 R2c 的模板（app）
与 R2d 的运行环境（runtime）铺路，同时保证既有插件链路一个字节都不变。

### 改动（`tools/skiff-server/src/api/store.rs`）

- 新增 `EntryKind`（`plugin` 缺省 / `app` / `runtime`），附 `as_str` 与 `is_plugin`。
- `Submission` 新增 `kind: EntryKind`：
  - `#[serde(default)]`：旧 `state/submissions/*.json` 缺该字段时解析为 `plugin`，无需迁移；
  - `skip_serializing_if = "EntryKind::is_plugin"`：插件记录写盘与 API 响应里**不出现** `kind`，
    源条目、索引与签名产物因此字节不变。
- `create` 构造记录时显式写 `kind: EntryKind::Plugin`；本步不新增接口，也不改任何校验与状态机。
- 命名区分：`Submission.kind` 是条目类型；`TakedownInfo.kind` 仍是撤包动作（yank / revoke）。

## 托管形态定案：内网 HTTP 先行，对象存储/CDN 后置

只改文档与配置默认值，分两次提交（文档先行，代码另开）。

### 定案口径

- **默认源**：`[catalog].mirrors` 默认 `["http://10.66.52.7:8080"]`，一期只 HTTP，不做留空引导；
  端口实测不通时只改这一处默认值。
- **域名与证书后置**：安全性由 Ed25519 签名 + 索引摘要 + 单调 `seq` 保证（不可伪造、不可回滚），
  传输不加密只影响保密性；HTTPS + `ca_bundle` 保留为可选增强。
- **缓存面板自管**：JSON 类（manifest/index）TTL 一天，`blobs/sha256/*` 永久，拉取失败 5 分钟后
  可重试；「刷新目录」强制绕过 TTL、失败冷却与镜像退避。
- **自定义源**：允许 `http`/`https`（域名/IP/端口/路径前缀）；多源只按优先级回落、不合并；
  切源保留本地快照，离线可读。
- **默认源不可达的降级**：面板照常启动、展示本地快照并提示「镜像源不可达，正在使用本地缓存」；
  失败 5 分钟冷却内页面加载不重复请求；无缓存时提示「尚未连上任何镜像源」并引导到设置页填地址。
- **显式配置优先**：环境变量 > 配置文件 > 默认值；测试机已有的 `mirrors` 原样保留，默认值只补空白实例。

### 文档

- `docs/SKIFF_SERVER.md`：§0 托管行改为已定案；§3.5/§4.2/§16.3 把 ETag / `If-None-Match` /
  304 / Range 标注为服务端可选优化、客户端不作依赖（`serve` 实现保留）；§4.4 补多源优先级回落、
  不合并、切源保留快照；§4.5/§9 第 8 项/§15.2 改为允许 http/https；§11.1 默认镜像与协议；

## 商店抓取超时与页面 504 修复

### 问题

镜像被网络静默丢包（TCP 建连无响应、不回 RST）时，ureq 默认建连超时是 30 秒，正好吃满
框架页面预算，商店页返回 504；快速失败（RST/503）则能正常降级。

### 修复

- 建连超时独立收紧为 **3 秒**（`fetch::CONNECT_TIMEOUT`），不随页面预算漂移。
- 单次请求总超时沿用 `[catalog].timeout_secs`（默认 10 秒）；一次刷新的所有镜像共享
  **10 秒总预算**（`FETCH_BUDGET`），预算耗尽即停止回退，不再每个源各等一个超时。
- 超时/丢包与连接被拒走同一条失败路径：有缓存展示「镜像源不可达，正在使用本地缓存」，
  无缓存展示「尚未连上任何镜像源 + 去设置填写」；页面始终 200，超时同样进入 5 分钟冷却。
- 测试：catalog 侧模拟无响应传输层（预算内失败 + 冷却 + 多镜像共享预算）；web 侧用
  「accept 后不回包」的本地监听断言商店页 200、降级提示与冷却内不再建连。
