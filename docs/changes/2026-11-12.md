# 2026-11-12

## R2b：提交记录抽象出 `kind`，旧记录与插件全链路零变化

R2 的第二步：先把「提交的是什么条目」从插件硬编码里抽出来，为 R2c 的模板（app）
与 R2d 的运行环境（runtime）铺路，同时保证既有插件链路一个字节都不变。

### 改动（`tools/skiff-server/src/api/store.rs`）

- 新增 `EntryKind`（`plugin` 缺省 / `app` / `runtime`），附 `as_str` 与 `is_plugin`。
- `Submission` 新增 `kind: EntryKind`：
  - `#[serde(default)]`：旧 `state/submissions/*.json` 缺该字段时解析为 `plugin`，无需迁移；
  - `skip_serializing_if = "EntryKind::is_plugin"`：插件记录写盘与 API 响应里**不出现** `kind`，
    源条目、索引与签名产物因此字节不变。
- `create` 构造记录时显式写 `kind: EntryKind::Plugin`；本步不新增接口，也不改任何校验与状态机。
- 命名区分：`Submission.kind` 是条目类型；`TakedownInfo.kind` 仍是撤包动作（yank / revoke）。

### 测试

- 新增 `tests/api.rs::plugin_records_omit_kind_and_legacy_records_still_load`：
  插件提交响应与落盘记录都没有 `kind`；无 `kind` 的旧记录反序列化为 `plugin`；
  approve → release 后源条目与 `index.json` 都不出现 `kind`。
- `cargo test -p skiff-server`：32 单测 + 23 API + 4 CLI + 15 P0 + 7 serve + 6 sync，共 87 项全绿；
  `cargo clippy -p skiff-server --all-targets -- -D warnings` 通过。

### 文档

- `docs/SKIFF_SERVER.md`：§17 状态与 §17.3 记录字段补 `kind`，新增 §17.12 R2b 落地说明。
- `docs/TEST_MATRIX.md`：发布面标题与重跑触发更新，新增 API-18。

## R2c：应用模板提交/审核/发布（compose 内容寻址 blob）

R2 的第三步：把提交面从插件扩到 Docker 应用模板。只做提交、审核、发布与展示，
安装仍走内置目录，索引不驱动安装。

### 改动

- `tools/skiff-server/Cargo.toml`：依赖 `skiff-compose`，compose 严格子集校验复用仓库唯一实现
  （与 `skiff-docker`、`xtask` 同源），不另写第二套解析器。
- `src/api/multipart.rs`：新增 `compose` 部分（UTF-8，≤ 1 MiB），并强制 `entry` +
  `package`/`compose` 二选一。
- `src/api/store.rs`：
  - 新增 `AppMeta`、`Submission.app`（插件记录不落该字段）与 `sid_of_app`（加 `app` 域前缀）；
  - 新增 `POST /api/v1/apps` 的 `create_app`：请求签名确立作者、`id` 前缀鉴权、
    `skiff-compose` 严格子集校验、`AppEntry::validate_source` 语义校验、compose 原文落
    `state/submissions/<sid>/compose.yaml`；
  - 版本不可变：同 `(kind=app, id, version)` 不同摘要或已发布 → 409，同摘要重复提交 → 200 同一 `sid`；
  - `reopen` 抽成共享 helper；审核事件 `subject.kind` 改为取自记录（插件仍为 `"plugin"`，字节不变）。
- `src/api/job.rs`：发布时按 `kind` 分流——app 把 compose 复制成 `catalog/assets/<sha>.yaml`，
  写 `catalog/<channel>/apps/<id>-<version>.json`（`asset` 指向该文件）；插件分支逻辑与输出不变；
  runtime 分支显式报「R2d 未接入」。
- `src/api/mod.rs`：路由 `apps` → `create_app`，审计动作记为 `submit`。

### 测试

- 新增：`app_submit_approve_release_writes_compose_blob_and_index`、
  `app_compose_outside_supported_subset_is_rejected`、
  `same_app_version_with_different_compose_conflicts`、
  `plugin_and_app_release_share_one_seq`；`multipart` 补 compose 解析与「package/compose 互斥」单测。
- `cargo test -p skiff-server`：34 单测 + 27 API + 4 CLI + 15 P0 + 7 serve + 6 sync，共 93 项全绿；
  `cargo clippy -p skiff-server --all-targets -- -D warnings` 与 `cargo fmt --check` 通过。

### 边界

- 客户端不依赖 `/api/**`：应用模板继续从签名索引 `apps[]` 展示（商店「应用模板」分区已有），
  R2c 不新增安装入口；`serve` 与 §16 契约零变化。
- 事件 outbox 仍 best-effort，写失败不影响提交/审核/发布结果。

### 文档

- `docs/SKIFF_SERVER.md`：§17 状态、§17.3 补应用模板提交载荷与规则、新增 §17.13 R2c 落地说明。
- `docs/TEST_MATRIX.md`：新增 API-19..API-22。

## R2d：运行环境提交、审核与元数据修订

R2 的第四步：运行环境只做提交/审核/展示，安装仍走内置目录。元数据（`eol`/`default`）
允许在发布后修订，但走独立动作并留审计；镜像与 digest 没有任何修改路径。

### 改动

- `src/api/store.rs`：
  - 新增 `RuntimeMeta`、`RuntimeRevision`、`Submission.runtime` 与 `sid_of_runtime`；
  - 新增 `POST /api/v1/runtimes` 的 `create_runtime`：JSON 载荷、`RuntimeEntry::validate` 语义校验、
    提交时 `default` 必须为 `false`、同 `(kind, version)` 不同 digest 或已发布 → 409、
    同一 digest 换 `image` → 409；
  - 新增 `POST /api/v1/submissions/{sid}/revise` 的 `revise_runtime`：仅审核者、仅 `published`、
    只接受 `eol`/`default`（带其他字段 422）；修订落 `state/runtime_revisions/<id>.json`
    （`seq` 为空表示未应用）并审计 `action=revise`；
  - 新增 `pending_runtime_revisions` / `mark_runtime_revision_released` 供 release 使用。
- `src/api/job.rs`：发布前应用待修订（校验源条目 `image_digest` 与修订一致，只改 `eol`/`default`），
  发布成功后回写修订的 `seq`；仅有修订待应用时也会触发一次发布（`seq` 仍只 +1）；
  运行环境源条目写到 `catalog/<channel>/runtimes/<kind>-<version>.json`。
- `src/build.rs`：同 kind 出现多个 `default=true` 时拒绝生成索引（release 兜底校验）。
- `src/api/mod.rs`：路由 `runtimes` 与 `submissions/{sid}/revise`，审计动作分别记 `submit` / `revise`。

### 测试

- 新增：`runtime_submit_approve_release_writes_index_entry`、`runtime_default_must_be_false_at_submission`、
  `runtime_revision_changes_eol_and_default_with_audit`、`runtime_revision_requires_reviewer_and_published_state`、
  `release_rejects_multiple_defaults_per_kind`。
- `cargo test -p skiff-server`：34 单测 + 32 API + 4 CLI + 15 P0 + 7 serve + 6 sync，共 98 项全绿；
  clippy `-D warnings` 与 fmt 通过。

### 边界

- 客户端不依赖 `/api/**`：运行环境继续从签名索引 `runtimes[]` 展示，安装仍走内置目录；
  `serve` 与 §16 契约零变化；事件 outbox 仍 best-effort，不影响业务结果。

### 文档

- `docs/SKIFF_SERVER.md`：§17 状态、§17.3 补运行环境提交与元数据修订规则、新增 §17.14 R2d 落地说明。
- `docs/TEST_MATRIX.md`：新增 API-23..API-26。

## R2e：分 kind 撤包与独立吊销命名空间

R2 的收尾：应用与运行环境各自拥有吊销命名空间，`revoked[]` 继续只表示插件。

### 改动

- `src/model.rs`：`IndexFile` 新增 `revoked_apps` / `revoked_runtimes`（空时省略）；
  `AppEntry` / `RuntimeEntry` 新增可选 `yanked` / `yank_reason`（未撤包不落字段）。
- `deploy/skiff-server/schema/`：`index.schema.json` 增加两个数组（运行环境条目 id 允许 1 字符的 kind），
  `app.schema.json` / `runtime.schema.json` 增加可选 `yanked` / `yank_reason`。
- `src/api/takedown.rs`：
  - `Takedown` 增加 `entry_kind`（缺省 plugin、不落盘，旧记录可直接读）；记录 id 对插件保持原派生式，
    其它 kind 加类型域前缀；
  - `yank` 泛化为 `yank(entry_kind, id, version)`，三个端点共用；
  - `find_source_entry` / `mark_source_yanked` 按 kind 定位目录（运行环境 id 字段是 `kind`）；
  - `append_source_revocation` 按 kind 写 `revoked.json` / `revoked_apps.json` / `revoked_runtimes.json`，
    新增 `source_digest`（应用取 compose 摘要、运行环境取 digest hex）。
- `src/api/job.rs`：撤包按 kind 写回源条目；插件 `revoke` 追加 `revoked[]`，非插件 `yank` 追加对应 kind 的吊销数组。
- `src/api/mod.rs`：新增 apps/runtimes 的 yank 路由，审计动作记 `yank`。
- 客户端 `crates/app/src/catalog/{model,mod}.rs`：解析两个吊销数组与 `yanked` 字段；
  商店「应用模板」「运行环境」分区的 `warn` 按吊销 > 下架 > EOL 展示。

### 测试

- 新增：`yank_app_marks_source_and_revoked_apps_only`、`yank_runtime_marks_revoked_runtimes_only`、
  `yank_kind_endpoints_are_reviewer_only_and_idempotent`、`plugin_yank_keeps_revoked_namespaces_untouched`，
  以及客户端 `app_and_runtime_takedown_use_their_own_namespaces`。
- `cargo test -p skiff-server` 102 项、`cargo test -p skiff-app catalog` 57 项全绿；clippy `-D warnings`、fmt 通过。

### 边界

- 插件撤包记录与索引字节不变，旧客户端照常解析（新数组为空时不落盘、未知数组被忽略）；
  `revoked[]` 语义不变；客户端仍不依赖 `/api/**`，`serve` 与 §16 零变化。

### 文档

- `docs/SKIFF_SERVER.md`：§17 状态、§17.4 补分 kind 撤包规则、新增 §17.15 R2e 落地说明。
- `docs/TEST_MATRIX.md`：新增 API-27..API-31。
