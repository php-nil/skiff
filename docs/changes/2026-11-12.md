# 2026-11-12

## R2b：提交记录抽象出 `kind`，旧记录与插件全链路零变化

R2 的第二步：先把「提交的是什么条目」从插件硬编码里抽出来，为 R2c 的模板（app）
与 R2d 的运行环境（runtime）铺路，同时保证既有插件链路一个字节都不变。

### 改动（`tools/skiff-server/src/api/store.rs`）

- 新增 `EntryKind`（`plugin` 缺省 / `app` / `runtime`），附 `as_str` 与 `is_plugin`。
- `Submission` 新增 `kind: EntryKind`：
  - `#[serde(default)]`：旧 `state/submissions/*.json` 缺该字段时解析为 `plugin`，无需迁移；
  - `skip_serializing_if = "EntryKind::is_plugin"`：插件记录写盘与 API 响应里**不出现** `kind`，
    源条目、索引与签名产物因此字节不变。
- `create` 构造记录时显式写 `kind: EntryKind::Plugin`；本步不新增接口，也不改任何校验与状态机。
- 命名区分：`Submission.kind` 是条目类型；`TakedownInfo.kind` 仍是撤包动作（yank / revoke）。

### 测试

- 新增 `tests/api.rs::plugin_records_omit_kind_and_legacy_records_still_load`：
  插件提交响应与落盘记录都没有 `kind`；无 `kind` 的旧记录反序列化为 `plugin`；
  approve → release 后源条目与 `index.json` 都不出现 `kind`。
- `cargo test -p skiff-server`：32 单测 + 23 API + 4 CLI + 15 P0 + 7 serve + 6 sync，共 87 项全绿；
  `cargo clippy -p skiff-server --all-targets -- -D warnings` 通过。

### 文档

- `docs/SKIFF_SERVER.md`：§17 状态与 §17.3 记录字段补 `kind`，新增 §17.12 R2b 落地说明。
- `docs/TEST_MATRIX.md`：发布面标题与重跑触发更新，新增 API-18。

## R2c：应用模板提交/审核/发布（compose 内容寻址 blob）

R2 的第三步：把提交面从插件扩到 Docker 应用模板。只做提交、审核、发布与展示，
安装仍走内置目录，索引不驱动安装。

### 改动

- `tools/skiff-server/Cargo.toml`：依赖 `skiff-compose`，compose 严格子集校验复用仓库唯一实现
  （与 `skiff-docker`、`xtask` 同源），不另写第二套解析器。
- `src/api/multipart.rs`：新增 `compose` 部分（UTF-8，≤ 1 MiB），并强制 `entry` +
  `package`/`compose` 二选一。
- `src/api/store.rs`：
  - 新增 `AppMeta`、`Submission.app`（插件记录不落该字段）与 `sid_of_app`（加 `app` 域前缀）；
  - 新增 `POST /api/v1/apps` 的 `create_app`：请求签名确立作者、`id` 前缀鉴权、
    `skiff-compose` 严格子集校验、`AppEntry::validate_source` 语义校验、compose 原文落
    `state/submissions/<sid>/compose.yaml`；
  - 版本不可变：同 `(kind=app, id, version)` 不同摘要或已发布 → 409，同摘要重复提交 → 200 同一 `sid`；
  - `reopen` 抽成共享 helper；审核事件 `subject.kind` 改为取自记录（插件仍为 `"plugin"`，字节不变）。
- `src/api/job.rs`：发布时按 `kind` 分流——app 把 compose 复制成 `catalog/assets/<sha>.yaml`，
  写 `catalog/<channel>/apps/<id>-<version>.json`（`asset` 指向该文件）；插件分支逻辑与输出不变；
  runtime 分支显式报「R2d 未接入」。
- `src/api/mod.rs`：路由 `apps` → `create_app`，审计动作记为 `submit`。

### 测试

- 新增：`app_submit_approve_release_writes_compose_blob_and_index`、
  `app_compose_outside_supported_subset_is_rejected`、
  `same_app_version_with_different_compose_conflicts`、
  `plugin_and_app_release_share_one_seq`；`multipart` 补 compose 解析与「package/compose 互斥」单测。
- `cargo test -p skiff-server`：34 单测 + 27 API + 4 CLI + 15 P0 + 7 serve + 6 sync，共 93 项全绿；
  `cargo clippy -p skiff-server --all-targets -- -D warnings` 与 `cargo fmt --check` 通过。

### 边界

- 客户端不依赖 `/api/**`：应用模板继续从签名索引 `apps[]` 展示（商店「应用模板」分区已有），
  R2c 不新增安装入口；`serve` 与 §16 契约零变化。
- 事件 outbox 仍 best-effort，写失败不影响提交/审核/发布结果。
