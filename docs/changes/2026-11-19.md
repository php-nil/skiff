- **为什么**：测试机上 job `job-1795053550-2542eb080`（安装 PHP 扩展 PDO PostgreSQL）的作业日志首屏渲染崩溃。根因：installer prelude 的 bash 参数展开片段 `${SKIFF_BASE%/}` 被追加成日志，budding 表达式引擎在解析 modelValue 字符串时遇到裸 `/` 误认为正则字面量起始符，后续无闭合 `/` 即抛 `Unterminated regular expression`，整个 code 组件消失。这是**通用 escape 漏洞**——任何含裸 `/` 的 shell 片段（`sed 's/a/b/'`、`PATH=/usr/bin`、`docker run -v /host:/container`）都能触发。
- **验证方式**：浏览器实测失败 job 页面，日志卡片恢复正常渲染；成功 job 页面无回归。全仓 fmt + 根 workspace / plugins 双 workspace clippy `-D warnings` + xtask check 全绿。

### 24. SKIFF_EXTRA_STATIC_DIR：磁盘文件覆盖 rust-embed 入库资源

- **改了什么**：
  - `crates/web/src/assets.rs::static_file`：在 `resolve_alias` 之后、`Assets::get` 之前插入磁盘分支——若 `SKIFF_EXTRA_STATIC_DIR` env 存在且 `{dir}/{asset}` 文件可读，直接从磁盘返回，不走 rust-embed；ETag 用 `sha256_bytes` 运行时计算（与 rust-embed 编译时 hash 对齐），mime-type 和 cache-control 策略完全复用，跳过 gzip 协商（磁盘热更新不需要）。
  - 新增私有 helper `sha256_bytes(data: &[u8]) -> [u8; 32]`，用 workspace `sha2` crate。
  - `crates/web/Cargo.toml`：追加 `sha2 = { workspace = true }`。
- **为什么**：`rust-embed` 编译进二进制的静态资源（JS/CSS/SVG）任何修改都需要重编整个 Rust 二进制 → 推 GitHub → 等 CI Release（musl cross build 约 20 分钟）→ 下载部署，前端迭代节奏被严重拖慢。加一个 env var fallback 后，测试机设上 `SKIFF_EXTRA_STATIC_DIR=/www/skiff/static-override`，以后改 `budding-boot.js` / `skiff.css` 等纯前端文件，SCP 覆盖 → `systemctl reload skiff.service`（或连 reload 都不需要，磁盘文件是每次请求读的）→ 刷新浏览器立即生效。
- **不变量**：磁盘分支完全不影响既有 rust-embed 流程——没设 env 或磁盘文件不存在时行为 100% 不变；ETag/cache-control/If-None-Match/304 协商全部保留，浏览器缓存行为与入库版一致。生产环境不用设这个 env，零额外开销。
- **验证方式**：`cargo clippy -p skiff-web --all-targets -- -D warnings` 全绿（-D clippy::needless-borrows-for-generic-args lint 触发并修复）；磁盘分支只在 env var 存在时进入，默认路径走原有 Assets::get，单测全部通过。
- **验证方式**：`cargo fmt --all --check` + `clippy -p skiff-web --all-targets -- -D warnings` 全绿；JS diff 只动 schema 层（7976-8127 行，原 7976-8073 行替换），动作函数零修改。
