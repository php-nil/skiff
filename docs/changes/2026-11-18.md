# 2026-11-18 变更记录

## 防火墙：端口参数兼容表单字符串，fail2ban 数值参数同口径

- **改了什么**：`plugins/firewall/src/main.rs` 新增 `u64_param`（数字或去空白后的数字字符串都接受），`port_param` 复用它；`h_rule_add`、`h_port_allow`、`h_rule_remove` 的端口，以及 `fail2ban.jail.ensure` 的 `maxretry / findtime / bantime` 全部改走该入口。补单测 `port_param_accepts_number_and_form_string`。
- **为什么**：schema 表单（`input-text` / `number`）提交的 `${port}` 是字符串，原实现只认 JSON number，UI 点「放行」/「添加规则」会报 `端口需在 1..65535`；fail2ban 数值若为字符串则会静默退回默认值（5 / 600 / 3600）。
- **验证方式**：`cargo test --manifest-path plugins/Cargo.toml -p skiff-plugin-firewall`（CI `plugins` job）；测试机 RPC `port.allow {port:"59991",protocol:"both"}` → `rules.list` 出现两条 tcp/udp → `rule.remove` 按 id 逐条删除至空。

## URL 契约 + 旧 SSR 全面清理：旧路由注册直接删除，旧 handler 函数与模板文件一并清除

- **改了什么**：
  1. `lib.rs` 删除 `/sites/env/*` 下 20+ 条路由注册 + 旧 `m/core/*` 深链 dispatch，访问直接 404。补规范路由 `POST /{p}/runtimes/{id}/extensions/batch`（契约 §5.2 batch 动词之前缺失）。
  2. `handlers/menu.rs`：`core/*` 返回 404（而非渲染旧 SSR）。保留 `overview` 概览 SSR（直到插件槽位迁完）和 `plugin/*` 插件工作台。
  3. **删除旧 SSR handler 函数**（共 18 个，均无路由引用）：
     - containers.rs：`list`、`detail`
     - compose.rs：`page`
     - resources.rs：`images`、`networks`、`volumes`（旧页面）
     - files.rs：`legacy_page`、`trash_page`、`quotas_page`
     - docker_settings.rs：`page`
     - settings.rs：`page`、`menu_page`
     - store.rs：`page`
     - nginx.rs：`index`
     - tasks.rs：`list`、`detail`
     - jobs.rs：`list`、`detail`
     - plugins.rs：`list`、`info`
     - sites/runtime.rs：`legacy_env_page`、`legacy_env_detail`、`env_page`
  4. **删除旧 SSR 模板文件**（共 12 个）：containers.html、resources.html、networks.html、site_env.html、menu_settings.html、docker_settings.html、tasks.html、task_detail.html、jobs.html、job_detail.html、plugins.html、plugin_info.html
  5. `templates.rs` 删除对应的 askama 数据结构（MenuSettingsPage、SiteEnvPage、RuntimeKindView、DockerSettingsPage、ContainersPage、ResourcesPage、NetworksPage、PluginsPage、PluginInfoPage、GrantRow、TasksPage、TaskDetailPage、JobsPage、JobDetailPage、ResourceRow）。
  6. `resources.rs` 里 6 个旧表单 POST handler（pull_image、remove_image、create_network、remove_network、create_volume、remove_volume）原本成功后渲染旧 SSR 页面，现在改为重定向到 `/settings/docker`（budding 壳页）。
  7. `main_flow.rs` 测试：删除 `legacy_tasks_filter_stays_on_legacy_route` 测试（依赖已删的 tasks.html），清理 ui_hidden_and_dialog_guards_hold、menu_settings_drops_layout_and_content_width 中对已删模板的 include_str! 引用。
- **为什么**：budding 壳页已全部覆盖资源面板，旧路由 + handler + 模板构成了一整套 dead code。用户明确要求「最终不要有旧版残留」，直接删除而非维护重定向更干净。
- **验证方式**：`cargo check -p skiff-web` ✅；`cargo clippy -p skiff-web -- -D warnings` ✅；`cargo test -p skiff-web --test main_flow legacy_paths_redirect_to_canonical_urls` ✅（files/api 308、docker/settings 308、store GET 303 兼容均正常）。
