# 2026-11-23

## 默认主题换新：图标改「扁舟点灯」、缺省配色改「深潜」、另两套预设可切

**背景**：界面主色一直是 budding/Vuetify 的框架缺省蓝 `#1867c0`，favicon 也是同一色方块；旧壳层 `skiff.css` 里的青绿 `#0f766e` 从未进到运行时。三处互不相干，整站没有品牌痕迹。定稿方向取自设计稿 `.workbuddy/design/theme-3-options.html`：图标用 C「扁舟点灯」的造型、配 A「深潜」的色；默认配色 A；B「石墨」、C「灯塔」保留为可切换预设。

### 1. 图标

- `crates/web/static/favicon.svg`：深墨绿底 `#0c2422` + 薄荷舟身与灯点 `#2fd3b0`，两元素剪影（横置舟身 + 一点灯），替换原来的蓝色方块 + 白色小帆。
- 引用处 `?v=1` → `?v=2`（壳页 `spa.rs`、登录页 `auth.rs`、路由测试），否则浏览器继续用缓存图标。
- `crates/web/src/handlers/auth.rs`：登录页品牌面板的 logo 换成同一造型（`currentColor`，落在半透明玻璃块里）。
- 尺寸取舍：灯点半径从 2.4 加到 3.0，16px 下才不至于消失；舟身保持 24/32 宽、7.6 厚，缩小后仍是「一横」而不是一片糊。

### 2. 缺省主题（深潜）

- `crates/app/src/theme.rs`：`DEFAULT_PRIMARY` `#1867c0` → `#17a98e`，`DEFAULT_PAGE` `#f5f5f5` → `#f4f6f5`，新增 `DEFAULT_MENU = #0c2422`。
- `read_menu_custom` 缺省改为**真**：默认形态是「深色导航 + 浅色内容」，与页面亮度无关；只有显式存 `"0"` 才回到按页面亮度自动取白/近黑。开了自定义却没存过值时落 `DEFAULT_MENU`。
- 新增 `is_dark_page` / `surface` / `surface_raised`：暗底页面（预设「灯塔」）的卡片与次级面按页面底色提亮，避免整页死黑、卡片边界消失。

### 3. 壳主题 CSS

- `spa.rs::theme_css` 增加 `--v-theme-surface` / `--v-theme-on-surface`（原先只覆盖 background，暗底页面上卡片仍是白的）；暗底页面再补 `--v-theme-surface-variant` / `--v-theme-on-surface-variant`。浅色页不注入次级面，保留 Vuetify 自带浅灰。
- `skiff.css`：`--accent` / `--accent-hover` / `--accent-soft` / `--accent-line` / `--focus` / `--nav-accent` / `--nav-active-soft` 及暗色档全部换到青绿族；登录页 `--login-*` 底色、品牌面板渐变（`#0c2422 → #103f39 → #071b18`）同步。
- `skiff-shell.css`：三级菜单里 `--v-theme-primary` 的兜底值 `24, 103, 192` → `23, 169, 142`。
- `SHELL_VERSION` 42 → 43（`skiff.css` / `skiff-shell.css` / `budding-boot.js` 都按 `?v={shell}` 引用）；`budding-boot.js` 的颜色示例改指新主色。

### 4. 预设（界面设置页）

- `settings_page.rs` 的 `UI_THEME_PRESETS` 由 5 套（星蓝 / 翡翠 / 石墨 / 暖岩 / 玫瑰）换成 3 套：**深潜**（= 缺省）、**石墨** `#5a4ae3` + 纯白导航、**灯塔** `#b8f04b` + 近黑底。第一套与 `theme.rs` 缺省值逐字段相等，避免「恢复默认」与「套用深潜」得到两种结果。
- 主色按钮文字保持 `best_on` 的纯黑/纯白二选一，没有引入 `on_primary` 覆盖：青柠、薄荷底上的纯黑与设计稿的近黑（`#0b1400`/`#04211c`）在 11–14px 上几乎不可分辨，不值得多一条配置面与一组派生逻辑。若以后要更柔和的按钮字色，再单独开。

### 5. 用例与文档

- `main_flow.rs`：缺省主色断言改 `#17a98e`，并补缺省菜单 `#0c2422` / `menu_custom=true`；预设名称清单改三套；favicon 请求版本改 `?v=2`。
- `settings_page.rs` 新增两例：三套预设自身必须 ≥ 4.5:1 且页面底色 ≠ 菜单底色；首套预设必须等于缺省主题。
- `theme.rs` 新增两例：缺省形态（深色导航 + 浅色页、主色不被校正）、卡片表面色随页面明暗切换。
- `spa.rs::theme_css_covers_shell_variables` 补 surface 断言与暗底页面分支。
- 文档：`docs/contract/MENU_CONTRACT/02-RENDER.md` §4.7 改写为三字段 + 缺省值 + 三预设 + 预设自检口径。

### 验证方式

`cargo fmt --all` + `cargo clippy -p skiff-app -p skiff-web --all-targets -- -D warnings` 通过（本机内存闸门一度拒到 200MB，按闸门自述用 `SKIFF_GATE_MIN_AVAILABLE_MB=150 ... -j 1` 单次放行）。**用例结果以 CI 为准**（`test` / `test-win`），本机不跑 `cargo test`；测试机浏览器验收待下一次部署。

## 同步上游 budding 1.8.6，并按回执落地上游六项建议

**背景**：上游对 `BUDDING_UPSTREAM_BACKLOG.md` 的 U6–U17 给了回执（`tests/BUDDING_UPSTREAM_BACKLOG_UP.md`），产物升到 1.8.6（`570a00a`）。回执里明确「宿主侧可删除」的两项（K3 弹窗注册表 + 克隆重开、K4 插件 schema 注入 no-op `api`）正是本仓上一轮的临时方案，本轮一并清掉。

### 1. 产物同步

- `crates/web/static/budding/`：`1.8.5` → `1.8.6`（JS 1,027,351 B / CSS 574,157 B / code 90,331 B / terminal 395,014 B / icons CSS 4,645 B + woff2 3,992 B）；旧版六个文件删除。CSS、code、terminal、woff2 与 1.8.5 逐字节相同，只有主包 JS 增加约 5 KB。
- `assets.rs`：`BUDDING_VERSION` / `BUDDING_ICONS_VERSION` 升 1.8.6，`SHELL_VERSION` 42/43 → **44**（`skiff.css` / `skiff-shell.css` / `budding-boot.js` 都按 `?v={shell}` 取，不升会继续跑一年缓存的旧壳）。

### 2. K4：表单提交改 `submitMode: "event"`

- `schema_kit::form` / `form_body` / `search_form` 与 `dialog_form_button` 不再伪造 `api: { sendOn: false }`，改声明 `submitMode: "event"`；`form` / `body` 的 `api_url` 参数随之删除（22 处调用点同步），`DialogForm.url` 字段删除（8 处字面量）。
- 内联表单（文件新建目录 / 新建文件 / 站点日志过滤 / 改密 / 启用 TOTP）同样改成事件模式；`settings` 改密表单上那句不会生效的 `successMessage` 一并删除（成功提示由宿主动作 `toast` 决定）。
- `crates/pkgfmt`：删除 `inject_form_submit_stub` 与其单测；新增校验——**带 `onEvent.submit` 的 `form` 必须声明 `props.submitMode: "event"`**，否则拒装（插件 schema 禁 `api`，缺声明会让提交静默空转）。三个官方插件的 5 张提交表单补上该声明。
- `handlers/plugins.rs`：`GET /schema/{view}` 不再注入，校验通过后原样下发。

### 3. K3：失败原地回填，删除弹窗注册表

- `budding-boot.js`：删除 `dialogRegistry` / `newDialogKey` / `dialogError`（关层后克隆 `content` 重开那一套）；`formError(ctx, message, field)` 改为直接把错误写进表单——`ctx.extras.form.setErrors({ __form__ | <字段>: 文案 })` + `focusFirstError()`，取不到表单（列表行按钮等）时才退回 `toast`。28 处调用点同步，本地校验类失败（目录名 / 文件名 / 权限 / uid… ）指到具体字段。
- `prepareServerSchema` 的 `registerServerDialog` 换成 `markLayerSubmit`：只用 `collectForms` 递归找出 `dialog.action.content` 里的表单，给 `onEvent.submit[0].props` 打 `inLayer: true`；宿主动作里三处 `args.dialog` 改用 `args.inLayer`。资产页 `pages/_file-row.json` 里手写的 `"dialog": "skiff-dialog-N"` 一并改成 `"inLayer": true`（6 处，原先靠注册表键名确定性，脆弱）。
- `submitMode: "event"` 之下组件不再走内置提交，`props.api` 与 `sendOn` 在代码里清零（只在注释里留历史说明）。

### 4. U9：`confirm` 的 `level` 改 `color`

- 壳的 `hostConfirm` 把 `args.level` 换成 `args.color`，`danger: true` 映射 `color: "error"`。上游**不加** `level` 别名，此前危险操作其实一直在用默认色。
