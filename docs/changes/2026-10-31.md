## 修复 CI 四 job 全红：supervisor Linux 专属代码编译不过

- **背景**：CI run 41213869330（HEAD `199289a`）单测 / MSRV / Clippy / 冒烟四个 job 全挂，同一根因在 `crates/plugin/src/supervisor.rs` 的 `#[cfg(unix)]` 代码——Windows 开发机编不到，本地三关看不见：
  - L281 `warn!` 未导入（`tracing::warn`），Linux 上直接编译错；
  - L244 `use std::os::unix::process::CommandExt;` 是死导入（tokio 的 `Command::pre_exec` 是固有方法，不走该 trait），clippy `-D warnings` 下判错。
- **变更**：
  - `warn!` 改全限定 `tracing::warn!`（不加模块级导入，免得非 unix 构建 unused import）；
  - 删掉 `spawn` 里的 `CommandExt` 导入。
- **影响**：纯编译修复，无行为变化；只影响 unix 构建路径。凡 `#[cfg(unix)]` 代码都只能由 Linux CI 把关，本地三关对这类错误天然盲。
- **验证**：本地 Windows 编不到该路径，以 GitHub CI（Linux runner）复核为准，绿后回填。

### CI 复测（run 41216606790）追加修复

- supervisor 修完后错误推进到下一层，三处：
  - `plugin/src/install.rs`：`plugin_uid(id) as u32` 多余转型（clippy `unnecessary_cast`）——`plugin_uid` 本就返回 `u32`；
  - `core/src/kernel.rs`：`use bytes::Bytes` 但 `skiff` 未依赖 `bytes`（E0432）——改用 `axum::body::Bytes`（axum 对 `bytes::Bytes` 的再导出，同类型），不动 `Cargo.toml`；
  - `sdk/tests/kernel_contract.rs`：`FakeKernel.socket` 死字段（`-D warnings` 下判错）——删字段。

### CI 复测（run 41217422729）追加修复：三处 Linux 真跑才暴露的问题

- **`policy` 15 个测试挂（单测 job）**：`check_root_safety` 要求授权根 `uid == 0`，CI 以 `runner` 用户跑，tempdir 归 runner 所有 → 全拒于 `UnsafeRoot`。Windows 上该检查是 no-op，本地全绿。修法：拥有者放宽为「root **或** skiff 进程自身 euid」——生产以 root 跑时两者等价、语义零变化，插件独立 UID 自建的根仍被拒。补一条 `world_writable_root_rejected` 回归（组/其他人可写必须拒）。`docs/sections/05-deploy.md` 授权根表述同步。
- **冒烟 20s 拉不起服务（真起服务 job）**：`main.rs` 里 `kernel::spawn(...).await`——unix 版 `kernel::spawn` 内部是常驻 accept 循环，await 卡死在此，`server::serve` 永远排不到，日志停在「kernel.sock 监听中」后 HTTP 全程 connection refused。Windows 版是立即返回的 stub，本地从没炸。修法：`kernel::spawn` 改为真·后台（内部 `tokio::spawn`，对外非 async），`main.rs` 去掉 `.await`。
- **`kernel_contract::plugin_serve_answers_healthz_and_rpc` 挂（单测 job）**：测试轮询/连接 `dir/plugin.sock`，但 helper 把 `Plugin::socket` 写死为 `temp_dir/skiff-test-plugin.sock`（参数语义是 `kernel_socket`），serve 根本没绑测试等的路径 → 轮询 2s 落空后 connect NotFound。修法：测试内 `p.socket = sock.clone()` 对齐两侧。该文件 `#![cfg(unix)]`，Windows 编不到，同属只能靠 Linux CI 把关的一类。
