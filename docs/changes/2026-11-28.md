# 2026-11-28 变更记录

## 一、架构复审（第八轮）结论

- 分层与依赖方向：`policy` / `pkgfmt` / `wire` 不依赖 `store` / `docker`，无环、无 Cargo feature 分叉，**零违规**。
- 四项单一来源（`skiff-wire` 协议、`plugin::trust::resolve`、`Docker::execute`、`skiff_model::Permission`）：**仍在位**。
- 文件写通道：`xtask check-channel` 白名单 **0 处**（承接 2026-11-27 C15 收口）。
- 本轮债务集中在 **`crates/web` UI 输出端的重复构件**（同一取数/请求/指标卡在 5–8 个 page 模块各写一份），以及 `app` 侧一处单实现 trait。

## 二、UI 输出端复用收口（`crates/web`）

### 2.1 JSON Pointer 取数四件进 `schema_kit`

`text` / `flag` / `num` / `rows` 此前在 8 个 page 模块里共 **14 份逐字相同**的实现。统一进
`handlers/ui/schema_kit.rs`（带「缺失/类型不符一律给空值」的语义说明），页面侧改为
`use super::schema_kit::{text, flag, …}` 直接导入，调用点不动。

| 文件 | 删除的本地副本 |
| --- | --- |
| `files_page.rs` | `text` / `flag` / `rows` |
| `overview_page.rs` | `text` / `flag` / `num` |
| `plugins_page.rs` | `text` / `flag` |
| `runtimes_page.rs` | `text` / `num` |
| `settings_page.rs` | `text` / `flag` |
| `store_page.rs` | `text` / `flag` |
| `web_page.rs` | `text` / `flag` |
| `sites_extra_page.rs` | 本地 `text(v, key)` 取的是顶层键而非 Pointer，**改名 `field`** 以免与 `kit::text` 混同 |

### 2.2 百分号编码四处副本 → `util::encode_uri_component`

`files_page` / `plugins_page` / `runtimes_page` / `containers_page` 各有一份 20 行的
`fn enc`（JS `encodeURIComponent` 语义：额外放行 `! * ' ( )`）。`crates/web/src/util.rs`
早已有 `encode_uri_component`，四份副本删除、16 个调用点改为直接调它。

**行为差异**：`! * ' ( )` 由原样输出变为 `%21 %2A %27 %28 %29`。五个字符在 RFC 3986 的
path/query 里都是合法保留字，服务端解码后等价；比原来**更保守**（不会出现未编码的 `'`）。

### 2.3 `human_size` 两处同名不同义 → 合并

`files_page::human_size`（≥10 取整：`15 KB`）与 `util::human_size`（恒一位小数：`15.0 KB`）
同 crate 同签名、输出不同。保留前者口径（信息密度更高）写回 `util::human_size`，
删除 `files_page` 本地版，文件页 5 个调用点改导入 `util::human_size`；
调用方另有两处（`resources.rs`、`sites.rs`）自动跟随。**展示串变化**：`15.0 KB` → `15 KB`、
`1.0 GB` → `1 GB`，无测试断言依赖旧串。

### 2.4 写请求信封 6 处 → `kit::post_request`

`{type:"request", props:{api:{method:"POST", url, data?}, messages?}}` 此前在容器操作、
回收站、任务、插件启停/卸载、作业取消/重试六处各拼一份。收敛为：

```rust
pub fn post_request(url: impl Into<String>, data: Option<Value>, success: &str, error: &str) -> Value
```

`success` 留空即整段省略 `messages`（原各页语义不同，统一按「空即不提示」），
`data` 为 `None` 时不写该键。作业重试的 `assign: "job"` 是该信封唯一的特例，
在页面侧建好节点后补一个键，不把特例塞进公共构件。

### 2.5 `metric_card` 三处变体 → 一处

`overview_page`（i64 值 + suffix）、`web_page`（&str 值、无 suffix）、`site_page`
（`impl Into<String>` + `Option<color>`）三份同形卡片。统一为
`kit::metric_card(title, value: impl Into<Value>, suffix, caption, color: Option<&str>)`：
`Into<Value>` 保证数字仍按 JSON 数字下发（组件的格式化行为不变），文本按字符串；
14 个调用点按新签名补齐 `suffix` / `Option`。

## 三、`app` 侧过度设计清理

`crates/app/src/tasks/store.rs` 的 `trait ParseAction` 只对 `String` 有一份实现、
全仓只有一个调用点（`audit_of`），改成自由函数 `fn parse_action(&str)`。
方法语法的收益为零，`impl … for String` 也无法被外部复用。
