# 2026-11-10

## SDUI P0 第一批：稳定错误码、动作注册表、授权唯一入口

按 [docs/SDUI_HANDBOOK.md](../SDUI_HANDBOOK.md) §3.2 P0 推进第一批；旧模板、旧交互与页面状态码不变，
不做页面切换，不改 `plugins/`。

### 稳定错误码与统一载荷

- `crates/model/src/error.rs`：新增 `ErrorCategory`（形状 / 未授权 / 领域冲突 / 未找到 / 依赖不可用 / 内部）
  与 `ErrorCode`（`shape.invalid`、`auth.forbidden`、`domain.conflict`、`lookup.not_found`、
  `dependency.unavailable`、`internal` 等 12 个机器码），每个码固定类别、HTTP 状态与 `retryable`；
  单测守护编码前缀、状态码合法性与「只有瞬时依赖故障可重试」。
- `crates/web/src/error.rs`：`AppError` 增加 `InvalidField { field, message }`，新增 `error_code()` /
  `field()` / `envelope()`；`ErrorEnvelope { error: { code, status, message, field, retryable } }`
  作为 `/api/v1` 统一错误载荷。HTML 错误页与既有状态码保持不变。
- 文件管理 API 的 `{ok:false,error:{code,message}}` 形状未动（前端 `files.js` 依赖），只统一授权判定。

### 动作注册表

- `crates/app/src/actions.rs`：新增 `Action` / `ActionSpec` / `Resource` 与 `action_table!`，
  一张表声明「动作 id → 资源 → 权限 → 领域命令 → 危险标记」，覆盖站点、运行时、容器与
  Docker 资源（镜像/网络/卷/Compose）、文件、任务、插件、设置、网站配置、作业，共 77 个动作。
- 权限口径：站点/运行时/文件/任务/设置/网站配置/作业 = `Admin`；插件 = `PluginManage`；
  Docker 动作与 `Verb::permission()` 逐项对齐。用户级菜单偏好不登记为特权动作。
- 单测：动作 id 唯一且 `<resource>.<verb>` 命名、命令名非空、Docker 动作与动词分档一致、
  动作 × 角色矩阵与 `Role::can` 一致、每个动作至少有一个角色可达。

### 授权唯一入口

- `crates/web/src/authz.rs`：`authorize(user, action)` 查注册表后走
  `handlers::require_permission`；`authorize_for(user, permission)` 供无对应动作的读页复用；
  `allowed` 只供展示。
- 写路径改为 `authorize`：`sites.rs` 24 个写 handler（站点 9、运行时 15）、`tasks.rs` 3 个、
  `jobs.rs` 取消/重试/日志、`nginx.rs` 主配置与参数保存；`files.rs` 的 `admin()` 改为收 `Action`，
  22 个 API 与回收站/配额页按动作判定。
- 保持不变：站点/运行时的读页仍走 `sites::require_admin`；设置与插件写路径仍由
  `AdminUser` / `PluginManagerUser` 提取器守门；容器/资源写路径仍走 `policy.check`（对象级保护）。
- 一致性测试：`authz.rs` 覆盖 viewer/operator/admin 三档、提取器守门口径、旧 `require_admin`
  分组口径；`error.rs` 覆盖错误码到状态与载荷形状。

- `cargo fmt -p skiff-model -p skiff-app -p skiff-web`
- `cargo clippy -p skiff-model -p skiff-app -p skiff-web --all-targets -- -D warnings`
- `cargo test -p skiff-model -p skiff-app -p skiff-web`（含 `skiff-web` 集成 89 项）

## SDUI P1 第一批：站点写命令与 DTO 收口

按 [docs/SDUI_HANDBOOK.md](../SDUI_HANDBOOK.md) §3.2 P1 拆分第一组（站点）。旧模板、旧交互、
页面输出与权限口径不变，不改 `plugins/`。

### 命令层

- 新增 `crates/app/src/commands/`：`mod.rs` 放共享 `Actor { username, ip }`（只供审计，不做权限判定）
  与命令单测的最小装配；`site.rs` 为站点 9 个动作各提供一个命令函数：
  `create` / `batch` / `save_config` / `delete` / `power` / `set_default` / `update_domains` / `ssl` / `backup`。
- 入参 DTO 只含业务输入：如 `CreateSite { domain, root_dir, site_type, runtime_id, proxy_target,
  proxy_websocket, aliases, actor }`；`domain` / `root_dir` 为原始输入，域名规范化与站点目录推导
  （`root_slug` ↑ 从 web 迁入）在命令内完成。出参为 `Site` / `VhostSaveOutcome` / `BatchReport`
  或 `SiteError`，不含文案、URL、CSS 等展示字段。
- 审计随命令产生：站点新建、启停、默认站点、别名、SSL、配置保存、删除、批量、备份的
  `audit_or_log` 从 handler 迁入命令；批量失败明细改用领域错误文本（原先携带 `AppError` 的
  `[状态码]` 前缀属于传输层泄漏，本次不再拼入审计），页面提示仍按原格式渲染。
- `crates/app/src/actions.rs`：站点 9 个动作的 `command` 字段改为真实模块路径
  `commands::site::*`；新增漂移测试，要求站点动作指向 `commands::site::NAMES` 中已登记的命令。

### handler 收窄

- `crates/web/src/handlers/sites.rs`：站点写 handler 只保留表单解析、CSRF、`authorize(&user, act::X)`、
  `map_err` 与 flash/跳转；`root_slug` 删除，`actor()` 统一构造命令调用主体。
- 批量删除的拒绝规则（必须走单站输入域名确认）移入命令 `batch`，错误信息与页面表现不变。
- 未知动作分支（站点启停/批量/域名/SSL）仍按原样：启停与批量返回 400，域名与 SSL 走 flash 提示。

### 测试

- 命令层（不依赖 HTTP、不依赖真实 Docker）：非法域名/越界目录优先于 Docker 报错、
  Web 服务缺失映射为 `Unavailable`、未知站点在启停/删除/默认站点/SSL/配置保存/备份上返回
  `BadRequest` 或 `Unavailable`、别名与主域名冲突/重复返回 `Conflict`、批量删除被拒、
  批量部分失败的结构化结果，以及上述路径的审计动作/目标/结果/明细。
- 传输层映射：`handlers/sites.rs` 单测锁定 `SiteError` → `AppError` 的状态码与机器码，
  以及「只有 `Internal` 升级错误页，其余就地提示」。

### 门禁

- `cargo fmt --all`
- `cargo clippy -p skiff-app -p skiff-web --all-targets -- -D warnings`
- `cargo test -p skiff-app -p skiff-web`（app 169 项、web 单元 63 项、web 集成 89 项）

## SDUI P1 第二批：运行时写命令与 DTO 收口

同一口径拆运行时组 15 个动作，`handlers/sites.rs` 的运行环境写 handler 不再直接调用
`AppState` 领域方法，也不手写审计。

### 命令层

- 新增 `crates/app/src/commands/runtime.rs`：`create` / `save_images` / `save_config` /
  `save_node_config` / `save_config_file` / `save_port` / `clone` / `action` /
  `save_extensions` / `install_extension` / `uninstall_extension` / `batch_extensions` /
  `install_pecl` / `probe` / `unbind_site`。
- 需要「先展示影响面再执行」的动作以出参表达：`RuntimeActionOutcome::NeedsConfirm { domains }`
  由 handler 渲染提示；`NodeConfigOutcome` 区分「未变化 / 已提交重建 / 配置已存但重建失败」；
  `CreatedRuntime` 携带是否提交安装任务。
- Web 服务（`id == web`）不落库：分支留在命令内，`sync` 明确拒绝；对应动作仍写
  `web_env.<action>` 审计。
- PHP 配置表单的数值解析与「端口是否被站点占用」的确认仍属表单形状/影响面提示，留在 handler；
  Node 配置的默认值兜底与环境变量文本解析迁入命令。
- `crates/app/src/actions.rs`：运行时 15 个动作的 `command` 指向 `commands::runtime::*`，
  漂移测试扩展为「站点 + 运行时」。

### 测试

- 命令层（不触达 Docker）：类型/版本在提交前校验、Web 服务拒绝 `sync`、未知环境在动作与
  保存路径上返回领域错误、被站点绑定的环境删除返回 `Conflict`、停用需确认时只返回影响面、
  PHP 环境保存 Node 配置返回 `Unavailable`、镜像参数落库与审计、解绑未知站点写失败审计。
- 传输层映射测试继续复用站点组的 `SiteError → AppError` 用例（运行时同用 `SiteError`）。

## SDUI P1 第三批：Docker 资源写命令与 DTO 收口

同一口径拆 Docker 资源组（容器 / 镜像 / 网络 / 卷 / Compose），
`handlers/containers.rs`、`handlers/resources.rs`、`handlers/compose.rs` 的写路径不再直接
`docker().execute` 或手写审计；读写流（exec、日志、详情查看）保持原样。

### 命令层

- 新增 `crates/app/src/commands/docker.rs`：`container_create` / `container_update` /
  `container_action` / `image_pull` / `image_remove` / `network_create` / `network_remove` /
  `volume_create` / `volume_remove` / `compose_up` / `compose_down` / `compose_project_action`。
- `DockerCommandError { BadRequest, Conflict, Unavailable }` 作为领域错误；`DockerError`
  不再穿透到 handler。各资源组按原 handler 口径映射：容器动作/Compose → `Unavailable`，
  命名资源（镜像/网络/卷）→ `BadRequest`，BusyGuard 拒绝 → `Conflict`。
- `ContainerTarget { name, short_id, object }` 承载已由写入口判定过权限的对象；命令内不再
  做 `policy.check`，避免两套授权口径。删除仍强制 `force: true`，BusyGuard 的 deny 审计随命令产生。
- `compose_project_action` 只接收已过对象级权限的目标清单，逐目标执行并返回
  `ProjectActionReport { done, failed }`；权限拒绝的目标仍由 handler 计入失败且不写审计。

### handler 收窄

- 容器：`create` 的「Docker 回包缺 id」仍映射传输层 400，引擎失败回填表单页；`update_limits`
  与 `action` 只做解析、`policy.check` 与跳转；资源限制校验仍在 handler（`validate_limits`）。
- 资源：镜像拉取失败仍以页面错误呈现（200），删除/网络/卷失败仍是 400；拉取后的整页重取不变。
- Compose：`up`/`down` 的引擎失败仍回填页面错误块，`project_action` 的 flash 文案不变。
- exec/日志流式通道不经过命令层，`actions.rs` 中 `CONTAINER_EXEC` 仍指向 `docker::execute`。

### 测试

- 命令层（不触达 Docker）：容器创建/动作的 `Unavailable` 映射与失败审计目标、
  内核任务运行中删除返回 `Conflict` 并写 deny 审计、六类命名资源统一 `BadRequest` 与失败审计、
  Compose up/down 的错误映射与审计、空目标的项目动作是零副作用 no-op。
- `actions.rs` 漂移测试扩展到 Docker 五个资源，`docker::execute` 作为流式通道显式豁免。
- 页面对外行为未变，web 既有 63 项单元 + 89 项集成测试全绿。

### 门禁

- `cargo fmt --all`
- `cargo clippy -p skiff-app -p skiff-web --all-targets -- -D warnings`
- `cargo test -p skiff-app -p skiff-web`（app 183 项、web 单元 63 项、web 集成 89 项）
