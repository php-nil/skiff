# 2026-11-10

## SDUI P0 第一批：稳定错误码、动作注册表、授权唯一入口

按 [docs/SDUI_HANDBOOK.md](../SDUI_HANDBOOK.md) §3.2 P0 推进第一批；旧模板、旧交互与页面状态码不变，
不做页面切换，不改 `plugins/`。

### 稳定错误码与统一载荷

- `crates/model/src/error.rs`：新增 `ErrorCategory`（形状 / 未授权 / 领域冲突 / 未找到 / 依赖不可用 / 内部）
  与 `ErrorCode`（`shape.invalid`、`auth.forbidden`、`domain.conflict`、`lookup.not_found`、
  `dependency.unavailable`、`internal` 等 12 个机器码），每个码固定类别、HTTP 状态与 `retryable`；
  单测守护编码前缀、状态码合法性与「只有瞬时依赖故障可重试」。
- `crates/web/src/error.rs`：`AppError` 增加 `InvalidField { field, message }`，新增 `error_code()` /
  `field()` / `envelope()`；`ErrorEnvelope { error: { code, status, message, field, retryable } }`
  作为 `/api/v1` 统一错误载荷。HTML 错误页与既有状态码保持不变。
- 文件管理 API 的 `{ok:false,error:{code,message}}` 形状未动（前端 `files.js` 依赖），只统一授权判定。

### 动作注册表

- `crates/app/src/actions.rs`：新增 `Action` / `ActionSpec` / `Resource` 与 `action_table!`，
  一张表声明「动作 id → 资源 → 权限 → 领域命令 → 危险标记」，覆盖站点、运行时、容器与
  Docker 资源（镜像/网络/卷/Compose）、文件、任务、插件、设置、网站配置、作业，共 76 个动作。
- 权限口径：站点/运行时/文件/任务/设置/网站配置/作业 = `Admin`；插件 = `PluginManage`；
  Docker 动作与 `Verb::permission()` 逐项对齐。用户级菜单偏好不登记为特权动作。
- 单测：动作 id 唯一且 `<resource>.<verb>` 命名、命令名非空、Docker 动作与动词分档一致、
  动作 × 角色矩阵与 `Role::can` 一致、每个动作至少有一个角色可达。

### 授权唯一入口

- `crates/web/src/authz.rs`：`authorize(user, action)` 查注册表后走
  `handlers::require_permission`；`authorize_for(user, permission)` 供无对应动作的读页复用；
  `allowed` 只供展示。
- 写路径改为 `authorize`：`sites.rs` 24 个写 handler（站点 10、运行时 14）、`tasks.rs` 3 个、
  `jobs.rs` 取消/重试/日志、`nginx.rs` 主配置与参数保存；`files.rs` 的 `admin()` 改为收 `Action`，
  22 个 API 与回收站/配额页按动作判定。
- 保持不变：站点/运行时的读页仍走 `sites::require_admin`；设置与插件写路径仍由
  `AdminUser` / `PluginManagerUser` 提取器守门；容器/资源写路径仍走 `policy.check`（对象级保护）。
- 一致性测试：`authz.rs` 覆盖 viewer/operator/admin 三档、提取器守门口径、旧 `require_admin`
  分组口径；`error.rs` 覆盖错误码到状态与载荷形状。
