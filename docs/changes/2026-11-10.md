## 站点统一身份：`skiff-web` 201000:201000

目的：站点内容（文档根、FTP 上传、面板文件管理写入、插件写入）归属同一个专用 uid，
`ls -ln` 一眼判断权限是否正确。不追求某个具体数字，但数值必须固定、任何机器一致。

### 身份与安装

- 常量集中在 `crates/model/src/site.rs`：`SITE_USER` / `SITE_UID` / `SITE_GID` /
  `SITE_INDEX_DIR` / `is_site_index_path`。数值避开人类账号（1000 左右）与插件
  UID（200000–200999）。
- `deploy/install.sh`：建运行组之后做 preflight 并幂等建号——
  `groupadd -g 201000 skiff-web`、`useradd -u 201000 -g 201000 -M -s /usr/sbin/nologin skiff-web`
  （Alpine 走 `addgroup`/`adduser`）。UID 或 GID 已被其它账号/组占用直接 `die`，
  **不静默换号**；已存在同名同号则复用。

### 四个写入点

1. **建站落盘**：`create_site` 结束前对 `sites/<domain>/index` 递归 `lchown` 到统一身份。
2. **FTP 建号**：`resolve_identity` 对 PHP 与静态站一律返回 201000:201000；
   删除容器 `www-data` 探测、`skiff-ftp` 动态系统用户与相关辅助函数。
3. **面板文件管理**：`api_write`/`api_upload`/`api_mkdir`/`api_archive` 写单路径后归还；
   `api_rename`/`api_copy`/`api_extract` 可能移动/生成子树，递归归还。
4. **插件 `fs` 写宿主路径**：`fsops::atomic_replace` 与 `write_chunk` 在
   `is_site_index_path` 命中时 `lchown` 归还。这是「保持宿主原属主」的唯一例外。

权限边界不变：`/www`、数据根仍 0711；只改 `index/` 子树属主。`is_site_index_path`
对含 `..` 的未规范化路径直接返回 false，避免 `index/../log` 被误判。

### PHP 容器（不改镜像）

- 数据根写只读初始化脚本 `php-account-init.sh`（0644 root:root），单文件 bind mount 到
  `/usr/local/etc/skiff-php-init.sh`；容器启动命令改为
  `["/bin/sh", "/usr/local/etc/skiff-php-init.sh"]`。脚本按包管理器幂等建号后
  `exec php-fpm`，master 仍以 root 起、再按池降权；镜像自带 `www-data` 保留。
- 拉镜像后核验 `Config.User` 为空且 `Config.Entrypoint` 含 `docker-php-entrypoint`，
  不满足直接失败，不猜启动路径。
- 池模板 `user/group` 改为 `skiff-web`；debian 系 `session.save_path` 指到 `/tmp`，
  `opcache.file_cache` 指到 `/tmp/skiff-opcache`（脚本建目录并 chown）；socket 仍由

- 明确不做：容器级 `--user`、`userns-remap`、挂载 `/etc/passwd` 片段。

## 防火墙插件：fail2ban 显式安装/卸载/启停与真实三态

- `firewall` 能力面新增 `fail2ban.start` / `fail2ban.stop` / `fail2ban.uninstall`
  （实现仍在 `crates/plugin/src/firewall.rs`，内核只做鉴权、审计与特权命令通道）：
  - `start`：`systemctl enable --now fail2ban`；`stop`：`disable --now`；未安装回 503，
    可读 message「fail2ban 未安装，无法启动/停止/卸载」。
  - `uninstall`：停服务 → 删除本能力面写入的 `skiff-defaults.conf` → `apt-get purge -y fail2ban`；
    停止失败不阻断卸载，原因放返回 `warning`；其它 `skiff-<jail>.conf` 保留。
  - `fail2ban.status` 增加 `state`（`missing` / `stopped` / `running`）与 `reason`
    （`systemctl is-active` 的 inactive/failed/未知状态翻成可读中文）；未运行时不再调用
    `fail2ban-client status`，避免把连接失败当成「无 jail」。
- 插件侧：`plugins/firewall` 的 RPC 路由、manifest verbs 同步；fail2ban 页按三态渲染
  安装/启动/停止/卸载按钮，失败后就地显示原因并重拉状态；卸载有二次确认。
- 审计沿用 `firewall.<method>`：`firewall.fail2ban.start/stop/uninstall`，actor `plugin:<id>`，
  source `uds`，result `ok|fail|deny`。
- 文档：`KERNEL_FIREWALL_CONTRACT.md` §3/§4/§6/§8/§9、`plugins/README.md`、
  `PLUGIN_CATALOG.md`、`TEST_MATRIX.md`（FW-07–FW-09）、`crates/sdk` 方法清单。
- 测试：`crates/plugin/src/firewall.rs` 新增三态、未安装 503、卸载流程单测。
- 明确不做：`start/stop/uninstall` 不通过 interop 暴露，避免调用方隐式改动服务生命周期。

## 修复 Skiff-server CLI 旗标解析失效（`--unsigned` / `--require-signature`）

- 根因：`main.rs::parse` 用 `strip_prefix("--")` 后的名字与调用方传入的 `["--unsigned"]` /
  `["--require-signature"]` 比较，两边永远不相等；旗标被当成缺值的普通选项，实际不生效。
- 修复：旗标判定改为按完整参数比较，`seen_flags` 也存完整形式，与调用方、选项键（`--dist` 等）
  统一为「带 `--` 的完整表示」；`--key=value` 与 `--key value` 仍归一为 `--key`。
- 自查：其余子命令名（`gen`/`publish`/`check`/`sync`/`help`）直接比对原始参数，其余选项读写均为
  `--key`，未发现同类前后缀不一致。
- 新增 `tools/skiff-server/tests/cli.rs`（4 项，直接执行编译出的二进制）：`--unsigned` 无密钥也能
  产出全 0 `key_id` 的空签名占位、`--unsigned` 压过环境里的私钥、不带 `--unsigned` 且无密钥时点名
  `SKIFF_SIGNING_KEY` 失败、同一未签名产物不带 `--require-signature` 通过而带上后失败。
- 门禁：`cargo fmt --all`、`cargo clippy -p skiff-server --all-targets -- -D warnings`、
  `cargo test -p skiff-server`（cli 4 + p0 12 + sync 6）。

## 内核健壮性第三轮：能力面阻塞 IO、查库失败语义、审计留痕

只看内核（`crates/`），不涉及 `plugins/` 第二个 workspace；行为与协议形状不变。

### 能力面 fs 阻塞 IO 移出 async worker

- `crates/plugin/src/capability.rs`：`fs_read` / `fs_write` / `fs_list` / `fs_mkdir` /
  `fs_remove` / `fs_rename` 中真正触碰磁盘的 `fsops::*` 调用（含整文件写的临时文件 +
  `sync_all` + rename、`read_dir` 逐项 `canonicalize`、chown）统一改走 `offload_fs` →
  `tokio::task::spawn_blocking`。路径判定与受保护目录检查仍在 async 侧（纯路径运算），
  审计与响应组装保持在原位置；`filter_protected` 改为接收数据根，便于随 list 一起下沉。

### 查库失败不再伪装成「越权 / 不存在」

- `crates/core/src/kernel/capability.rs`：`docker_call` 读插件授权由 `_ => Vec::new()`
  改为三分支——`Ok(Some)` 正常、`Ok(None)` 记 `deny` 并回 403（会话与库不一致）、
  `Err(e)` 记 `fail` 并回 503。此前 DB 故障会以空授权进入判权，产生一条误导性的
  `deny` 审计。
- 同一文件 `identity_self`：`Err` 不再回落 404「插件不存在」，改为 500 + 错误日志。

### 插件拉起成功后的状态回写失败不再反向判失败

- `crates/plugin/src/supervisor.rs`：`spawn()` 成功后 `set_plugin_status("running")`
  由 `?` 改为记录 `warn` 后照常返回 socket。进程已经拉起，状态回写失败不应让调用方
  以为启动失败（此前会返回错误但进程实际在跑，下一轮 `ensure` 又直接复用，语义矛盾）。

### 审计写入失败统一留痕

- `crates/web/src/handlers/mod.rs` 新增 `audit_db`（与 `AppState::audit_or_log` 同语义，
  供只拿得到 `Arc<Db>` 的闭包使用）；Web 侧剩余的 `let _ = db.audit(...)` 全部改为
  `state.audit_or_log(...)` / `handlers::audit_db(...)`，涉及 `api` / `containers`
  （含 exec WebSocket 的 start/fail/end）/ `docker_settings` / `jobs` / `nginx` /
  `plugins` / `store` / `settings`。内核侧 `kernel/interop.rs` 同步改为 `audit_or_log`。
  审计内容、顺序与「操作结果不受审计失败影响」的口径均不变，只是写失败会落 `error` 日志。

### 留待决策（本轮未改）

- ~~`AppState::set_plugin_enabled` 的 `enabled` 与 `status` 两次写库不在同一事务~~：已由
  `Db::set_plugin_enabled_state` 合并为单条 `UPDATE` 收口，见文首「插件启用状态合并写」。

## 上机 FAIL 修复（`eea2969` 验收四条）

### 1. Debian 系 PHP 池 `nobody` 组

- 根因：池模板固定 `listen.group = nobody`，Debian 系 gid 65534 的组名是 `nogroup`，
  FPM 启动时 `getgrnam("nobody")` 失败。
- 修法：不加镜像家族分支，改由容器初始化脚本（`PHP_ACCOUNT_INIT_SCRIPT`）在 `exec php-fpm`
  前保证 `nobody` 解析到 65534——已存在则校验 gid，缺失则 `groupadd -o`（Alpine 用
  `addgroup`）建同 gid 别名，最后兜底直写 `/etc/group`。模板与 golden 不变，自建镜像同样适用。
- 测试：`php_init_script_resolves_nobody_from_gid_not_family_name` 断言别名段不含
  `alpine-release` / `debian_version` 且与 `SOCKET_GID` 一致。

### 2. 任务中心重试只插行不执行

- `crates/app/src/sites.rs` 新增 `retry_job`：先按原作业 kind/params 解析 `RetryPlan`，再插入
  新行并 spawn 与正常提交相同的执行器（`run_runtime_install_job` / `run_single_extension_job` /
  `run_runtime_extensions_job` / `run_batch_extensions_job`）；无执行器的 kind 直接 400 且不插行。
- 同目标冲突口径：唯一索引返回 Busy → 409「该对象已有任务在执行…」，明确拒绝、不排队。
- `crates/web/src/handlers/jobs.rs::retry` 改走 `retry_job` 并映射 `SiteError`。
- 测试：`main_flow.rs::job_retry_reuses_executor_and_rejects_unsupported_kind`。

### 3. 插件 RPC 状态码错位

- `rpc_error` 改为逐语义透传内核状态：401/403/404/409/500/503/504/507 → 对应 `AppError`；
  仅未识别状态与普通业务错误归 400。此前 500 也被压成 400，一并纠正。
- 测试：`rpc_error_passes_kernel_status_through` 覆盖 503/500/401/504/未识别/业务错误。

### 4. fail2ban 装后配置不生效

- `fail2ban_install` / `fail2ban_start` 改为 `systemctl enable` + 显式 `restart`，不再依赖对
  已运行服务无效的 `enable --now`。
- 新增 `restart_and_verify`：重启后按 `skiff-*.conf` 中 `enabled = true` 复核实际 jail；
  非预期 jail 先 `fail2ban-client stop`，缺失关闭段时追加到 `skiff-defaults.conf` 再重启复核，
  返回可带 `disabled_jails`。无托管 defaults（宿主原有 fail2ban）时不触碰既有 jail。
- 测试：安装后停用 sshd、启动时补写关闭段、无 defaults 不干预宿主 jail、`enabled_jails` 解析。
