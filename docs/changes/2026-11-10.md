# 2026-11-10

## SDUI P0 第一批：稳定错误码、动作注册表、授权唯一入口

按 [docs/SDUI_HANDBOOK.md](../SDUI_HANDBOOK.md) §3.2 P0 推进第一批；旧模板、旧交互与页面状态码不变，
不做页面切换，不改 `plugins/`。

### 稳定错误码与统一载荷

- `crates/model/src/error.rs`：新增 `ErrorCategory`（形状 / 未授权 / 领域冲突 / 未找到 / 依赖不可用 / 内部）
  与 `ErrorCode`（`shape.invalid`、`auth.forbidden`、`domain.conflict`、`lookup.not_found`、
  `dependency.unavailable`、`internal` 等 12 个机器码），每个码固定类别、HTTP 状态与 `retryable`；
  单测守护编码前缀、状态码合法性与「只有瞬时依赖故障可重试」。
- `crates/web/src/error.rs`：`AppError` 增加 `InvalidField { field, message }`，新增 `error_code()` /
  `field()` / `envelope()`；`ErrorEnvelope { error: { code, status, message, field, retryable } }`
  作为 `/api/v1` 统一错误载荷。HTML 错误页与既有状态码保持不变。
- 文件管理 API 的 `{ok:false,error:{code,message}}` 形状未动（前端 `files.js` 依赖），只统一授权判定。

### 动作注册表

- `crates/app/src/actions.rs`：新增 `Action` / `ActionSpec` / `Resource` 与 `action_table!`，
  一张表声明「动作 id → 资源 → 权限 → 领域命令 → 危险标记」，覆盖站点、运行时、容器与
  Docker 资源（镜像/网络/卷/Compose）、文件、任务、插件、设置、网站配置、作业，共 77 个动作。
- 权限口径：站点/运行时/文件/任务/设置/网站配置/作业 = `Admin`；插件 = `PluginManage`；
  Docker 动作与 `Verb::permission()` 逐项对齐。用户级菜单偏好不登记为特权动作。
- 单测：动作 id 唯一且 `<resource>.<verb>` 命名、命令名非空、Docker 动作与动词分档一致、
  动作 × 角色矩阵与 `Role::can` 一致、每个动作至少有一个角色可达。

### 授权唯一入口

- `crates/web/src/authz.rs`：`authorize(user, action)` 查注册表后走
  `handlers::require_permission`；`authorize_for(user, permission)` 供无对应动作的读页复用；
  `allowed` 只供展示。
- 写路径改为 `authorize`：`sites.rs` 24 个写 handler（站点 9、运行时 15）、`tasks.rs` 3 个、
  `jobs.rs` 取消/重试/日志、`nginx.rs` 主配置与参数保存；`files.rs` 的 `admin()` 改为收 `Action`，
  22 个 API 与回收站/配额页按动作判定。
- 保持不变：站点/运行时的读页仍走 `sites::require_admin`；设置与插件写路径仍由
  `AdminUser` / `PluginManagerUser` 提取器守门；容器/资源写路径仍走 `policy.check`（对象级保护）。
- 一致性测试：`authz.rs` 覆盖 viewer/operator/admin 三档、提取器守门口径、旧 `require_admin`
  分组口径；`error.rs` 覆盖错误码到状态与载荷形状。

## SDUI P1 第一批：站点写命令与 DTO 收口

按 [docs/SDUI_HANDBOOK.md](../SDUI_HANDBOOK.md) §3.2 P1 拆分第一组（站点）。旧模板、旧交互、
页面输出与权限口径不变，不改 `plugins/`。

### 命令层

- 新增 `crates/app/src/commands/`：`mod.rs` 放共享 `Actor { username, ip }`（只供审计，不做权限判定）
  与命令单测的最小装配；`site.rs` 为站点 9 个动作各提供一个命令函数：
  `create` / `batch` / `save_config` / `delete` / `power` / `set_default` / `update_domains` / `ssl` / `backup`。
- 入参 DTO 只含业务输入：如 `CreateSite { domain, root_dir, site_type, runtime_id, proxy_target,
  proxy_websocket, aliases, actor }`；`domain` / `root_dir` 为原始输入，域名规范化与站点目录推导
  （`root_slug` ↑ 从 web 迁入）在命令内完成。出参为 `Site` / `VhostSaveOutcome` / `BatchReport`
  或 `SiteError`，不含文案、URL、CSS 等展示字段。
- 审计随命令产生：站点新建、启停、默认站点、别名、SSL、配置保存、删除、批量、备份的
  `audit_or_log` 从 handler 迁入命令；批量失败明细改用领域错误文本（原先携带 `AppError` 的
  `[状态码]` 前缀属于传输层泄漏，本次不再拼入审计），页面提示仍按原格式渲染。
- `crates/app/src/actions.rs`：站点 9 个动作的 `command` 字段改为真实模块路径
  `commands::site::*`；新增漂移测试，要求站点动作指向 `commands::site::NAMES` 中已登记的命令。

### handler 收窄

- `crates/web/src/handlers/sites.rs`：站点写 handler 只保留表单解析、CSRF、`authorize(&user, act::X)`、
  `map_err` 与 flash/跳转；`root_slug` 删除，`actor()` 统一构造命令调用主体。
- 批量删除的拒绝规则（必须走单站输入域名确认）移入命令 `batch`，错误信息与页面表现不变。
- 未知动作分支（站点启停/批量/域名/SSL）仍按原样：启停与批量返回 400，域名与 SSL 走 flash 提示。

### 测试

- 命令层（不依赖 HTTP、不依赖真实 Docker）：非法域名/越界目录优先于 Docker 报错、
  Web 服务缺失映射为 `Unavailable`、未知站点在启停/删除/默认站点/SSL/配置保存/备份上返回
  `BadRequest` 或 `Unavailable`、别名与主域名冲突/重复返回 `Conflict`、批量删除被拒、
  批量部分失败的结构化结果，以及上述路径的审计动作/目标/结果/明细。
- 传输层映射：`handlers/sites.rs` 单测锁定 `SiteError` → `AppError` 的状态码与机器码，
  以及「只有 `Internal` 升级错误页，其余就地提示」。
