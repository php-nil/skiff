## SDUI P0 第一批：稳定错误码、动作注册表、授权唯一入口

按 [docs/SDUI_HANDBOOK.md](../SDUI_HANDBOOK.md) §3.2 P0 推进第一批；旧模板、旧交互与页面状态码不变，
不做页面切换，不改 `plugins/`。

### 稳定错误码与统一载荷

- `crates/model/src/error.rs`：新增 `ErrorCategory`（形状 / 未授权 / 领域冲突 / 未找到 / 依赖不可用 / 内部）
  与 `ErrorCode`（`shape.invalid`、`auth.forbidden`、`domain.conflict`、`lookup.not_found`、
  `dependency.unavailable`、`internal` 等 12 个机器码），每个码固定类别、HTTP 状态与 `retryable`；
  单测守护编码前缀、状态码合法性与「只有瞬时依赖故障可重试」。
- `crates/web/src/error.rs`：`AppError` 增加 `InvalidField { field, message }`，新增 `error_code()` /
  `field()` / `envelope()`；`ErrorEnvelope { error: { code, status, message, field, retryable } }`
  作为 `/api/v1` 统一错误载荷。HTML 错误页与既有状态码保持不变。
- 文件管理 API 的 `{ok:false,error:{code,message}}` 形状未动（前端 `files.js` 依赖），只统一授权判定。

### 动作注册表

- `crates/app/src/actions.rs`：新增 `Action` / `ActionSpec` / `Resource` 与 `action_table!`，
  一张表声明「动作 id → 资源 → 权限 → 领域命令 → 危险标记」，覆盖站点、运行时、容器与
  Docker 资源（镜像/网络/卷/Compose）、文件、任务、插件、设置、网站配置、作业，共 77 个动作。
- 权限口径：站点/运行时/文件/任务/设置/网站配置/作业 = `Admin`；插件 = `PluginManage`；
  Docker 动作与 `Verb::permission()` 逐项对齐。用户级菜单偏好不登记为特权动作。
- 单测：动作 id 唯一且 `<resource>.<verb>` 命名、命令名非空、Docker 动作与动词分档一致、
  动作 × 角色矩阵与 `Role::can` 一致、每个动作至少有一个角色可达。

### 授权唯一入口

- `crates/web/src/authz.rs`：`authorize(user, action)` 查注册表后走
  `handlers::require_permission`；`authorize_for(user, permission)` 供无对应动作的读页复用；
  `allowed` 只供展示。
- 写路径改为 `authorize`：`sites.rs` 24 个写 handler（站点 9、运行时 15）、`tasks.rs` 3 个、
  `jobs.rs` 取消/重试/日志、`nginx.rs` 主配置与参数保存；`files.rs` 的 `admin()` 改为收 `Action`，
  22 个 API 与回收站/配额页按动作判定。
- 保持不变：站点/运行时的读页仍走 `sites::require_admin`；设置与插件写路径仍由
  `AdminUser` / `PluginManagerUser` 提取器守门；容器/资源写路径仍走 `policy.check`（对象级保护）。
- 一致性测试：`authz.rs` 覆盖 viewer/operator/admin 三档、提取器守门口径、旧 `require_admin`
  分组口径；`error.rs` 覆盖错误码到状态与载荷形状。

## Skiff-server P0：清单 schema、样例与静态产物生成

按 [docs/SKIFF_SERVER.md](../SKIFF_SERVER.md) §8 的 P0 落地**服务端产物侧**：源数据 → 校验 →
静态产物树。不引入常驻服务，不碰 `crates/app|web|core`，客户端拉取与签名流水线未接入。

### 实现落点

- 新增根 workspace 成员 `tools/skiff-server`（`anyhow` / `serde_json` / `sha2` / `ed25519-dalek`）：
  纯 Rust、零原生 C 依赖，故不放依赖 `zstd`/`rusqlite` 的 `xtask`。
- `deploy/skiff-server/schema/`：`channel` / `plugin` / `app` / `runtime` / `upgrade` / `index` /
  `manifest` / `signature` 共 8 份 JSON Schema，字段版本写在 `schema` 常量里。
- `deploy/skiff-server/catalog/`：`stable` 渠道的四类条目各一条 + `assets/` 占位资产；
  源条目用 `asset`，生成器读文件后派生 `*_sha256` / `*_url` / `size` 并移除 `asset`。
- 校验路径：`schema.rs` 自研最小 JSON Schema 子集（`type`/`required`/`properties`/
  `additionalProperties`/`items`/`enum`/`const`/`minLength`/`maxLength`/`minimum`/`maximum`/
  `allOf`/相对文件 `$ref`），`model.rs` 做语义校验（反向域名 id、semver、摘要、时间戳、URL）。

### 产物与命令

- `gen` 从源数据生成 `channels/<name>/{manifest.json,manifest.json.sig,index.json}` +
  `blobs/sha256/<hex>` + `schema/`；`seq` 与 `generated_at` 取自 `channel.json`，条目稳定排序，
  同一输入两次生成字节一致。
- `check` 校验 schema 合规、摘要与大小一致、索引引用完整（并禁孤儿 blob）、`seq` 不回退；
  `--require-signature` 作为发布门禁，占位签名直接失败。签名只有接口（`Signer` 占位），
  未生成真实密钥。
- CI 新增 `server` job 跑 `cargo run --locked -p skiff-server -- check`；
  [docs/CI.md](../CI.md) §2/§6 同步。

### 测试

- `tools/skiff-server/tests/p0.rs` 8 项：样例过 schema 与语义、非法条目被拒（未知字段/坏枚举/
  缺必填/坏类型）、生成索引含样例、篡改或缺失 blob 被拒、确定性生成、`seq` 回退被拒、
  未签名产物在严格模式失败、签名接口可验签且篡改后验签失败。
- 门禁：`cargo fmt -p skiff-server -- --check`、`cargo clippy -p skiff-server --all-targets --
  -D warnings`、`cargo test -p skiff-server`。

### 未完成

签名流水线（私钥托管、离线签发、轮换）、镜像同步脚本、客户端拉取/验签/缓存/回退、增量索引。

## Skiff-server P1：客户端只读接入（商店目录展示）

按 [docs/SKIFF_SERVER.md](../SKIFF_SERVER.md) §11 落地客户端只读接入：拉取渠道清单、验签、
防回滚、本地缓存与「插件 → 商店」只读页面。不做安装、不引入常驻服务、不改 `plugins/`，也不动
既有插件安装与 TOFU 信任链路；配置默认关闭。

### 拉取 / 验签 / 缓存

- 新增 `crates/app/src/catalog/`：`model.rs`（清单/索引字段与校验）、`fetch.rs`（`Transport`
  + ureq HTTPS 实现 + 测试假传输层）、`verify.rs`（Ed25519 固定公钥验签、`key_id =
  sha256(公钥)`）、`store.rs`（原子缓存与 `meta.json`）、`mod.rs`（`CatalogService` 状态机）。
- 缓存 `<data_dir>/catalog/`：`channels/<channel>/{manifest.json,manifest.json.sig,index.json}` +
  `blobs/sha256/` + `meta.json`（已见 seq、ETag/Last-Modified、上次成功时间与来源）。
- 条件请求：manifest/index 带 `If-None-Match` / `If-Modified-Since`，304 直接复用缓存并标记
  「目录未更新」；manifest 304 时不再重复拉签名（复用已验过的缓存）。
- 失败处理：验签失败、`seq` 回退、索引摘要/大小不符、条目摘要三件套不一致一律拒绝新清单，
  保留上次成功快照并标「校验失败」；全部镜像不可达标「离线」；未签名渠道默认拒绝，只有
  `allow_unsigned`（且启动期确认开发模式）才放行。多镜像按序回退。
- 条目校验：`*_sha256` / `*_url` / `size` 必须同时存在，URL 必须是 `blobs/sha256/<sha>`；
  本地已有同名 blob 时复核大小与 sha256，不符即拒绝。

### 配置与页面

- `crates/core/src/config.rs`：新增 `[catalog]`（`enabled` / `channel` / `mirrors` /
  `public_key` / `allow_unsigned` / `timeout_secs`）与环境变量 `SKIFF_CATALOG_*`；镜像必须
  `https://`，公钥必须是合法 Ed25519 点，`allow_unsigned` 在非开发形态启动失败。
  `deploy/config.toml.example` 同步示例（默认注释关闭）。
- `crates/web`：新增 `/{p}/store` 只读页、深链 `core/plugins/store` 与登录即可见的菜单项
  （仅 `enabled` 时出现）。页面按四类分区展示名称/版本/来源/更新时间/兼容性/说明与警示，
  顶部状态提示条区分已更新/目录未更新/离线/校验失败；无任何安装按钮或写操作。

## Skiff-server P2：从商店目录安装插件

按 [docs/SKIFF_SERVER.md](../SKIFF_SERVER.md) §12 补上「插件」从已验证目录直接安装的链路：
下载 → 摘要/大小 → `.wbpkg` 验签 → 权限确认 → 既有 `install_package`。应用模板与运行环境
仍只展示；不改 `plugins/`，不改既有安装与 TOFU 信任口径；默认关闭，未配置固定公钥时不提供入口。

### 安装命令

- `crates/app/src/catalog/mod.rs`：内存快照同时保留已验证索引与命中镜像；新增
  `plugin_package`（按 id/版本查条目、带撤回原因）与 `download_blob`（校验条目三件套与
  URL 摘要一致、按 `blobs/sha256/<sha>` 下载、大小与 sha256 双重校验、`.part` 原子 rename
  落 0600，失败清理 `.part` 与目标文件）。
- `crates/app/src/catalog/fetch.rs`：`Transport` 增加 `get_blob`（二进制上限 128MiB，目录
  JSON 仍 8MiB），ureq 实现与假传输层默认行为一致。
- 新增 `crates/app/src/commands/store.rs`：`prepare` 依次做启用/公钥检查、目录条目查找、
  撤回检查、兼容性预检（内核 API 主版本一致且次版本不高于 `KERNEL_API`、`requires` ⊆
  `Capability::available_in(form)`、低于已装版本拒绝）、下载、`resolve_trust` 验签，成功后
  返回确认页所需的 `token` / 暂存路径 / 信任判定。失败按 `download` / `digest` / `signature` /

### 页面与审计

## Skiff-server 客户端三项修复：拒绝审计、换钥作废缓存、暂存包 TTL

测试机实测发现的三条目录相关问题，逐项独立提交；不改协议校验（`https` 与 webpki 根），
不改既有安装信任口径。

### 目录刷新拒绝落审计

- `crates/app/src/catalog/mod.rs`：拒绝原因收敛为 `RejectKind::{signature,seq,digest}`；
  `CatalogService` 经 `OnceLock<Arc<Db>>` 注入审计出口（`AppState::new` 装配），验签 /
  `seq` 回退 / 摘要失败记 `catalog.refresh`（`result = fail`，`detail` 前缀
  `reason=<code> `），全部镜像不可用记 `reason=offline`。审计写失败只 `tracing::error!`，
  不改变拒绝语义，也不影响旧快照展示与离线回退。

### 换 `catalog.public_key` 后作废旧缓存

- `crates/app/src/catalog/store.rs`：`CacheMeta` 增加 `key_id: Option<String>`
  （`#[serde(default)]`，= 写入时的公钥 sha256）。
- `crates/app/src/catalog/mod.rs`：载入缓存改走 `cached_for_current_key`，指纹与当前配置
  不一致即丢弃（`info!` 留痕），等价于「没有缓存」：新清单生效前不展示旧条目、不允许凭
  旧条目安装（`plugin_package` 不命中），条件请求头为空从而忽略 ETag 强制重拉。

### `.incoming` 暂存包 24h TTL

- `crates/app/src/commands/store.rs`：新增 `INCOMING_TTL` 与 `cleanup_stale_incoming`，
  只删 `.incoming` 下超期的 `.wbpkg` / `.part`，读不到 mtime 或 mtime 在未来时保守跳过，
  单文件删除失败 `warn!` 留痕；`prepare` 入口每次扫一次。
- `crates/core/src/bootstrap.rs`：启动时（`clean_run_dirs` 之后）扫一次。

### 测试

- `catalog/tests.rs`：四类拒绝/离线断言 `catalog.refresh` 审计落库；换钥 → 旧缓存作废 →
  manifest/index 请求均无 ETag；换钥且离线 → 无条目且 `plugin_package` 返回 `None`（共 43 项）。
- `commands/store.rs`：23h 不删 / 25h 只删暂存物、`prepare` 前清掉 25h 遗留且不误删刚下载的包
  （共 11 项）；`bootstrap.rs`：启动清 25h 遗留、保留未过期暂存（共 9 项）。
