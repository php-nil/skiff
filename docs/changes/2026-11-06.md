  调度语义不落列（`schedule / payload / retry / buffer / last_run` 整体 JSON），
  状态变化并入审计，不建 `task_state_changes`。
- `crates/app/src/tasks.rs` 落地 `TaskStore` 的 SQLite 适配、`TaskService` 与 1s tick：
  锁内只出票与结算，执行体 `tokio::spawn` 锁外执行，超时后晚到 `finish` 按 `run_id` 丢弃。
  适配器放 `app` 而非 `core`：`core` 无 lib，Web 与插件都经 `AppState` 取服务。
- 内置执行体：`site-backup`（`tar` 到 `data_dir/backups/sites/<domain>`）、
  `db-vacuum`（`Db::backup_to`）；`builtin:db-vacuum` 以 `0 4 * * 0` 种入。
- 插件门：未安装 / 禁用 / API 不匹配只记 `task.blocked`，不产生失败运行；
  执行期 `BusyGuard` 阻止该插件回调 `scheduler`（403）。
- 能力面 `/api/v1/capability/scheduler/call`（SDK `scheduler_call`）：插件只能看 / 管
  `plugin:<self>:*`，每插件 ≤20 条；新增 `scheduler:admin` 供内核指定 UI 跨来源管理。
  `buffer.push / buffer.stat` 仍未开放。

## 运行环境扩展安装修复

- 镜像内置扩展（`opcache` / `curl`）不再执行 `docker-php-ext-enable/disable`：
  PHP 8.5 镜像里 `opcache` 无独立 `.so`，脚本必失败（实测 `'opcache' does not exist`），
  新建 PHP 环境因此整单失败。启用/停用两处循环都按 `builtin` 跳过并写入任务日志。
- Redis 的 PECL 安装改为 `yes '' | pecl install redis`：pecl 会就 igbinary / lzf / zstd
  等编译选项逐个提问，面板 `docker exec` 带 PTY 无人应答会永久阻塞（实测挂起 20 分钟以上）。
  空行取默认值，pecl 退出后 `yes` 收到 SIGPIPE 自然结束。
- 停用扩展改为删除 `/usr/local/etc/php/conf.d/docker-php-ext-<key>.ini`：官方镜像只带
  `docker-php-ext-enable`，没有 `docker-php-ext-disable`（实测 exit 127 `not found`），
  取消勾选 Redis 必失败。
- vhost 的 `include fastcgi_params` 改为容器内绝对路径：主配置候选校验用
  `nginx -t -c /www/nginx/nginx.conf.candidate`，此时配置目录变成 `/www/nginx`，
  相对 include 解析到不存在的 `/www/nginx/fastcgi_params`，**任何合法修改都会被误判失败**
  （实测：未改动的配置复制成候选即报 No such file）。
- 回归：`builtin_extensions_are_flagged`（内置标记）、`pecl_extensions_feed_stdin`
  （pecl 必须重定向 stdin）、`disable_scripts_remove_ini_files`（停用走 ini 删除），
  以及 `php_vhost_points_fastcgi_at_runtime_socket` 增加绝对 include 断言。

## 运行环境：版本元数据、Rust 与扩展矩阵

### 版本显示（镜像元数据 + image_id 缓存）

- `ContainerRow` 增加 `image_id`；`skiff-docker` 增加 `inspect_image` / `ImageInfo{env,repo_digests}`。
  列表以 image_id 为 key 查进程内缓存，未命中只对该镜像 inspect 一次读 `PHP_VERSION`（Node/Go
  同理，Rust 无稳定 env 回退目标并标注）；正缓存无 TTL，失败 60 秒负缓存。
- 删除列表/详情渲染路径的 `exec_capture` / `pending_versions` 循环；停止但容器仍存在时仍显示
  镜像真实版本；容器缺失显示「未安装」，元数据读不到显示「版本未读取」。
- 抽屉保留唯一主动 exec：「实测版本」按钮（2 秒超时，显示结果与时间戳）。
- 安装/重建拉镜像后从 `ImageInspect.repo_digests` 落库 `site_runtimes.image_digest`；默认仍按 tag。

### Rust 运行环境（P1）

- `runtime_catalog` 增加 Rust（1.83/1.82/1.80，`rust:<ver>-slim`）；端口区间 9100–9199，创建时分配
  最小未占用端口并落库（schema v11 `site_runtimes.port`）。
- 容器 `skiff-rust-<name>` 使用 host 网络，容器内 `cargo run --release`，日志写
  `/www/runtime/rust/<name>/log/server.log`；安装任务写最小 std HTTP 工程并等待端口监听。
- 站点绑定 Rust 环境时 vhost 生成 `proxy_pass http://127.0.0.1:<port>`；抽屉「站点」页签可解绑。

### 日志按需加载

- 初始 `tab=logs` 只渲染「选择日志 → 选择范围」空态，服务端在 `load` 缺失时
  不打开任何日志文件；点「加载」后按查询参数读取。
- 参数：`type=access|error`、`lines`（后端夹取 50–500，默认 200）、`q` 关键字、
  `status`（`404` / `4xx`，仅访问日志）、`level`（错误日志级别）、`offset`（加载更多）。
- 后端 `seek` 到文件尾反向读取，单次最多 2 MiB；截断点落在行中间时丢弃残行，
  不整文件读入内存再过滤。访问日志读取全局 + 各站点日志（按 mtime 从新到旧，
  共享 2 MiB 预算）；错误日志读取 `nginx-error.log`。
- 页面显示本次加载行数、偏移、扫描尾部字节/行数、文件总大小与「文件更大，
  仅扫描尾部 2 MiB」提示；`has_more` 时提供「加载更多（更早 N 行）」。
- 状态码分布只对当前已加载行统计，并在页面注明「不代表全量」。

## 调度器 buffer 能力面与 image_digest 保留

- `TaskService` 新增 `buffer.push` / `buffer.stat` 能力：`buffer.push` 需 `scheduler:manage`，
  `buffer.stat` 需 `scheduler:read`，均只允许操作 `source = plugin:<self>` 的任务；
  `buffer.push` 另加每任务 100 点/秒滚动窗口限速（契约 §10.2）。
- 返回体：`push` 输出 `outcome`（accepted/seq/bytes/dropped/aggregated 或 rejected/reason）、
  `signals` 与 `net_bytes`；`stat` 输出 scheduler 的 `BufferStat`。
- 回归：`buffer_push_and_stat_are_exposed_to_the_owning_plugin`、
  `buffer_push_rate_limit_is_per_task_and_per_second`。
- `Db::ensure_runtime` 更新路径补写 `image_digest`，且空 digest 视为「未探测」保留旧值，
  避免每次启动校准把安装时探测到的 digest 清零；回归
  `ensure_runtime_writes_digest_but_never_clears_it_with_a_blank_probe`。重建仍按 tag 拉取，
  已记入 `docs/TEST_LEDGER.md`。
