# SDUI 内核适配手册（JSON Schema 驱动的服务端 UI）

> 状态：**设计稿，未实施**（2026-11-09）。本文只描述目标、契约与推进方式，不代表当前代码已具备这些能力。
> 前置：SDUI 框架由外部提供，其组件集、事件模型与布局能力尚未确定（见 §6）。
> 关系：视觉与交互基准见 [UI_CONTRACT.md](UI_CONTRACT.md)，插件页路由与 iframe 边界见 [PLUGIN_UI_CONTRACT.md](PLUGIN_UI_CONTRACT.md)，菜单声明模型见 [MENU_CONTRACT.md](MENU_CONTRACT.md)，分层红线见 [AGENTS.md](../AGENTS.md) §3.1 与 [03-architecture.md](sections/03-architecture.md) §3.1。本文不重复上述结论，只回答「内核要交出什么、保留什么、怎么迁」。

## 0. 一页结论

| 判断 | 结论 |
|---|---|
| 内核的长期职责 | **领域服务 + 资源描述 + 动作契约 + 权限/校验/审计 + 异步任务**；不承担布局、组件、交互状态 |
| 页面是什么 | **资源引用的组合**：页面描述由表现层拼装，内核只提供「有哪些资源、字段是什么、能做什么动作」 |
| 当前最大阻碍 | handler 把「解析 → 鉴权 → 业务 → 审计 → 渲染」写在一个函数里；视图模型携带 CSS 类名与中文文案；动作结果经重定向与内存 flash 传递 |
| 最先做的事 | 稳定错误码、统一 DTO、动作注册表、权限元数据、分页/筛选契约、作业进度模型（均不依赖 SDUI 框架） |
| 明确不做 | 为旧模板做二次抽象；在 schema 里放布局/颜色/组件；让业务层出现 page/flash/tab/modal 等词汇 |
| 迁移策略 | 新增并行端点、按页切换、最后删除模板与展示依赖；每阶段可独立回滚 |

### 1.3 内核必须保留 / 应被 SDUI 接走

| 必须保留在内核 | 理由 | 应接走 | 理由 |
|---|---|---|---|
| 授权矩阵与对象解析 | 唯一来源在 `skiff_model::Permission` 与 `policy`；UI 只能消费结论 | 布局与组件选择 | 属于表现层能力，框架提供 |
| 领域校验与不变量 | 与存储/宿主副作用同生共死，不可由前端保证 | 表单控件与客户端校验提示 | 控件行为与视觉由框架决定 |
| 状态迁移、幂等、超时、取消 | 与 Docker/nginx/调度器副作用绑定 | 分页控件、筛选控件、排序控件 | 内核只声明查询语义 |
| 审计事实与危险动作标记 | 合规与追溯要求；`dangerous` 由内核声明 | 提示条、确认弹窗、抽屉 | 交互形态属框架 |
| 异步作业、进度与日志游标 | 事实源在 `jobs` 表与内存缓冲 | 页面文案排版与多语言呈现 | 文案可用 key 由前端决定落点 |
| 稳定错误码与错误类别 | 客户端分支依赖它，不能靠 HTTP 状态猜 | 重定向、PRG、flash 语义 | 是旧 UI 的结果传递方式 |
| 资源字段语义（类型、单位、只读、敏感、引用） | 决定数据能否被正确理解与授权 | 局部刷新片段与 htmx 分支 | 是旧渲染技术的实现细节 |
| 流式通道（SSE/WS/上传下载） | 与长连接、票据、超时层强绑定 | 主题、CSS、静态资产 | 表现层资产 |

### 1.4 耦合的根因

1. **五合一 handler**：解析表单、CSRF、授权、调用领域、写审计、拼响应都在同一函数。站点、运行时、Docker、文件四组写路径已拆为「解析 → 命令 → 响应」，读 handler 与插件/任务/作业仍是多职责一体。
2. **视图模型带表现语义**：`state_class`（`ok`/`warn`/`danger`）、`state_label`（中文）、格式化后的字符串进入视图结构；同类数据在 `app` 与 `web` 各写一遍（如运行环境的两种视图）。
3. **表单字段名即接口**：字段名散落在模板与 handler，改名等于破坏契约；没有字段类型、必填、范围的可机读描述。
4. **三套错误出口**：`AppError` 渲染 HTML 错误页，`ApiError` 输出 `{code,message}`，写操作错误又走 flash 文案；没有稳定机器码，也没有字段定位。
5. **结果经重定向传递**：写操作不返回结果本体，而是「写会话 flash + 303」，客户端拿不到结构化结果，无法做局部更新。
6. **列表重取写在写 handler 里**：如镜像删除成功后递归调用列表 handler 重新渲染整页，读与写路径缠在一起。
7. **查询参数各自为政**：`?filter=`、`?q=`、`?tab=` 由各页自行解释，审计固定取 200 条、作业固定取 limit，没有统一分页模型。
8. **导航与授权混写**：菜单既要读 manifest 声明、按角色过滤，又要排序、落库偏好、生成渲染模型；前两者属内核，后两者属表现层。逻辑已迁到 `app/menu.rs`，混写事实仍在。

## 2. 目标分层

### 2.1 五层与依赖方向

依赖只向下，越往下越稳定：

| 层 | 职责 | 不做什么 | 归属 |
|---|---|---|---|
| 表现运行时 | 布局、组件、交互状态、主题、表单控件 | 不判定权限、不写业务状态 | SDUI 框架（外部） |
| 传输适配 | HTTP 形状、会话/CSRF、状态码、SSE/WS、上传下载 | 不解释业务语义 | 内核（薄） |
| 资源与动作契约 | 资源 schema、动作注册表、查询语义、错误码 | 不描述布局与组件 | 内核 |
| 领域服务 | 不变量、状态迁移、幂等、事务、审计事件、作业 | 不感知 HTTP、表单、页面 | 内核（现 `skiff-app` 与下层 crate） |
| 基础设施 | store / docker / identity / fs / sched / plugin | — | 现有 crate |

### 2.2 内核职责边界

一个请求在目标形态下的固定顺序：**传输校验（会话、CSRF、形状）→ 策略判定 → 领域校验 → 执行 → 审计 → 返回结构化结果**。任何一步都不产生 HTML，也不读取页面上下文。

内核保留：资源字段语义、动作清单、权限与 scope、校验与不变量、审计事实、作业与进度、错误码、流式通道。
内核放弃：视图模型、格式化字符串、状态到样式的映射、重定向、flash、模板、页面级查询参数解释。

### 2.3 资源描述（JSON Schema）

一个资源 = **稳定 id** + **读模型 schema** + **动作清单**。schema 只描述「字段是什么」，不描述「放在哪、长什么样」。

约定：

- 字段名是契约，发布后只增不改；改名视为破坏性变更，需升版本并存。
- 字段可带语义提示：类型、枚举、单位、格式、只读、敏感、引用（指向另一资源）、排序与筛选能力。禁止出现布局、颜色、组件、栅格、宽度一类提示。
- 展示文案不进入 schema 正文，最多给稳定 key；默认中文可由前端兜底。
- 派生字段（如 `short_id`、`elapsed`）由内核给原始值，格式化交给前端。

一行示意，仅表达形状而非最终字段：

```json
{ "resource": "job", "version": 1, "fields": [ { "name": "status", "type": "enum", "readonly": true } ], "actions": [ "job.cancel", "job.retry" ] }
```

### 2.4 动作契约

动作是**业务命令的唯一边界**，不是页面操作的回调。

- 标识：`<resource>.<verb>`，全局唯一且稳定；动作 id 同时作为审计 `action` 的来源（映射表单一维护）。
- 输入：参数 schema（类型、必填、范围、枚举）。传输层可用表单或 JSON 承载，但语义相同。
- 元数据：所需权限、所需 scope、是否危险、是否幂等、超时、是否异步（返回作业）、成功后是否使资源失效。
- 输出：成功返回结果数据或作业引用；失败返回错误对象。**动作永不返回页面、重定向或提示文案。**
- 一次动作对应一个事务性命令；命令内部完成策略、语义校验、执行与审计（顺序见 §2.6），handler 只做形状转换。
- 危险动作的二次确认是表现层行为，内核只声明 `dangerous` 与可逆性。

### 2.5 查询契约

- 列表：显式声明可筛选字段、可排序字段、默认排序、`limit` 与游标；返回 `items`、`next_cursor`（或 `has_more`），总数按需给出。
- 详情：资源 id + 主键，返回同一套字段语义。
- 禁止把任意表达式、SQL 片段或字段路径透传给存储层。
- 现有查询能力需补齐：审计与作业只有 `limit`，站点与容器为全量，文件目录浏览无分页模型。统一为「游标 + 上限」，逐页替换。

### 2.6 权限、校验、审计的挂接点

| 挂接点 | 位置 | 规则 |
|---|---|---|
| 资源读 | 资源的读声明 | 取 `Permission`；API token 另受 scope 收窄 |
| 动作执行 | 动作元数据 | 先策略后参数语义；未授权不泄露参数级反馈 |
| 字段敏感 | schema 标记 | 由内核裁剪或拒绝，不能依赖前端隐藏 |
| 校验 | 命令内部 | 形状校验在传输层，语义与不变量在领域，判定顺序固定 |
| 审计 | 命令内部 | 成功/失败都留痕；不由 handler 代写，也不因渲染失败而丢 |

原则：**权限与审计只随命令走**。同一动作被旧页面、新 SDUI、`/api/v1` 或插件调用时，结论必须一致。

### 2.7 异步任务与进度

- 长动作返回作业引用，而不是阻塞到完成；短动作直接返回结果。
- 作业状态固定为「排队 / 执行中 / 成功 / 失败 / 已取消」，阶段名与进度单位由资源声明（百分比、字节、步数）。
- 日志按游标增量获取（现有 `logs_since` 已具备），传输层自行选择 SSE 或轮询；内核不规定刷新方式。
- 取消是请求而非保证；最终状态由领域决定。重试沿用现有作业语义。

### 2.8 错误模型

错误对象固定包含：稳定机器码、人读信息、可选字段定位、是否可重试、可选细节。HTTP 状态码只表达传输语义，客户端分支一律看机器码。

- 机器码形如 `site.domain_invalid`，一经发布不复用、不改语义。
- 现有 `AppError` 变体保留为「类别」，类别到机器码的映射表是唯一来源。
- 旧 UI 的 flash 文案与表单字段高亮转为：错误对象 + `field`，由表现层决定呈现。

### 2.9 页面如何由 schema 描述

页面 = **菜单项 + 资源引用 + 动作引用 + 表现层布局**。

- 内核提供：资源目录、字段 schema、当前主体可见的动作集合、菜单声明与授权过滤结果。
- 表现层提供：布局、页签、弹窗、表格列选择、空态、确认流程。
- 禁止让内核生成「页面描述」再交给前端渲染布局，否则布局概念会回流到内核。若框架要求整页描述，由适配层按资源引用拼装，内核不参与。

### 2.10 词汇纪律

| 业务与契约层禁止 | 允许 |
|---|---|
| page、template、redirect、flash、button、tab、modal、toast、badge、column、layout、css | resource、field、action、permission、scope、job、cursor、error code、invalidated |

评审时以「业务层是否出现上表左列词汇」作为一条硬检查。

## 3. 迁移路径

### 3.1 原则

1. 新端点并行，旧页面不动，直到对应页切换完成。
2. 每阶段独立可验收、可回滚；回滚不依赖数据回滚。
3. 命令层是唯一业务入口，旧 handler 与新适配层都调它。
4. 不为了迁移做「通用页面抽象」；抽象只发生在资源与动作这一层。

### 3.2 阶段

| 阶段 | 内容 | 入口条件 | 验收标准 | 回滚方式 |
|---|---|---|---|---|
| P0 契约骨架 | 稳定错误码映射、动作 id 命名规范、DTO 收口原则 | 现有 CI 绿；不改业务行为 | 旧页面行为零变化；错误码表有单测；新端点契约测试通过 | 纯新增，删除新模块即回滚 |
| P1 命令与 DTO | 写 handler 拆为「解析 → 调命令 → 映射响应」；视图格式化下沉 | P0 完成 | 命令层单测覆盖权限、校验、审计；旧页面回归通过 | 旧 handler 路径保留，命令层新增 |
| P2 资源与动作描述 | 选取低风险资源生成 schema 与动作元数据，提供只读目录端点 | P1 完成；字段命名冻结 | schema 快照测试；动作权限与 `Permission` 矩阵一致性表驱动测试 | 端点独立，不接 UI |
| P3 新旧并行 | SDUI 接 1–2 个只读页，走同一命令层 | P2 完成；框架可运行 | 字段、动作、错误、权限逐项对比一致；越权动作后端仍拒绝 | 页面级开关回旧路由 |
| P4 逐页切换 | 按 §3.3 顺序迁移，每页独立验收 | 该页 P3 对比通过 | 功能等价、权限一致、审计一致、错误可读；流式能力不退化 | 单页开关 |
| P5 删除旧展示 | 移除模板、askama、htmx、页面级脚本与菜单渲染 | 全部内核页切换完成 | 依赖树无模板引擎；路由表无 HTML 页面；体积与内存变化**实测后**再声明 | 回退到发布 tag |

### 3.4 回滚协议

- 开关粒度到页面：同一资源可同时存在旧 HTML 路由与新 SDUI 路由。
- 回滚只切路由，不回滚数据；schema 版本只增不减。
- 命令层一旦被两种 UI 共用，修复必须落在命令层，禁止只改一侧。

## 4. 立即可以做的优化

全部与 SDUI 方向一致，且不要求框架到位；按「不做会阻塞迁移」排序。这些改动本身不删除旧 UI。

| 优化 | 优先级 | 影响面 | 与 SDUI 的关系 | 备注 |
|---|---|---|---|---|
| 结构化错误对象与机器码映射 | 高 | 全部 handler | 客户端分支、字段定位 | 保留 `AppError` 类别，新增映射表；旧错误页继续可用 |
| DTO 收口：领域返回原始值，格式化与样式下沉 | 高 | `app` 视图与 `web` 视图 | 字段语义与 schema | 先新增无样式 DTO，旧视图适配它，逐页替换 |
| 动作注册表雏形 | 高 | 全部写路径 | 动作契约与审计映射 | 动作 id、权限、审计 action 三列一张表 |
| 读写路径拆分：写动作不再重取整页 | 中 | 镜像/网络/卷/容器 | 动作返回结果 | 写命令返回结果，列表由读端点单独提供 |
| 分页与筛选契约 | 中 | 审计、作业、任务、站点、容器 | 查询契约 | 统一 `limit` + 游标；先落审计与作业 |
| 长任务进度模型 | 中 | 作业、运行环境安装、插件安装 | 异步动作 | 补状态、阶段、进度单位与日志游标声明 |
| 权限元数据随动作声明 | 中 | RBAC 与 API scope | 可见动作集合 | 与 `Permission` 矩阵一致性由测试守护 |
| 字段级错误定位 | 低 | 网站、设置 | 校验反馈 | 用错误对象 `field` 替代「错误文案到表单字段」的映射函数 |
| flash 降级为旧 UI 专用 | 低 | 全部写 handler | 结果传递 | 新端点直接返回结果，不写会话提示 |
| 菜单声明与渲染分离 | 低 | `menu.rs` | 导航 schema | 声明、授权过滤留内核；排序、偏好、渲染归表现层 |

判断口径：高 = 不做就无法定义资源与动作；中 = 能立即做且能减少后续返工；低 = 需要前序完成或等框架能力确认。

## 5. 手册

### 5.1 新增一个资源页

1. **定资源**：给出稳定资源 id，写明它是读模型还是可写资源，主键是什么。
2. **定字段**：逐字段声明名称、类型、只读、敏感、单位、枚举、引用；派生值只给原始值。
3. **定查询**：可筛选字段、可排序字段、默认排序、分页方式与上限。
4. **定动作**：列出动作 id，逐个写权限、scope、危险标记、幂等性、是否异步、超时。
5. **写命令**：一个动作一个命令函数，内部按「权限 → 语义校验 → 执行 → 审计」顺序，返回结果或作业引用。
6. **注册**：把资源与动作登记到注册表，补契约测试与权限矩阵测试。
7. **接适配**：旧表单或 JSON 只做形状转换，不复制校验与判定。
8. **验收**：权限拒绝路径、错误码、审计事实、分页边界、危险动作后端强制校验。

### 5.2 命名与版本

| 对象 | 约定 | 示例 |
|---|---|---|
| 资源 id | 小写单数、下划线、领域前缀 | `site`、`site_runtime`、`container`、`job`、`audit` |
| 字段 | 小写下划线；禁止 UI 词汇 | `domain`、`memory_limit_mb`、`created_at` |
| 动作 | `<resource>.<verb>`；动词取领域语义 | `container.restart`、`job.cancel`、`site.delete` |
| 错误码 | `<resource>.<reason>` | `site.domain_invalid`、`job.not_cancellable` |
| 版本 | 资源级整数，放在载荷里而非 URL | `version: 1` |

版本规则：同版本只允许加可选字段、加动作、加错误码；删字段、改类型、改语义必须升版本并短期并存。动作 id 与错误码一经发布不复用。

### 5.3 动作与权限声明

- 权限取值只能来自 `skiff_model::Permission`，不新增旁路判定；对象级解析在命令内部完成。
- scope 只用于 API token 收窄，不替代角色权限。
- 声明项固定为：权限、scope、危险、可逆、幂等键、异步、超时、成功后失效的资源。
- 审计 `action` 由动作 id 派生，禁止在 handler 手写另一套名字。
- 前端隐藏按钮不构成保护；后端必须独立拒绝。

### 5.4 校验放在哪

| 层 | 校验内容 | 失败形态 | 顺序 |
|---|---|---|---|
| 传输 | 形状、必填、类型、大小、编码 | `invalid_shape`（400） | 1 |
| 权限 | 角色、scope、目标对象可否解析 | `forbidden` / `not_found`（403 / 404） | 2 |
| 领域 | 不变量、状态机、命名规则、配额 | `domain_*`（400 / 409 / 507） | 3 |
| 执行 | 下游失败、超时、取消 | `unavailable` / `timeout` / `cancelled` | 4 |

顺序遵循现有约定：**未授权者不获得参数级反馈**，因此语义校验在权限判定之后；形状解析只做「能不能读成参数」，不泄露业务规则。

### 5.5 测试

| 类型 | 覆盖点 | 判定 |
|---|---|---|
| schema 快照 | 字段名、类型、只读、动作清单 | 变更必须显式更新快照 |
| 动作 × 角色 | 每个动作在每个角色下的允许/拒绝 | 表驱动，与 `Permission` 矩阵同源 |
| 错误码 | 每个码有唯一产生点与 HTTP 映射 | 不允许未注册码 |
| 命令 | 成功、失败、审计、幂等、并发 | 不依赖 HTTP |
| 新旧对比 | 同一命令经旧页面与新端点结果一致 | 迁移期每页必跑 |
| 契约端点 | JSON 形状、分页边界、未知字段容忍 | 不测布局与样式 |

回归矩阵的编号与执行方式沿用 [TEST_MATRIX.md](TEST_MATRIX.md)，本文只补充 SDUI 新增项，不复制其条目。

### 5.6 常见反模式

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 命令里渲染页面或重定向 | 业务被传输形态绑架 | 命令返回数据，适配层决定响应 |
| 视图模型携带 CSS 类名或中文状态 | 换 UI 必须改业务 | 返回枚举与原始值 |
| 把错误映射到表单字段名 | 错误语义被表单结构绑死 | 错误对象给 `field`，由表现层映射 |
| 用 flash 传递动作结果 | 客户端拿不到结构化结果 | 直接返回结果或作业引用 |
| 写 handler 成功后重取整页 | 读写耦合、重复查询 | 写返回结果，读端点单独取 |
| schema 里放布局、宽度、颜色 | 布局概念回流内核 | 只描述字段语义 |
| 每个页面各写一套 DTO | 同一资源多份字段、口径漂移 | 一个资源一套字段定义 |
| 权限判断写在模板或前端 | 越权面 | 后端判定，前端只消费可见动作 |
| 用 HTTP 状态区分业务分支 | 语义无法扩展 | 稳定机器码 |
| 透传下游原始结构 | 字段不稳定、泄露内部细节 | 显式字段白名单 |

## 6. 风险与待定

### 6.1 依赖框架的能力

具体框架（budding）的产物、JSON 契约与能力缺口见 [SDUI_BUDDING_INTEGRATION.md](SDUI_BUDDING_INTEGRATION.md)；本文只保留框架无关结论。

| 框架能力 | 影响的设计 | 现在能否先做 |
|---|---|---|
| 组件集（表格/表单/详情/图表/终端） | 字段类型覆盖面 | 能：先定字段语义，后补映射 |
| 事件模型（动作调用、刷新、导航） | 动作契约的调用方式 | 能：先定动作 id 与输入输出 |
| 布局能力（菜单、页签、弹窗、抽屉、响应式） | 页面组合方式 | 不能：内核不产出布局 |
| 数据获取（轮询、SSE、局部刷新） | 作业进度与日志呈现 | 能：先给游标与增量接口 |
| 字段级校验反馈 | 错误 `field` 的呈现 | 能：先给 `field` |
| 权限感知（按钮显隐） | 可见动作集合 | 能：先给动作清单与权限结论 |
| 国际化与文案 | 文案归属 | 能：先定 key 策略 |
| 文件上传/下载与流式 | 文件管理页迁移 | 能：暂保留独立前端 |
| 主题与字体 | 无 | 不涉及内核 |

### 6.2 可先行与必须等

- **可先行**：领域命令、DTO、错误码、动作注册表、权限元数据、查询契约、作业进度、schema 生成与契约测试。
- **必须等**：页面布局与组件映射、交互状态、客户端校验提示、文件管理的流式交互。

### 6.3 需要定夺的取舍

| 议题 | 选项 | 建议 |
|---|---|---|
| schema 来源 | 手写 JSON；从 Rust 类型派生后补语义 | 派生字段表 + 手工补语义提示，减少双写；用一致性测试防漂移 |
| 端点命名空间 | 复用 `/api/v1`；新开 `/api/sdui` | 新开命名空间，避免既有自动化契约随 UI 需求漂移 |
| 认证方式 | 复用会话 Cookie + CSRF；新增 Bearer | 复用会话与 CSRF，同源调用，不扩大令牌面 |
| 插件 UI | 继续 iframe；纳入 SDUI | 继续 iframe（见 [PLUGIN_UI_CONTRACT.md](PLUGIN_UI_CONTRACT.md)），SDUI 先只覆盖内核页 |
| 文案归属 | 内核出中文；内核出 key + 前端兜底 | 出 key，默认中文由前端或兜底表提供 |
| 文件管理 | 用 SDUI 重建；保留独立前端 | 暂保留独立前端，等框架支持流式与分片再评估 |
| 旧 UI 周期 | 长期双栈；逐页切换后删除 | 逐页切换，等全部完成即删，不接受长期双栈 |
| 分页模型 | 游标；偏移量 | 统一游标；仅当框架要求页码跳转时对稳定小表例外 |
| schema 版本位置 | URL 路径；载荷内 | 载荷内资源级版本，URL 只承载资源 id |
| 菜单归属 | 作为可写资源；作为声明端点 | 作为声明端点，偏好由设置动作保存，不引入菜单动作面 |

### 6.4 主要风险

| 风险 | 触发条件 | 缓解 |
|---|---|---|
| 框架要求整页描述 | 框架只接受完整页面 JSON | 适配层按资源引用拼装，内核不产出布局 |
| schema 变成页面配置 | 为省事把列宽、顺序写进 schema | 词汇纪律 + 评审硬检查 |
| 双栈长期共存 | 迁移停滞，两套 UI 同时维护 | 页面开关带截止条件，完成即删旧路径 |
| 流式能力退化 | 新框架不支持 SSE/WS | 终端、日志、上传下载保留内核通道，不接入页面描述 |
| 权限与 UI 不一致 | 前端自行判断可见性 | 可见动作集合由内核计算，测试对比 |
| 字段语义漂移 | 每个页面各写 DTO | 一个资源一套字段定义，快照测试 |
| 迁移期审计缺口 | 命令层与 handler 各写一次审计 | 审计只在命令层，旧 handler 删除自写审计 |
