## 第三轮：代码优化（最小改动 / 可验证 / 有闭环）
- 基线先测：118 测试全绿、fmt 与 clippy `-D warnings` 干净（不是「已坏」状态，所以只做有依据的改动）。ARCH_REVIEW 新增 §11 逐项记录。
- **最有价值的一项不是性能而是缺陷**：`/plugins/install` 落在 axum 默认 2MB body 上限内，`.wbpkg` 内含二进制必然超；超限发生在 Multipart 解析阶段并被 `map_err` 包装成「上传解析失败」，handler 里 100MB 的 `archive_bytes` 判断永远走不到 → 大于 2MB 的插件包此前**根本装不上**。修法：该路由挂 `DefaultBodyLimit::max(archive_bytes + 64KB)`。
  - 教训：`DefaultBodyLimit` 默认 2MB 对 Multipart **也生效**（axum 0.8 `req.with_limited_body()`），应用层再写一道大小判断不等于真的能到那一行。

## Docker 前置：从「不提供」到「安装脚本补装」（本轮）

用户问「运行后是否提供 docker 安装、考虑网络用代理」。查完确认原来**完全没有**：只连 socket、缺了就降级，`install.sh` 连 `command -v docker` 都没有，也没有任何 registry-mirrors / proxy 配置。用户要求补上，但**不要塞进 Rust**（体积），放安装脚本，借助 LinuxMirrors。

- 新建 `deploy/docker-bootstrap.sh`（POSIX sh）：缺才装、已有可用 daemon 一律不动、Alpine 走 `apk`、其余走 LinuxMirrors `docker.sh`。
- 关键风险（实测 LinuxMirrors 源码确认）：`docker.sh` 的 `install_docker_engine` 一旦发现已有 docker，会 `systemctl disable --now docker` + `apt-get remove -y 'docker*'` 重装 CE。正跑容器的机器上是停机事故。所以脚本对「有二进制但 daemon 不起来」直接 exit 3 拒绝，只有 `--force-reinstall` 才走。
- 非交互卡死点：`docker.sh` 用 `[[ ]]`/数组（非 POSIX，需 bash）；`choose_mirrors` 只在 `SOURCE` 为空时交互；`change_docker_registry_mirror` 在 `SOURCE_REGISTRY` 为空时默认 `registry.hub.docker.com` 并**整文件重写** daemon.json。对策：显式传 `--source`/`--source-registry`、`--pure-mode --ignore-backup-tips`、`< /dev/null`。
- 加速器**不设默认值**（国内公共加速器多已停服），没给时脚本会写一个无意义的 `registry.hub.docker.com`，装完用 `drop_useless_registry` 只在「≤3 行且单条 registry-mirrors」时清掉，用户自维护的 daemon.json 不碰。
- 顺序坑：`DockerService` 只在进程启动时 connect 一次 → Docker 步骤必须排在 systemd 启动**之前**；单跑 `docker-bootstrap.sh` 时 `finish_ok` 会检测 `systemctl is-active skiff` 并提示重启。
- 顺带修掉一个真缺陷：`install.sh` 用 `for arg in "$@"` + `shift 2` 解析参数，POSIX 下 for 列表进循环前已固定，`sh install.sh --prefix /opt` 会把 `/opt` 当未知参数退出 2（已实测复现）。改成 `while [ $# -gt 0 ]`。
- 验证：`sh -n`、shellcheck `-S error` 干净（warning 只有 trap 里函数的 SC2317 误报）；mock docker 跑通 4 条分支（已就绪 exit 0 / daemon 挂 exit 3 / --force-reinstall exit 4 / 未知参数 1）。**Linux 上的真实安装路径未实测**，已记进 `12-pending-tests.md`。
- 改动文件：`deploy/docker-bootstrap.sh`（新）、`deploy/install.sh`、`deploy/pack-release.sh`、`docs/sections/05-deploy.md`（§5.1 五条）、`docs/DEPLOY_TEST.md`（A6 改前置 + A12–A20）、`docs/sections/12-pending-tests.md`、`.github/workflows/release.yml`（注释 + notes）。
- 补充：区分两种「代理」——`--registry-mirror`（改 registry 地址）与 `--daemon-proxy`（改 daemon 出网，写 `docker.service.d/10-skiff-http-proxy.conf`）。后者仅新装时自动写，已有 docker 只打印片段，避免重启 daemon 中断容器。

## Dependabot 分支污染（本轮，GitHub 侧）

现象：GitHub 分支切换器里冒出 8 条 `dependabot/cargo/*` 与 `dependabot/github_actions/*`。本地 `git branch -a` 只有 `main`——因为截图那个下拉列的是**远程**分支。

根因（实测确认，非推测）：`.github/dependabot.yml` 里 `groups.<name>.update-types: ["minor","patch"]` **只决定哪些更新能被并进分组 PR，并不阻止 Dependabot 给分组外的 major 各开一条独立分支**。8 条 PR 全是 major（hmac 0.12→0.13、sha1 0.10→0.11、sha2 0.10→0.11、axum-server 0.7→0.8、toml 0.8→1.1、checkout 4→7、upload-artifact 4→7、download-artifact 4→8），刚好 5 cargo + 3 actions，把 `open-pull-requests-limit` 吃满 → 一个 minor/patch 分组 PR 都没生成。配置文件注释写「刻意只开 minor/patch」，实际意图完全没生效。

处置：
- 删除 8 条远程分支（`git push origin --delete`，凭据在 `~/.git-credentials` 的 store helper）；远程现只剩 `main`，`state=open` 的 PR 数 = 0（删 head 分支会连带关闭 PR）。
- 分支 SHA 备份在 `.workbuddy/dependabot-branch-shas-2026-10-31.bak`，要恢复可 `git push origin <sha>:refs/heads/<branch>`。
- 配置修复：两个 ecosystem 都加 `ignore: [{dependency-name: "*", update-types: ["version-update:semver-major"]}]`。**这是让「只要 minor/patch」真正生效的唯一写法。**
- 顺手：`.gitignore` 加 `.workbuddy/`（此前未忽略，`git add -A` 会把 agent 记忆文件带进仓库）。
- 状态：改动**仅本地未提交**（`M .github/dependabot.yml`、`M .gitignore`；`M .github/workflows/ci.yml` 是本轮之前就有的脏改动，没碰）。不推送则下周一 Dependabot 仍按旧配置重开。
- 排查工具：本机无 `gh`，用 `curl https://api.github.com/repos/php-nil/skiff/pulls?state=all` + 本机 python3 解析即可（未认证配额够用）。注意 Windows python 不认 msys 的 `/tmp` 路径，临时文件要落在仓库相对路径。
