# 2026-10-30

## 项目启动：Rust 极简 Linux 面板（D:/panel）

- 需求：Rust 开发、极低内存/CPU、Docker 部署并兼容 1Panel 的 docker 模式、远程 HTTP 管理、功能靠扩展以保证内核稳定。
- 本轮只做需求评估 + 方案设计，未编码。产出 `docs/DESIGN.md`（约 400 行）。
- 核心决策：
  - 后端 axum + tokio（多线程 2 worker），存储 rusqlite(bundled) + TOML。
  - 前端 askama SSR + htmx + 懒加载 ESM（xterm.js/uPlot），**无 Node 构建链**，rust-embed 打包。
  - 扩展机制 = **进程外插件 + Unix Socket JSON-RPC 2.0**，按需启动/空闲 300s 回收/退避重启/熔断；否决 dlopen（崩溃连带）与 wasmtime（+20~50MB，与轻量冲突）。
  - 内核只保留 6 个原子能力：metrics / fs / proc / docker / shell / identity，其余全部插件化。
  - 三档部署：compose.bridge.yml（默认）/ compose.host.yml / 1Panel 应用商店包。
- 已核实的 1Panel 应用商店约定（社区上架说明 + 官方 appstore 仓库）：
  `networks: 1panel-network: {external: true}`、`container_name: ${CONTAINER_NAME}`、
  `labels: createdBy: "Apps"`、`${PANEL_APP_PORT_HTTP}` 且需在 data.yml formFields 有同名 envKey、
  持久化用相对路径 `./data/`。1Panel 默认端口 10086，安全入口 /entrance。
- 待用户确认的 4 个决策点：前端路线(htmx vs Preact)、默认部署档位(A/B)、是否引入 docker-socket-proxy、是否本期上 1Panel 商店。
- 未验证项（勿当事实引用）：所有内存/体积/CPU 目标值、1Panel 商店对镜像与自定义变量的校验行为、`docker.sock:ro` 对 API 写操作的实际限制。

## 三功能适配评估（同日）：文件管理器 / 网站管理 / 防火墙管理

- 评估口径：插件机制层 / 内核能力面 / 部署边界 三层分开判。结论——**机制装得下，边界装不下**；三功能的「Docker 瘦身版」在射程内，「主机版」全部撞单容器部署边界。
- 文件管理器：宿主版无解（无 fs 能力 + §5.4 不挂宿主目录）；容器版可做（白名单补 /containers/{id}/archive，即 docker cp 底层）。
- 网站管理：站点容器运维 = 设计内（示范插件就是它）；建站/LNMP/ACME = §1.4 明确不做（产品决策非机制限制）；web root 推荐 volume/全容器化路线；开站端口经 docker 发布可行（docker 自写 DNAT）。
- 防火墙管理：宿主 iptables/nftables 物理不可达（netns 隔离 + 无 NET_ADMIN + 参数策略禁 host 网络/privileged）；仅「容器端口/网络管理」可做；1Panel 形态下与 1Panel 防火墙重复建设存疑。**§1.4 两栏都没提防火墙，建议补声明**。
- **新发现缺口（未修，待拍板）**：§6 参数策略绑定挂载只校验不白名单——有 containers.create 权限的插件可挂 /:/host 逃逸，绕过 v0.8 降权与「不挂宿主目录」。需补：绑定挂载白名单（默认 ./data 子路径 + named volume）+ 超白名单用户确认。网站插件落地前必须修。

## 架构纠偏（同日）：插件应落宿主机，插件体系才算真核心

- 用户纠偏：**插件进程应放在宿主机上**，不是容器内。理由：docker 与插件体系是两个核心，前提是插件能力面超出 docker（fs/防火墙/站点等）——若插件只在容器内做 docker 动词，插件=docker 功能的延迟实现，产品塌缩为「只有 docker」。v0.8 文档现状（插件同容器）该改的是文档。
- 硬约束：容器内 Supervisor fork 不出宿主进程（nsenter 需 pid:host+SYS_ADMIN，v0.7 砍的增强包）。两条路线已提给用户拍板：
  - **A 全家 native**（推荐）：core+插件都 systemd 直装宿主，docker 只是被管资源；能力面扩 fs/net/proc，requires 本就预留多形态口；产品升格为「极简服务器面板」，1Panel 关系变同机共存；容器包降级可选分发。
  - **B 核容器 + skiff-hostd 宿主守护**：保 1Panel 商店 Docker 包，插件经 hostd 落宿主；代价是多一个 root 组件 + 共享 UDS 挂载 + init.sh 装宿主守护。
- 连带（拍板后改 DESIGN.md）：能力面 docker/identity → +fs/net；信任模型升压（宿主插件=root 等价，沙箱升 landlock/seccomp/cgroupsv2）；三功能评估翻案（A 下文件/网站/防火墙全进射程）；§1.4 范围声明重写。
