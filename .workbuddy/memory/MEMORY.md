# Skiff（轻舟）项目记忆

- 主文档：`docs/DESIGN.md`，当前 **v1.0（MVP 实施稿）**；**MVP 代码已落地**（13 个 crate + xtask，Windows 上 149 项测试全绿、fmt/clippy `-D warnings` 干净）。Linux 专属能力与资源数字仍未实测；GitHub CI 已配置但**尚未首次运行**。
- 架构审查：`docs/ARCH_REVIEW.md` 四轮（§1–9 初审，§10 二轮复审，§11 三轮代码优化，§12 四轮把 §11.2 遗留四项做完，均 2026-10-31）。第三轮修掉的真缺陷：**`/plugins/install` 受 axum 默认 2MB body 上限，>2MB 的 .wbpkg 根本装不上**（`map_err` 还会把它伪装成「上传解析失败」）。第四轮落地：exec 单连票据、API Token scope、按路由分组的请求超时、`AppState` 下沉 `skiff-app`。
- 文档结构（2026-10-30 起）：DESIGN.md 只保留一页结论 + 文档地图 + 文档约定 + 变更记录（索引三节不占正文编号）；正文在 `docs/sections/`，**文件名前缀号 = 章号**（01–12 共 13 个文件，§4 分 `04-plugin-package` / `04-plugin-publish` 两册）。章节号 `§x.y` 全局唯一、拆分不重编号；每篇顶部导航行同构（主文档/本文件/上一章/下一章）。
- 文档格式约定（踩过的坑）：表格单元格内禁止裸 `|`（`\|` 写在代码 span 里也会被拆列）；表格与代码块必须放顶层，不能缩进进列表项；列表项内不要写跨行代码 span；中文引号统一用“ ”。
- 产品边界：三核心 = Web 管理服务 / Docker 管理 / 插件体系。文件管理、防火墙、网站管理、主机监控等宿主功能不进内核，由插件层实现。
- 部署主形态：宿主机 systemd 直装；1Panel 商店 Docker 包是可选受限形态（能力面收缩为 docker/identity）。
- 2026-10-30 已按审查建议落地：插件包签名/哈希规范、Docker 三层控制、受限形态 bind 禁用、插件迁移恢复、独立 UID/GID、IPC 限额、postMessage 鉴权、HTTPS/可信反代、Compose MVP 子集、发布物验签。
- 关键约束：R1 Rust，但明确例外 SQLite、ring、zstd-sys，以及 POSIX sh 部署脚本；配置唯一路径 `/etc/skiff/config.toml`；插件 secret 不落启动环境/插件可写目录。
- 验收口味：所有数字和能力声明未实测前只能标“设计目标/待实测”；M5 才回填资源指标、共存、备份恢复和发布验签。
- 代码分层（2026-10-31 起）：`model`（零依赖词汇 Role/Grant/Form/Permission/Scope）→ `store`/`policy`/`pkgfmt` → `identity`/`wire` → `docker`/`plugin` → `app`（AppState/WebConfig）→ `web` → `core`(bin)。`app` 不含路由/模板；`core/kernel` 吃 `skiff_app::AppState`，**不再反向依赖 `skiff-web`**；`web` 用 `pub use skiff_app as state` 保留 `crate::state::*` 路径。**policy 与 pkgfmt/wire 禁止依赖 store/docker**，安全结论必须能脱离数据库与 Docker 单独验证。`cargo test -p skiff-policy` 是判定逻辑的唯一快速回归入口。
- 协议/存疑点：插件↔内核 UDS 协议只在 `skiff-wire`（路由常量 `routes::*`、帧编解码），两端不得再写字面量；TOFU 只在 `plugin::trust::resolve`；动词→Docker 分发只在 `Docker::execute`。
- 编辑坑：写代码时 `impl` 必须与类型同 crate（`impl Mount` 曾留在 docker 触发孤儿规则）；`std::sync::Mutex` 不可重入，`Db` 的方法内禁止持锁再调 `self.xxx()`。
- 权限模型（2026-10-31 定稿）：数据根与 `plugins/` **0711**（可穿越不可列），`data/cache/run` 0700 归插件 UID，`skiff.db`/backup 0600/0700；`/run/skiff` 0711 root:skiff-plugins，`kernel.sock` 0660 同组。插件主 gid 是自己的 uid，靠 `setgroups([skiff-plugins])`（必须在 setgid/setuid 前）拿组权限。**千万别把数据根改回 0700**——降权插件会全线 EACCES。
- 打包纪律：`.wbpkg` 只收 `bin/ ui/ migrations/` + manifest（`PAYLOAD_DIRS`）。整目录打包会把签名私钥和 `target/` 塞进分发包。
- Linux 目标类型检查（Windows 上唯一可行的子集）：`cargo check -p skiff-model -p skiff-policy -p skiff-wire --target x86_64-unknown-linux-gnu`（需 `RUSTUP_DIST_SERVER=https://rsproxy.cn` 装 std）；含 C 依赖的 crate 必须在真 Linux 上编。
- 看警告要用 `CARGO_INCREMENTAL=0`：MSYS 增量模式会刷「删除 lock 文件 拒绝访问」的假 warning。
- CI（2026-10-31 起，`docs/CI.md`）：三个工作流 = `ci.yml`（fmt / clippy `-D warnings` / test / msrv / xtask verify / 插件包真签真验 / shellcheck+LF / smoke / musl 静态构建）、`release.yml`（`v*` 标签 → `cross` 编 amd64+arm64 musl → `gh release create`）、`audit.yml`（周更）。**没有 continue-on-error**。
- CI 三条硬规矩：① 工具链锁在 workflow 顶部 `RUST_VERSION`（现 1.98.1），不跟 stable 浮动；② **MSRV = 1.89**（1.85 实测连依赖解析都过不去，rusqlite 0.41 要 1.89）；③ 每个跑 cargo 的 job 先 `rm -f .cargo/config.toml` 走 crates.io（仓库那份是国内镜像，只给开发机）。
- 发布：签名私钥走仓库 secret `RELEASE_SIGNING_KEY_HEX`，没配只 `::warning::` 不伪造已签名；产物是 musl 静态（不绑 glibc），打包统一走 `deploy/pack-release.sh`（支持 `CARGO=cross` 覆写）。
- 提交前本地对齐 CI：`cargo fmt --all`、`cargo clippy --workspace --all-targets --all-features --locked -- -D warnings`、`cargo test --workspace --locked`（现 149 项）。`.gitattributes` 已锁全仓 LF。
- 安全边界四条（2026-10-31 定稿）：① exec WS 必须带 `?ticket=`（30s、一次性、绑定 session+容器 id，内存只存 sha256；端点 `POST /{p}/containers/{id}/exec/ticket`，admin+CSRF+Exec 策略）；② API Token 权限 = 角色权限 ∩ scope（`docker:read`/`docker:write`/`plugins:read`/`*`，write 蕴含 read，未知名严格报错 401+审计；`token create --scope` 默认 `docker:read`）；③ 请求超时 30s 只挂非流式路由（`streaming` router 在 `.merge` 前不 layer，SSE/WS 因此排除），超时是 `AppError::Timeout`→504 错误页；④ 登录限流表与票据表都有上限，越界先回收过期再淘汰最旧。
- 测试坑：只断言状态码会骗人——`Multipart` 超限错误被 `map_err` 包成 400，和应用层校验的 400 撞在一起，**必须断言错误文案**才能分辨是哪一层拒的。`DefaultBodyLimit` 默认 2MB 对 Multipart 也生效（axum 0.8 `with_limited_body()`），应用层再写大小判断不等于能走到那一行。
